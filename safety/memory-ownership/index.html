Memory & Ownership Safety

Complete reference for ^T ownership, affine moves, rc/arc cycle prevention, impl drop destructors, static leak analysis, --leaks quarantine, and --guard page protection.

Overview

Lora manages heap memory without a garbage collector by combining affine unique owners (^T, ^[]T, ^str), deterministic destructors (impl drop), acyclic reference counting (rc / arc with weak), and static raw-pointer leak analysis (Cleak.c):

MechanismType / FormCleanup & Safety Rule
Unique Owner^T, ^[]T, ^strMoves on assignment/pass/return; freed automatically on scope exit, overwrite, or free(owner).
Destructorimpl drop for TRuns deterministically when a value or ^T leaves scope, on early return, or in delete.
Shared Ownerrc::rc[T], arc::arc[T]Reference-counted handle; use rc::weak[T] / arc::weak[T] to break parent/child cycles.
Raw Memoryrelease(o), mem::newTracked by Cleak.c (L0100–L0106) so every path frees or adopts it.

12. Memory

Locals live on the stack and are freed when their block ends. Heap memory comes from alloc, which gives an owner, ^T: a pointer that owns what it points to and frees it when it goes out of scope (see Ownership). There is no garbage collector, and no counting: an owner is as small and fast as a raw pointer. Allocation can fail, so alloc, append and insert return nomem as an error to handle with !, ? or match. An append or insert that fails leaves the slice as it was, and drops what it was given.

lora 
type node = struct { value: int, next: nullable ^node }

export fn main() void = {
	let p = alloc(42)!;                      // ^int, freed at the end of main
	let n = alloc(node { value = 1, next = null })!;
	let xs = alloc([1, 2, 3])!;              // ^[3]int, a heap copy
	let zeros = alloc([0u8...], 1024)!;      // 1024 zeroed bytes, not written
	let buf: ^[]int = alloc([], 16)!;        // empty, room for 16

	append(buf, 1)!;
	append(buf, [2, 3, 4]...)!;              // several
	insert(buf[0], 0)!;                      // at an index
	delete(buf[1]);                          // one element
	delete(buf[0..2]);                       // a range
	assert(len(buf) == 2 && buf[0] == 3);

	match (alloc(5)) {
		let q: ^int => free(q),                 // freed now, not later
		nomem => abort("out of memory"),
	}
}

A fill of zeroes, alloc([0...], n) with any value that is all zero bytes (0, false, 0.0, a struct of them), takes memory the system gives already zeroed, so a large buffer costs only the pages that are used. Any other fill, -0.0 among them, is written into every element.

Ownership

^T owns a T on the heap. Lora prefers unique ownership and borrowing:

  • One owner. An owner cannot be copied; it moves where ownership goes: to a ^T parameter, into a binding, a field or an array, or a return. A move must be the owner's last use: using it afterwards is an error, and so is a move inside a loop that the next turn would repeat.
  • Dropped automatically. An owner that has not moved is dropped when its scope ends, on every way out (return, ?, break, the end of the block): what it owns is dropped too, and its memory freed. free(p) drops it early. Owners that move somewhere carry a hidden flag so a path where they moved does not drop them; others cost nothing but the free.
  • Borrowed as *T. &p, or passing p where a *T (or *const T, or a view *T.{a}) is taken, lends it without moving it. A loan may not outlive its owner: it cannot be returned or stored in a global.
  • Fields. A field ^T is owned by what holds it: it is dropped with it, and replaced values are dropped when a new one is assigned. Moving out of a field is an error; lend it instead.
  • Escapes. release(p) gives up ownership and returns the raw *T, for code (or C) that frees it itself; adopt(raw) takes ownership of a raw pointer. Both need unsafe, as does growing a slice that isn't a ^[]T with append or insert. Outside unsafe, all heap memory has an owner. What is certain is checked in unsafe code too: adopt or free of memory no allocation made, a local's, a global's or a temporary's, is an error (L0105), as is adopting what an owner lends (a double free), and a raw pointer to memory an owner gave up leaks if it is given a new value before that memory is freed.
  • The library's types are owners too. map, set, pool::pool, regex::regex, json::document, expanse::region and coro::chan free themselves when they are dropped, and so move as an owner does. finish frees one earlier.
  • Nothing is lost. Unpacking, if let, delete and a failed append all drop what they hold. What could not be dropped is an error (L0607): leaving with ? after an owner was handed to a call or literal still being built, or from inside alloc; or with no name for an error that owns memory.
lora 
type node = struct { value: int, next: nullable ^node }

fn push(head: nullable ^node, v: int) (^node | nomem) =
	alloc(node { value = v, next = head });   // head moves into the node

fn sum(list: *node) int = {                  // borrows
	let total = 0;
	let p: nullable *node = list;
	for (true) {
		match (p) {
			null => break,
			let n: *node => {
				total += n.value;
				p = n.next;
			},
		}
	}
	return total;
}

export fn main() (void | nomem) = {
	let list = push(null, 1)?;
	list = push(list, 2)?;     // list moves into push, then owns the new head
	assert(sum(&list) == 3);   // &list lends it
}                             // the whole list is freed here

export fn main() void = {

Growing a list reached through a pointer moves that list. What the list holds views of doesn't move: views of those stay good, and views of the list itself don't:

lora 
type keeper = struct { vals: ^[]str }

fn keep_all(k: *keeper, args: []const str) (^[]str | nomem) = {
	let rest: ^[]str = [];
	for (let a .. args) {
		append(rest, a)?;     // views of args
		append(k.vals, a)?;   // moves k.vals, not args
	}
	return rest;
}

export fn main() void = {
	let k = keeper { vals = [] };
	let rest = keep_all(&k, ["a", "b"])!;
	assert(len(rest) == 2);

Where a function's result comes from is worked out from its body, across modules. A call the compiler can't see into, of a closure, a function pointer or an interface method, is taken to view all its arguments and to change what they point to, though not what is stored behind those. A value with no pointers, slices or strings anywhere in it, as a socket of numbers and addresses, is the exception: changing it only changes its bytes, so views of it stay good. When it isn't sure, it refuses. What unsafe { ... } does is its author's to get right: free of what no owner holds needs it too, as it may be a view.

Several owners: rc and arc

When data genuinely needs several owners (a graph, a cache), the library's rc[T] counts them, and drops the value with the last; rc::weak[T] points at it without keeping it alive; arc[T] is the same across threads. Sharing is always explicit, rc::share(&r), never a copy.

A value can't own itself. Values in a cycle of owners keep each other's counts above zero, and are never freed. So rc::new and arc::new refuse a type that could form one: nothing in it, at any depth, may lead back to it through rc or arc. No such type means no such value, whatever the program does. A link back is an rc::weak, and a graph has one owner of all its nodes, with weak links between them:

lora 
use rc;

type node = struct { value: int, next: (rc::weak[node] | void) }

export fn main() void = {
	let nodes: ^[]rc::rc[node] = [];
	append(nodes, rc::new(node { value = 1, next = void })!)!;
	append(nodes, rc::new(node { value = 2, next = void })!)!;
	rc::get(&nodes[0]).next = rc::downgrade(&nodes[1]);
	rc::get(&nodes[1]).next = rc::downgrade(&nodes[0]);   // a cycle of weak links
}
text 
type node = struct { next: (rc::rc[node] | void) };

let n = rc::new(node { next = void })!; // error: This value could own itself through rc
lora 
use rc;

type config = struct { port: int }

export fn main() void = {
	let a = rc::new(config { port = 80 })!;
	let b = rc::share(&a);                 // two owners
	assert(rc::count(&a) == 2 && rc::get(&b).port == 80);
}                                         // the last one drops the config

Cleaning up: impl drop

A type can say what dropping a value of it does first, by implementing drop (export impl drop for T lets other modules' owners run it too). A value of such a type is an owner too, even on the stack: it moves rather than copies, and its drop runs when its owner ends, so files, sockets and locks clean themselves up (RAII). net::listener, net::conn and fs::file close themselves this way.

lora 
let open_files = 0;

type file = struct { fd: int }

impl drop for file {
	fn drop(f: *file) void = { open_files -= 1; }
}

fn open(fd: int) file = {
	open_files += 1;
	return file { fd = fd }
}

export fn main() void = {
	{
		let a = open(3);
		let b = open(4);
		assert(open_files == 2);
	}                          // b, then a, are dropped: closed
	assert(open_files == 0);
}

static append and static insert add to a slice of a fixed array without allocating, aborting if it is full:

lora 
let storage: [8]int = [0...];
let s = storage[..0];
static append(s, 1)!;
static append(s, 2)!;
assert(len(s) == 2 && storage[1] == 2);

Ignoring a possible allocation failure is an error:

lora 
let s: ^[]int = [];
append(s, 1); // error: Cannot ignore an error here

Conventions:

  • Whoever allocates frees, usually with defer free(x) right after the allocation.
  • Library functions that return new memory say so (strings::concat, fmt::format, strings::split, …); the caller frees the result.
  • Slices returned by slicing (a[1..]) share memory: never free those.

Finding leaks

Memory that is never freed is found two ways.

Memory an owner holds (^T, ^str, ^[]T, a closure) frees itself, so it cannot leak. Raw memory only exists through unsafe: what an owner gave up with release, memory from C, and plain slices grown with append. These checks are for that memory.

As you compile, the compiler follows each local that holds new raw memory along every path out of its scope, and it is an error where the memory is certain to be unfreed: at a return (a failed ? included), a break or continue leaving its loop, the end of its block, or an assignment that overwrites the only pointer to it. The editor shows these errors as you type, with a quick fix that adds defer free(x);.

lora 
use fmt;
use strings;

type parse_error = !void;

fn check(s: str) (void | parse_error) = if (s == "") parse_error else void;

fn greet(name: str) void = {
	let s = unsafe { release(strings::concat("hello, ", name)!) } // error: `s` holds the memory allocated on line 9, and nothing frees it: it leaks when its block ends
	fmt::println(s)!;
}

fn first_word(text: str) (str | parse_error) = {
	let copy = unsafe { release(strings::clone(text)!) }
	check(text)?; // error: `copy` still holds the memory allocated on line 14 when the function returns here, and nothing frees it: it leaks
	return copy;
}

fn shout(s: str) str = {
	let out = unsafe { release(strings::clone(s)!) }
	out = unsafe { release(strings::concat(out, "!")!) } // error: `out` is given a new value here, but it is the only pointer to the memory allocated on line 20, which is never freed: it leaks
	return out;
}

export fn main() void = {
	greet("lora");
	let w = first_word("hi")!;
	defer unsafe { free(w) }
	let x = shout("hey");
	defer unsafe { free(x) }
}

A local holds new raw memory when it is bound to release(...) of an owner, to a library call returning raw memory ((str | nomem), ([]T | nomem) or (*T | nomem)), or to an empty slice that is later appended to. The error goes away once the memory is freed, deferred, returned, stored (in a struct, array, slice or global), captured by a closure, has its address taken, or is passed to one of your own functions, which may keep it. These are not reported, to keep false alarms rare:

  • memory freed on some paths but not others;
  • paths taken only when memory runs out (a ? on nomem);
  • memory from your own functions, which may hand out memory they keep (an arena, say): the run-time check covers those.

Raw memory is also reported when it goes nowhere it could be freed from: a statement whose value is dropped, an operand of a comparison, a condition, len, or an argument to a call that only borrows it. (An owned result used this way is simply freed once the call or comparison is done.)

lora 
use strings;

export fn main() void = {
	assert(unsafe { release(strings::concat("a", "b")!) } == "ab"); // error: `strings::concat` returns memory the caller must free, and nothing frees it here: it leaks
	assert(strings::concat("a", "b")! == "ab");          // an owner: freed after the comparison
}

Valid Usage & Examples

Affine moves and conditional ownership transfer (`^T`)

An owner moved on one branch is not dropped there, while the non-moving branch drops it automatically.

lora Allowed 
type node = struct { value: int, next: nullable ^node }

fn maybe(n: ^node, give: bool) (^node | void) = {
	if (give) return n; // moves out on this path
	return void;        // dropped automatically on this path
}

export fn main() void = {
	let a = alloc(node { value = 10, next = null })!;
	let res = maybe(a, false);
	assert(res is void);
	let b = alloc(node { value = 20, next = null })!;
	let kept = maybe(b, true) as ^node;
	assert(kept.value == 20);
}

Deterministic cleanup with `impl drop` and cycle-free `rc` trees

impl drop runs on scope exit for both stack values and heap ^T owners; rc::weak avoids reference cycles.

lora Allowed 
use rc;

let closed = 0;
type handle = struct { id: int }
impl drop for handle {
	fn drop(h: *handle) void = { closed += 1; }
}

type tree = struct {
	value: int,
	parent: (rc::weak[tree] | void),
}

export fn main() void = {
	{
		let h = handle { id = 1 };
		assert(h.id == 1);
	}
	assert(closed == 1);

	let root = rc::new(tree { value = 1, parent = void })!;
	let child = rc::new(tree { value = 2, parent = rc::downgrade(&root) })!;
	assert(rc::get(&child).value == 2);
}

Explicit raw memory lifetime with `release` and `defer unsafe { free(p) }`

When interfacing with C or custom allocators, defer unsafe { free(p) } ensures cleanup on every path.

lora Allowed 
export fn main() void = {
	let p = unsafe { release(alloc(99)!) };
	defer unsafe { free(p); }
	assert(*p == 99);
}

Disallowed Forms & Diagnostics

Leaking raw memory from `release` (`L0100`)

Cleak.c verifies that raw memory obtained from release is freed or adopted on every control-flow path.

L0100: `s` holds the memory allocated, and nothing frees it: it leaks when its block ends
lora Rejected 
use strings;

fn greet(name: str) void = {
	let s = unsafe { release(strings::concat("hi ", name)!) }; // error[L0100]: leaks
	assert(len(s) > 0z);
}

export fn main() void = greet("lora");
lora Allowed 
use strings;

fn greet(name: str) void = {
	let s = strings::concat("hi ", name)!; // ok: ^str owner frees itself
	assert(len(s) > 0z);
}

Using a freed owner or raw pointer (`L0102`)

Touching memory after free(p) is rejected statically.

L0102: `p` is used here, but the memory it owned was freed
lora Rejected 
type node = struct { v: int }

export fn main() void = {
	let p = alloc(node { v = 1 })!;
	free(p);
	p.v = 2; // error[L0102]: use after free
}
lora Allowed 
type node = struct { v: int }

export fn main() void = {
	let p = alloc(node { v = 1 })!;
	p.v = 2;
	free(p); // ok: free after last use
}

Runtime Aborts

Double-free or write-after-free under `LORA_LEAKS=1` / `--leaks`

Quarantine poison checks report exact allocation and free sites and abort; unfreed leaks exit with status 23.

lora Aborts 
use mem;

export fn main() void = {
	unsafe {
		let p = mem::new(16z)!;
		mem::release(p);
		mem::release(p); // runtime abort under --leaks: double free
	};
}
lora Allowed 
export fn main() void = {
	let buf: ^[]u8 = alloc([0u8...], 16z)!; // ok: unique owner freed once via defer
	defer free(buf);
}

Out-of-bounds or UAF access under `--guard` / `LORA_LEAKS=guard`

Every heap allocation is placed against a PROT_NONE guard page so any OOB read/write or UAF triggers an immediate hardware SIGSEGV.

lora Aborts 
use mem;

export fn main() void = {
	unsafe {
		let p = mem::new(16z)!;
		let b = p as *u8;
		*mem::ptr_add(b, 16z) = 1u8; // SIGSEGV on PROT_NONE guard page under --guard
		mem::release(p);
	};
}
lora Allowed 
use mem;

export fn main() void = {
	unsafe {
		let p = mem::new(16z)!;
		p[15] = 1u8; // ok: access stays within the allocated 16-byte slice
		mem::release(&p[0]);
	};
}

  • Double-free or write-after-free under `LORA_LEAKS=1` / `--leaks`
