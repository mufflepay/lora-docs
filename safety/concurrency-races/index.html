Concurrency & Data Races

M:N cooperative coroutines (@all, @first, @scope, @go, @each), structured cancellation & deadlines, task-locals (coro::local), coro::serial, thread::shared, and compile-time data-race proofs (L0700).

Overview

Craces.c proves at compile time that concurrent tasks started with @all, @first, @scope, @go, @each, coro::detach, or thread::spawn never race on shared memory (L0700):

  • Shared Read-Only: Any number of tasks may read *const T or immutable globals concurrently.
  • Disjoint Ownership / Channels: Tasks may move ^T values through coro::chan[T] or mutate disjoint variables.
  • Synchronized Primitives: Cross-task mutation is permitted through thread::atomic, thread::new_shared(v) + thread::with, thread::mutex, sync::*, or @synchronised module globals.

## 18. Optionals

`?T` is short for `(T | void)`, a value that may be missing. `a ?? b` is
`a`'s value, or `b` when `a` is `void`; it works the same on nullable
pointers (`b` when `a` is `null`). `a` is evaluated once and `b` only when
needed, and `b` can leave the function:

```lora
fn find(xs: []int, v: int) ?usize = {
	for (let i = 0z; i < len(xs); i += 1) if (xs[i] == v) return i;
	return void;
}

fn index_or_fail(xs: []int, v: int) int = {
	let i = find(xs, v) ?? return -1;          // an early exit
	return @int(i);
}

export fn main() void = {
	let xs = [1, 2, 3];
	assert(find(xs, 3) ?? 99 == 2);
	assert(find(xs, 9) ?? 99 == 99);
	assert(index_or_fail(xs, 9) == -1);
	let fallback = 0;
	let p: nullable *int = null;
	assert(*(p ?? &fallback) == 0);            // nullable *T ?? *T is *T
	match find(xs, 2) {
		let i: usize => assert(i == 1),
		void => abort(),
	}
}

?? binds more loosely than arithmetic and more tightly than comparisons, and groups to the right: a ?? b ?? c.

An optional is not an error, so ? does not apply to it:

lora 
fn f() ?int = void;
fn g() ?int = {
	let x = f()?; // error: No error can occur here, so there is nothing to propagate
	return x;
}
export fn main() void = void;

19. String interpolation

$"..." holds expressions in braces and is a str. {{ and }} are literal braces. It needs no use fmt, and what it costs depends on where it is:

  • As a format string, the argument before a function's rt::any... parameter, it expands to the format string and its values: fmt::printfn($"{a} + {b}") is fmt::printfn("{} + {}", a, b). No string is made.
  • Borrowed, as another call argument (a str parameter, as in fmt::println($"...")), in len($"...") or $"...".len(), it is a temporary string, freed as soon as the call is done.
  • Kept, when it is bound, assigned, returned or stored, it is an owned string, ^str, freed when its owner ends: let s = $"..." is let s = fmt::string(...).

Running out of memory while making one aborts.

lora 
fn center() (int, int) = (3, 4);

export fn main() void = {
	let name = "lora", n = 3;
	fmt::printfn($"{name} has {n} items, {n * 2} doubled, {{literal}}")!;
	fmt::println($"center: {center().0}, {center().1}")!; // a temporary
	let width = $"center: {center().0}".size();             // also one
	assert(width == 9);
	let s = $"{n}!";                                       // kept: a ^str
	assert(s == "3!" && s.len() == 2);
}                                                         // s is freed here

A spec follows the expression after a colon, as in fmt: $"{n:x} {ratio:.2} {name:>8}" is ("{:x} {:.2} {:>8}", n, ratio, name). The last colon outside brackets begins the spec when what follows it is a spec; write {(a ? b : x)} to print a conditional whose last part looks like one.

lora 
use fmt;

export fn main() void = {
	let n = 255, pi = 3.14159;
	let s = $"{n:#x} {pi:.2} [{n:>5}] {[1, 2]:?}";
	defer free(s);
	assert(s == "0xff 3.14 [  255] [1, 2]");
}

A literal format string passed with values to a function taking rt::any... is checked when compiling: each placeholder must be well formed, and there must be a value for each.

lora 
use fmt;

export fn main() void = {
	fmt::printfn("{} and {}", 1)!; // error: This format string needs 2 values, but 1 is given
}

20. Concurrency

Lora's concurrent work runs as coroutines (coro): lightweight tasks on a pool of threads, which move between them. There is no async and no await: any function can run concurrently, and a coroutine waits inside the calls that wait (a channel, coro::sleep, a socket), letting others run. Work is started by three forms that wait for it, so it is part of the code that starts it:

FormRunsGives
@all(f(), g())each expressiona tuple of their values, or the first error
@all for (let x .. xs) f(x)the expression for each turn of the loopan owned slice of the values, in order, or the first error
@first(f(), g())each expressionthe first value to come, or the last error if all fail
@scope { ... }@go f(x) anywhere in its blockthe block's value, or the first error of a child
@each for (let x .. xs) f(x) => |r| handlethe expression for each turn of the loopnothing: handle takes each result r as its child finishes
lora 
use coro;

type gone = !void "gone";

fn profile(id: int) (str | gone) = if (id < 0) gone else "ann";
fn orders(id: int) (int | gone) = id * 10;

fn dashboard(id: int) ((str, int) | gone | coro::cancelled) = {
	// both run at once, and @all waits for both
	let (name, count) = @all(profile(id), orders(id))?;
	return (name, count);
}

export fn main() void = {
	let (name, count) = dashboard(7)!;
	assert(name == "ann" && count == 70);
	assert(dashboard(-1) is gone);
}
  • The work is the code's own. A form ends only once all of its work has, on every way out of it, so a child can use the locals and views of the code around it: nothing it uses can go away first.
  • The first failure ends it. The other children are cancelled and waited for, and the form gives that error, with a type that says which errors it can be. ?, or and match handle it as any error.
  • Cancelling is cooperative. A cancelled child's waits end at once: a receive or send is done, coro::sleep returns, and a socket read or write fails with ECANCELED. Long work asks with coro::check()? or coro::is_cancelled(). Cancelling a scope cancels the scopes its children have open. Every form can be cancelled, so each can give coro::cancelled.
  • Options, in the parentheses: within = ms cancels the work if it is not done in time, and gives coro::timed_out; max = n (for @all for) runs at most n children at once; workers = n runs the work on n threads when nothing runs coroutines yet.
lora 
use coro;

fn slow(ms: u64) int = {
	coro::sleep(ms);
	return 1;
}

export fn main() void = {
	// the first to come wins, and the other is cancelled
	assert(@first(slow(500), slow(1))! == 1);
	// too slow: cancelled, and timed out
	assert(@all(slow(1000), within = 10) is coro::timed_out);
	let ns = [1, 2, 3];
	let ones = @all(max = 2) for (let n .. ns) slow(1);
	let got = ones!;
	assert(len(got) == 3);
	free(got);
}

@scope is for children started as the code goes, as by a server for each connection. @go starts one, in the innermost @scope:

lora 
use coro;
use thread;

export fn main() void = {
	let hits = thread::atomic { ... }
	let ph = &hits;
	@scope {
		for (let i = 0; i < 10; i += 1) @go thread::add(ph, 1);
	}!;
	assert(thread::load(&hits) == 10);
}
lora 
use coro;
export fn main() void = { @go void; } // error: @go starts a child of the @scope it is in, and this is in none.

Children start running at once, in a coroutine or not: in main, outside any coroutine, the scope's children run on worker threads while its block goes on, so a loop that accepts connections and starts a child for each serves them as they come. The block's end waits for them all.

When @go f(..., x, ...) gives an owner x that is a local, x moves into the child, which drops it when f returns: a connection each child serves and closes, a buffer it fills. The code after can't use x, and a call gives one owner this way; more go together in a struct or tuple.

lora 
use coro;
use strings;

fn check(s: ^str) void = assert(s == "hi");

export fn main() void = {
	@scope {
		let s = strings::clone("hi")!;
		@go check(s);   // s is the child's now
	}!;
}

@each handles results as they come, errors included: a ? in the handler returns from the function, which cancels the children still running and waits for them, as every way out does. Results not yet taken are dropped. Run from outside any coroutine, the children all run first, and their results come in the order they finished.

lora 
use coro;

type gone = !void "gone";

fn slow(ms: u64) (u64 | gone) = {
	coro::sleep(ms);
	return if (ms == 7) gone else ms;
}

fn first_two(ms: []u64) ([2]u64 | gone | coro::cancelled) = {
	let got: [2]u64 = [0...];
	let n = 0z;
	@each for (let m .. ms) slow(m) => |r| {
		if (n < 2) got[n] = r?;
		n += 1;
	}?;
	return got;
}

export fn main() void = {
	let got = @all(first_two([30, 10, 20]))!;
	assert(got[0] == 10 && got[1] == 20);
	assert(@all(first_two([30, 7, 20])) is gone);
}

What children inherit. A child of @all, @first, @each or @scope starts with what its parent has: its cancellation and deadline, its priority, and its task-local values. A detached coroutine starts with none of these.

  • Priority. coro::priority is low, normal or high: a ready coroutine runs before those of lower priority. priority = p sets a form's children's, coro::set_priority(p) the running coroutine's, and a coroutine waiting for its children raises theirs to its own, so work it waits for is never held up behind it.
  • Task-local values. coro::bind(&key, v, fn() R = ...) binds key to v for the length of the call, for the coroutine and every child it starts there; coro::lookup(&key) gives it, or void. Each reads a copy, so a value can't point into memory or own it.
lora 
use coro;

let request: coro::local[u64] = coro::local { name = "request" }

fn current() u64 = match (coro::lookup(&request)) {
	let r: u64 => r,
	void => 0,
}

export fn main() void = {
	let (a, b) = coro::bind(&request, 42u64, fn() (u64, u64) =
		@all(current(), current())!);
	assert(a == 42 && b == 42 && current() == 0);
}

Serial values. coro::serial[T] is a value one coroutine at a time uses, as an actor's state is: coro::with(&s, fn(v: *T) R = ...) runs the closure on it, while others wait their turn as coroutines. The closure may not wait itself (the compiler checks), so a turn is short and the value can't change in the middle of one: read or change it, and wait before or after.

lora 
use coro;

fn add(t: *coro::serial[int], n: int) int =
	coro::with(t, fn(v: *int) int = {
	*v += n;
	return *v;
});

export fn main() void = {
	let total = coro::serial_new(0);
	let pt = &total;
	let sums = @all for (let n .. [1, 2, 3]) add(pt, n);
	let each = sums!;
	assert(len(each) == 3);
	free(each);
	assert(coro::with(&total, fn(v: *int) int = *v) == 6);
}

Detached coroutines. coro::detach(fn() void = ...) starts work that nothing waits for, which may outlive the code that started it, so it takes only what it owns: the compiler refuses a capture that points into memory it doesn't own. coro::detach_with(v, fn(v: T) void = ...) gives it an owned value, such as an arc share, and coro::run() runs detached coroutines until all have finished. Each gives a coro::detached, which coro::cancel(d) cancels (its waits end at once, as a cancelled child's do) and coro::running(d) asks about; it is an id, never reused, so it may be kept and copied, and cancelling one that has finished does nothing.

lora 
use coro;
fn start() void = {
	let n = 0;
	let p = &n;
	coro::detach(fn() void = { *p = 7; })!; // error: A detached coroutine may outlive `p`, which is a *int, a view of memory it doesn't own: it takes only what it owns.
}
export fn main() void = start();

A plain function, *fn, views nothing that can end, as its code lasts as long as the program: a detached coroutine may be given one, with the value it works on.

lora 
use coro;

fn count(c: *int) void = { *c += 1; };

export fn main() void = {
	let f: *fn(c: *int) void = &count;
	coro::detach_with(f, fn(f: *fn(c: *int) void) void = {
		let n = 0;
		f(&n);
		assert(n == 1);
	})!;
	coro::run();
}
  • Coroutines are cooperative: one runs until it waits. A loop that never does holds its worker thread; coro::yield_now() lets others run.
  • Code in coroutines on different workers runs in parallel: protect what they share with channels, coro::serial, thread::mutex or atomics.
  • Blocking C calls belong in coro::blocking(fn() void = ...), which moves them off the scheduler.
  • Threads (thread::spawn, thread::spawn_with) are OS threads, joined with thread::join, which take only what they own (below).

Data races

Code started on another thread, a closure given to thread::spawn, coro::detach or coro::blocking, a child of @all, @first or @scope, and every function of the module it calls, runs at the same time as the code that started it. The compiler checks that it does not change data other threads may use without synchronising:

  • it may not change a mutable global, or read one that other code changes;
  • children that run at the same time (of one @all, @first or @scope, or started in a loop, as @all for does) may not reach the same data when one of them may change it;
  • a @go child may not reach data it may change at all, as the code of its @scope runs beside it.

What a child reaches is worked out from the types of what it captures, not from what its code happens to do: a *T or []T reaches data of type T it may change, a *const T or []const T data it only reads, and a pointer inside a struct, or inside data a pointer reaches, counts too. So a function the child passes a pointer to, or a pointer it reads from memory, can't change shared data unseen. Two children reach the same data when they reach data of one type, or of a type holding the other (a *point and a *f64 may both reach a point's x), unless each points at a different local, by let p = &x given no other value, of a type holding no pointers itself: two connections, two counters. What one child captures is used by that child alone, one thing after another, so it is not compared with itself.

Shared data is fine when it is thread-safe: a thread::atomic, a thread::mutex or thread::cond, a coro::chan, coro::group or coro::serial, or a thread::shared::[T], a value guarded by a lock that threads reach one at a time with thread::with. Code between thread::lock(m) and thread::unlock(m) in the same block holds the lock, and a global marked @synchronised is guarded by its module itself (as coro's scheduler state is, by its lock). A struct type marked @synchronised is thread-safe too: its module guards it, and only its module touches its fields, as with allocator::atomic_fixed_buffer and sql::db.

An interface value can't be shared: what it points to may be of any type. Share a pointer to the thread-safe value itself, and make the interface in the child:

lora 
use allocator;
use coro;

export fn main() void = {
	let af = allocator::atomic_fixed_buffer_owned(4096)!;
	let p = &af;                                 // thread-safe: shared
	@scope {
		for (let w = 0; w < 4; w += 1) {
			@go {
				let a: allocator::allocator = p;
				let x = allocator::create(a, w)!;
				assert(*x == w);
			};
		}
	}!;
}
lora 
use thread;

Valid Usage & Examples

Structured `@scope`, `@go`, and `@all` with owned channel transfers

Structured concurrency blocks wait for all spawned coroutines to finish before exiting, allowing safe stack borrows to channels.

lora Allowed 
use coro;
use fmt;

fn worker(id: u32, out: *coro::chan[^str]) (void | coro::cancelled) = {
	coro::send(out, fmt::format("job-{}", id)!) as void;
}

export fn main() void = {
	let ch = coro::chan_new::[^str](4);
	let pch = &ch;
	@scope {
		for (let i = 0u32; i < 3; i += 1) {
			@go worker(i, pch);
		}
		for (let k = 0; k < 3; k += 1) {
			let msg = coro::recv(pch) as ^str;
			assert(len(msg) > 0z);
		}
	}!;
}

Sharing mutable state safely via `thread::atomic` and `arc`

Detached coroutines and OS threads own arc::share(&r) handles and mutate thread::atomic without races.

lora Allowed 
use arc;
use coro;
use thread;

export fn main() void = {
	let r = arc::new(thread::new_atomic(0u64))!;
	coro::detach_with(arc::share(&r), fn(mine: arc::arc[thread::atomic]) void = {
		thread::add(arc::get(&mine), 42u64);
	})!;
	coro::run_on(2);
	assert(thread::load(arc::get(&r)) == 42u64);
}

Mutex-protected state with `thread::new_shared` and `thread::with`

thread::new_shared enforces lock acquisition via thread::with before accessing the inner value.

lora Allowed 
use coro;
use thread;

fn add_val(s: *thread::shared[int], delta: int) void = {
	thread::with(s, fn(v: *int) void = { *v += delta; });
}

export fn main() void = {
	let shared = thread::new_shared(0);
	let ps = &shared;
	@all(add_val(ps, 10), add_val(ps, 20))!;
	let total = 0;
	thread::with(ps, fn(v: *int) void = { total = *v; });
	assert(total == 30);
}

Disallowed Forms & Diagnostics

Mutating a non-synchronized global from `thread::spawn` (`L0700`)

Writing to an ordinary global from a spawned thread or coroutine is a compile-time data race.

L0700: `counter` is changed by a thread while other threads may use it
lora Rejected 
use thread;

let counter = 0;

export fn main() void = {
	let t = thread::spawn(fn() void = {
		counter += 1; // error[L0700]: unsynchronized global write
	})!;
	thread::join(t);
}
lora Allowed 
use thread;

let counter = thread::atomic { ... };

export fn main() void = {
	let t = thread::spawn(fn() void = {
		thread::fetch_add(&counter, 1); // ok: atomic increment
	})!;
	thread::join(t);
	assert(thread::load(&counter) == 1);
}

Passing the same mutable pointer to concurrent `@all` branches (`L0700`)

Two concurrent branches cannot reach the same memory when either branch can mutate it.

L0700: `p` reaches data (an int) that may change while another thread uses it
lora Rejected 
use coro;

fn bump(p: *int) void = { *p += 1; }

export fn main() void = {
	let n = 0;
	let p = &n;
	@all(bump(p), bump(p))!; // error[L0700]: concurrent mutable alias
}
lora Allowed 
use coro;

fn bump_val(v: int) int = v + 1;

export fn main() void = {
	let (a, b) = @all(bump_val(10), bump_val(20))!; // ok: independent by-value calls
	assert(a + b == 32);
}
