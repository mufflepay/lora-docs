Lexical Conventions

Words, Keywords & Attributes

Complete reference of reserved keywords, soft contextual keywords, primitive type names, and every built-in @ form recognized by the compiler.

Overview

Lora distinguishes reserved keywords (never valid as identifiers), soft/contextual keywords (usable as variable/function names outside their special grammar positions, e.g. macro), built-in primitive types, and @ attributes/intrinsics.

Reserved & Soft Keywords

Keywords (reserved everywhere):

text 
_ abort align alloc append as assert bool break const continue def defer
delete done else enum export f32 f64 false fn for free i16 i32 i64 i8 if
insert int is len let match never nomem null nullable offset opaque ref
return rune size static str struct true type u16 u32 u64 u8 uint uintptr
union use usize vaarg vaend valist vastart void yield

macro, closure, interface and impl are special only where they start a declaration or a type, and requires and ensures only after a function's result type (unit functions), so they remain usable as names:

lora 
let interface = 1, impl = 2, closure = 3, macro = 4, requires = 5, ensures = 6;
assert(interface + impl + closure + macro + requires + ensures == 21);

Complete Built-in Attributes Table

AttributeApplies toEffect
@initfunctionruns before main
@finifunctionruns after main returns
@testfunctiona test function (fn() / fn() (void | E) / fn(t: *testing::t) void)
@benchfunctiona benchmark function (fn(b: *testing::b) void) run with lora test --bench
@fuzzfunctiona fuzz target (fn(f: *testing::f) void) run with lora test --fuzz
@depth(n, max)functionbounds recursion depth statically for stack checking
@bits(T)structbitstruct packed into unsigned integer T (u8–u64)
@symbol("name")function, globalthe linker symbol: declares a C function or exports under a C name
@threadlocalglobalone copy per thread
@shorthand(name)typea tag type's short form (tags)
@rule(fn)typewhat checks a tag type's uses at compile time (tags)
@synchronisedglobalits module guards it for threads itself, as with a lock (data races)
@unsafefunction, interface methodits callers make sure of what it needs, in unsafe code; its body may do unsafe operations (unsafe code)
@uncheckedfunction, block, expressionno bounds checks inside, which makes it unsafe code: @unchecked { ... }, @unchecked a[i]
@inlinefunction, callits calls are replaced by its body; at a call, @inline f(x) replaces that one
@noinlinefunctionnever inlined
@partialmatch@partial match (x) { ... }: cases may be left out, and do nothing
@packedstructno padding between fields
@align(n)struct, unionaligned to n
@field_align(min = n, max = m)struct, unioneach field aligned to between n and m
@simplestruct, unioncompared as its bytes
@sealedstruct, unionits fields are its module's alone (layout)

@inline is always done, or it is an error that says why: a function that calls itself, makes a closure, has an ensures, takes variadic arguments, or uses something private to another module can't be. The inlined body behaves exactly as the call would, its defers and drops included. Inlining stops after 8 levels of @inline functions calling each other, and makes a call there instead.

@partial match does nothing for the cases it leaves out, so it has no value, and it can't leave out an error, which would be ignored without a word: handle errors with an arm of their own.

@unchecked removes bounds checks from indexing and slicing. An index out of range then reads or writes memory it shouldn't, so it is unsafe code, and the author's to get right.

Valid Usage & Examples

Use soft keywords as identifiers and built-in `@` attributes on declarations

Words like macro are contextual; @packed, @align, @simple, and @test control layout and test discovery.

lora Allowed 
type hdr = struct @packed { tag: u8, size: u32 }
type pt = struct @simple { x: i32, y: i32 }

export fn main() void = {
	let macro = 1;
	assert(macro == 1 && size_of(hdr) == 5 && pt { x = 1, y = 2 } == pt { x = 1, y = 2 });
}

Shadow built-in `@` macros with module-local `macro` definitions

A module’s own macro name(...) takes precedence over built-in @name macros within that module.

lora Allowed 
macro square(x) = x * x;

export fn main() void = {
	assert(@square(3) == 9);
}

Disallowed Forms & Diagnostics

Using a reserved keyword as a variable or function name

Reserved keywords (fn, let, match, struct, if, for, return, etc.) cannot be used as identifiers.

Syntax: syntax error: unexpected keyword `match`
lora Rejected 
export fn main() void = {
	let match = 1; // error: `match` is a reserved keyword
}
lora Allowed 
export fn main() void = {
	let matched = 1; // ok: valid non-keyword identifier
	assert(matched == 1);
}

Invoking an unknown `@` attribute or macro (`L0001`)

Unrecognized @name forms that do not match a built-in or module macro fail at check time.

L0001: `nope` is an unknown macro/attribute
lora Rejected 
export fn main() void = {
	let _ = @nope(1); // error: unknown @nope
}
lora Allowed 
export fn main() void = {
	assert(@has_zero(int)); // ok: recognized built-in @has_zero macro
}

Constraints & Limits

Macro Shadowing
Module-scoped
User macro definitions shadow built-in @ macros in that module.
  • User-declared macro definitions shadow built-in @ macros of the same name within that module.
