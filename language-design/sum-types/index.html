Language Design

Sum Types, Optionals, Errors & Enums

Tagged unions (A | B | C), optionals ?T ((T | void)), self-describing error types (!struct, (T | !)), pattern-constrained scalar types (u32 is 0..4096), @bits structs, and scoped enums.

Overview

Lora unifies algebraic sum types, optionals, and error handling around tagged unions (A | B):

FormUnderlying RepresentationKey Operations
(A | B | C)4-byte tag + aligned max payloadis T, as T, match, if (let x: T = v), ...subunion
?TAlias for (T | void)opt ?? fallback, opt ?? return, match
!T / (T | err)Error-flagged member (same size as T)? propagate, ! unwrap-or-abort, or default
enum [base] { ... }Underlying integer or runeScoped E::A or inferred .A; explicit @base(e)
u32 is 0..4096Pattern-constrained scalarChecked on conversion @T(val) and literals
@bits struct { ... }Bit-packed integer fieldsField-level @bits(n) widths and optional patterns

Tagged Unions

Tagged unions

(A | B | C) holds a value of exactly one of its member types and knows which. is tests the member and as extracts it (aborting if it is the wrong one); match handles every case:

lora 
type token = (int | str | void);

fn describe(t: token) str = match t {
	let n: int => if (n < 0) "negative" else "number",
	let s: str => s,
	void => "nothing",
}

export fn main() void = {
	let t: token = 42;
	assert(t is int && t as int == 42);
	assert(describe("word") == "word" && describe(void) == "nothing");
	let nested: (int | (str | bool)) = true;   // nested unions flatten
	assert(nested is bool);
	let wider: (int | str | bool) = t as int;
	assert(wider is int);
}

Operators don't apply to a tagged union itself, since it may hold a member they make no sense for: take the member out first.

lora 
let r: (int | void) = 5;
let big = r > 0; // error: Cannot compare (void | int), a tagged union
let ok = r is int && r as int > 0;

A union converts to a union with more members, but not to one member or a smaller union without a check:

lora 
let t: (int | str) = 1;
let n: int = t; // error: Initializer of type (str | int) is not assignable to binding type int
lora 
// aborts
let t: (int | str) = 5;
let s = t as str;     // type assertion failed

Tagged unions, like tuples and arrays, cannot be compared with ==. Match on them instead.

Enums, Pattern Types & @bits

Enums

An enum is a type of named values, stored as an integer (or rune). The default storage is int, numbered from 0; a value can be set explicitly, also from the values before it, and the next ones count on from it:

lora 
type color = enum { red, green, blue }
type mode = enum u8 { READ = 1, WRITE, EXEC = 4, ALL = READ + WRITE + EXEC }
type letter = enum rune { A = 'a', B = 'b' }

export fn main() void = {
	assert(@int(color::green) == 1);
	assert(@u8(mode::WRITE) == 2 && @u8(mode::ALL) == 7 && size_of(mode) == 1);
	assert(@rune(letter::B) == 'b');
}

Enums are scoped: a value is named through its enum, color::green, so two enums can both have a red, and neither puts names in the module. Where the enum is already known, .green is enough: a typed binding, an argument, a return, a field, an array element, an assignment, the other side of ==, and a match arm.

lora 
type direction = enum { north, south, east, west }

fn turn(d: direction) direction = match (d) {
	.north => .east,
	.east => .south,
	.south => .west,
	.west => .north,
}

export fn main() void = {
	let d: direction = .north;
	assert(turn(d) == .east && d != .south);
}

Each of the other places, in one program:

lora 
type direction = enum { north, south, east, west }
type robot = struct { name: str, facing: direction }

fn back(d: direction) direction = {
	if (d == .north) return .south;              // == and a return
	return .north;
}

export fn main() void = {
	let d: direction = .east;                    // a typed binding
	let r = robot { name = "r2", facing = .north } // a field
	r.facing = .west;                            // an assignment
	let ways: [2]direction = [.north, .south];   // an array element
	assert(back(.north) == .south);              // an argument
	assert(r.facing == .west && d != .south && ways[1] == .south);
}

An enum is its own type, not a number. Its values compare with ==, != and the orderings, against its own values only, and nothing else: no arithmetic, and no mixing with integers or other enums. Converting is explicit both ways. @int(e) gives the number. @color(n) gives the enum, and checks that n is one of its values: a constant when compiling, anything else when the program runs, which stops if it isn't one. n is color tests first, for a number that may not be one. In @unchecked code the check is left out.

lora 
type color = enum { red, green, blue }

fn parse(n: int) (color | void) = if (n is color) @color(n) else void;

export fn main() void = {
	let n = 2;
	assert(@color(n) == color::blue && @int(color::blue) == 2);
	assert(parse(7) is void);
}
lora 
type color = enum { red, green, blue }
export fn main() void = { let n: int = color::green; } // error: Initializer of type color is not assignable to binding type int
lora 
type color = enum { red, green, blue }
export fn main() void = { let c: color = 1; } // error: A color is one of its named values, and a number is not one of them.
lora 
type color = enum { red, green, blue }
export fn main() void = { let c = @color(7); } // error: 7 is not a value of color.
lora 
type color = enum { red, green, blue }
export fn main() void = { let c = .red; } // error: `.red` is a value of an enum, and nothing here says which enum.
lora 
type name = enum str { A = "a" } // error: syntax error: Enum storage must be an integer or rune
export fn main() void = void;

Enums carry no data. For values with payloads, use a tagged union of structs.

Pattern types

A pattern type is a type whose values also match a pattern: type errno = u32 is 0..4096; is a u32 from 0 to 4095. It has exactly the layout and calling convention of u32, so it costs nothing at run time, and the pattern is checked where values come in. It generalizes NonZero (u32 is 1..) and NonNull (Lora's *T is already never null). A pattern is literals, ranges and constants of an integer or rune type, joined with |; lo.. is a range with no end.

lora 
type errno = u32 is 0..4096;
type nonzero = u32 is 1..;
type digit = rune is '0'..='9';
def MAX: int = 100;
type percent = int is 0..=MAX;
type small_prime = u8 is 2 | 3 | 5 | 7;

fn describe(e: errno) u32 = e;            // errno to u32: nothing is lost

fn parse_errno(n: u32) (errno | void) = n is errno ? @errno(n) : void;

export fn main() void = {
	let e: errno = 2;                      // a constant: checked when compiling
	let raw: u32 = 17;
	let f = @errno(raw);                    // checked when the program runs
	let sum = e + f;                        // arithmetic gives a u32
	let g = @errno(sum);
	assert(describe(e) == 2 && g == 19);
	assert(parse_errno(5000) is void && size_of(errno) == size_of(u32));
	assert('5' is digit && !('x' is digit) && 3u8 is small_prime);
	let nz: nonzero = 1;
	let p: percent = 100;
	assert(nz == 1 && p == 100);
}
  • A value of a pattern type converts to its base type implicitly. The other way, a constant is checked when compiling; any other value needs @errno(x), which aborts if x does not match, or x is errno, which tests without aborting.
  • Arithmetic on a pattern type gives its base type, since the result may be outside the pattern; assign it back with @errno(...). A pattern type cannot be changed in place (+=, ++).
  • Zero-filling (...) is allowed only when the pattern contains 0.
  • Patterns cross module boundaries with the type.
lora 
type errno = u32 is 0..4096;
export fn main() void = {
	let e: errno = 5000; // error: This value does not match the pattern of errno
}
lora 
// aborts
type errno = u32 is 0..4096;
export fn main() void = {
	let n: u32 = 9000;
	let e = @errno(n);   // value does not match its pattern type
}
lora 
type errno = u32 is 0..4096;
export fn main() void = {
	let e: errno = 1;
	e += 1; // error: A value of the pattern type errno cannot be changed in place
}
lora 
type errno = u32 is 0..4096;
export fn main() void = {
	let n: u64 = 3;
	let e = @errno(n); // error: Convert u64 to u32 first
}

Bits

struct @bits(u16) { ... } packs its fields into an unsigned integer: u8, u16, u32 or u64. It is that integer: the same size, passed and compared as it, and a register file or a wire format can be written as one. Each field takes the bits its type needs, from the lowest bit up in order:

Field typeIts bits
boolone
an enumenough for its values
an integer with a pattern, speed: u8 is 0..8, or a pattern typeenough for its pattern
an integerall of its own

@at(n) before a field places it at bit n, and the fields after it follow on. Bits no field has are kept as they are, and can't be reached.

lora 
type mode = enum { off, low, high }

type status = struct @bits(u8) {
	ready: bool,            // bit 0
	error: bool,            // bit 1
	speed: u8 is 0..8,      // bits 2 to 4
	mode: mode,             // bits 5 and 6
	@at(7) busy: bool,      // bit 7
}

fn faster(s: *status) void = {
	s.speed += 1;
}

export fn main() void = {
	let s = status { ready = true, speed = 5, mode = .high, ... }
	faster(&s);
	assert(s.speed == 6 && s.ready && size_of(status) == 1);
	assert(@u8(s) == 0b0_10_110_0_1); // busy, mode, speed, error, ready
}

A field is read and written as any field is, and the other fields' bits stay as they were. What goes in is checked as a pattern type's values are: a constant when compiling, anything else when it is stored, which stops the program if it doesn't fit, and nothing in @unchecked code. So a field always holds one of its values.

A @bits value compares with == and !=. When every field is a bool it is a set of flags, which also combine with |, & and ^, and ~ flips them. Converting is explicit both ways: @u8(s) gives the integer, and @status(n) checks that each enum and pattern field's bits of n hold one of its values, as @e(n) does for an enum. n is status tests it first.

lora 
type perms = struct @bits(u8) { read: bool, write: bool, exec: bool }
type mode = enum { off, low, high }
type status = struct @bits(u8) { ready: bool, mode: mode }

fn parse(n: u8) (status | void) = if (n is status) @status(n) else void;

export fn main() void = {
	let rw = perms { read = true, ... } | perms { write = true, ... }
	assert(rw.read && rw.write && !rw.exec && (~rw).exec);
	assert(parse(0b101) is status && parse(0b111) is void);
}
lora 
type status = struct @bits(u8) { ready: bool, speed: u8 is 0..8 }
export fn main() void = { let s = status { ready = true, speed = 9 } } // error: 9 does not fit in `speed`, which holds 0..8.
lora 
type status = struct @bits(u8) { ready: bool, speed: u8 is 0..8 }
export fn main() void = { let s = status { ready = true, speed = 1 } let p = &s.speed; } // error: A @bits field is some bits of an integer, so it has no address of its own.
lora 
type status = struct @bits(u8) { a: u8 is 0..16, b: u8 is 0..32 } // error: `b` needs bits 4 to 8, and a u8 has 8.
export fn main() void = void;

Errors & Propagation

let a: ^[]u8 = alloc([0...], 4)!; let b: ^[]u8 = alloc([0...], 4)!; defer { a[0] = 0; free(a); free(b); } a[0] = 1; b[0] = 2; assert(a[0] + b[0] == 3); }

text 

A defer belongs to the block it is written in, and runs when that block
ends. So `unsafe { defer free(p) }` frees `p` at once, as its block is the
`unsafe { ... }`, which is an error (L0106); and a use of what a defer in
an inner block freed, after that block, is a use after free. Write the
`unsafe` inside the defer, which then runs when the block around it ends:

```lora
export fn main() void = {
	let p = unsafe { release(alloc(10)!) };
	defer unsafe { free(p) }    // runs when main's block ends
	assert(*p == 10);
}

10. Errors

Errors are ordinary values. A type declared with ! is an error type, and a function that can fail returns a tagged union of its result and its errors. There are no exceptions. Lora's rule is that a failure always says what went wrong and why: errors describe themselves, a dropped error is warned about, and a failing program prints the error, what it was doing, and where the error came from.

lora 
use strconv;

type not_found = !void "no such record";
type parse_error = !struct { line: int } "cannot parse line {line}";

fn lookup(id: int) (str | not_found) = if (id == 1) "one" else not_found;

fn parse(s: str) (int | parse_error) = {
	if (s == "") return parse_error { line = 3 }
	return 1;
}

fn both(id: int) (int | not_found | parse_error) = {
	let name = lookup(id)?;       // ? returns the error to our caller
	return parse(name)?;
}

export fn main() void = {
	assert(lookup(1)! == "one");  // ! aborts if it is an error
	assert(both(2) is not_found);
	match (parse("")) {
		let e: parse_error => assert(e.line == 3),
		int => abort(),
	}
	let n = strconv::parse_int("42")!;
	assert(n == 42);
}

Errors that describe themselves

An error type may end with its message: a template whose {placeholders} are fields of the error, checked when compiling, or the name of a function fn(e: *const T, buf: []u8) str that describes a value. Printing an error with {}, a failing x! and a main that returns it all use the message; {:?} still shows the fields. Your own errors work exactly like the library's:

lora 
type quota = !struct { user: str, limit: usize }
"user {user} is over the limit of {limit}";

export fn main() void = {
	let e = quota { user = "ann", limit = 5 }
	let text = fmt::format("{} / {:?}", e, e)!;
	defer free(text);
	assert(text == "user ann is over the limit of 5 / quota { user = \"ann\", limit = 5 }");
}

Each library module has its own error, named <module>::error: io::error, fs::error, net::error, os::error. It says what was being done and holds the system's error number, rt::errno, which tells causes apart: cannot listen on 127.0.0.1:8080: Address already in use (EADDRINUSE, errno 48), and e.errno == rt::EADDRINUSE. Errors of different modules join in one union, (void | nomem | io::error | net::error), so each can still be matched; nothing is wrapped or lost.

A name for a union of errors only, as a library gives its errors, stands for those errors wherever it is used in a union: (T | json::error) is T or any of json's errors, each matched and passed on with ? by itself.

lora 
type too_big = !void "too big";
type too_small = !void "too small";
type bad_size = (too_big | too_small);

fn sized(n: int) (int | bad_size) =
	if (n > 9) too_big else if (n < 1) too_small else n;

fn doubled(n: int) (int | bad_size) = sized(n)? * 2;

export fn main() void = {
	assert(doubled(2)! == 4);
	match (doubled(0)) {
		int => abort(),
		too_big => abort(),
		too_small => void,
	}
}

Inferred errors: (T | !)

! in a function's result stands for the errors its body can return: the compiler gathers what its ?s and returns pass on.

lora 
use strconv;

type config = struct { port: int }
type bad_port = !struct { port: int } "port {port} is out of range";

fn load(text: str) (config | !) = {
	let port = strconv::parse_int(text)?; // strconv::invalid_number
	if (port < 1 || port > 65535) return bad_port { port = port }
	return config { port = port }
}
// load returns (config | strconv::invalid_number | bad_port)

export fn main() (void | !) = {
	let c = load("8080")?;
	fmt::println($"port {c.port}")?; // io::error, with no need to name it
}

Callers see the whole type and match each error as usual. Exported functions (other than main) write their errors out, since other modules rely on them; so do lambdas, and functions that use themselves, whose errors would depend on what they are:

lora 
use strconv;

export fn port(s: str) (int | !) = strconv::parse_int(s)?; // error: `port` is exported, so its errors must be written out

export fn main() void = void;

lora 
use strconv;
use rt;

fn port(s: str) (int | strconv::invalid_number) =
	strconv::parse_int(s) ? $"reading the port {s}";

export fn main() void = {
	let a = strconv::parse_int("x") or 8080;           // a fallback
	let b = port("90") or |e| {
		fmt::eprintfn("bad port: {}", e)!;
		yield 8080;
	}
	for (let s .. ["1", "x", "3"]) {
		let n = strconv::parse_int(s) or continue;     // skip what fails
	}
	assert(a == 8080 && b == 90);
}

The function's result type must include what ? returns:

lora 
type err = !void;
fn f() (int | err) = 1;
export fn main() void = {
	let x = f()?; // error: Error type err is not assignable to function result type void
}
lora 
fn f() (int | str) = 1;
fn g() (void | str) = {
	let x = f()?; // error: No error can occur here, so there is nothing to propagate
}
export fn main() void = void;

?, ! and or look only at error types. A (T | void) optional is not an error; use ?? for it.

Traces, and main returning errors

Returning an error starts an error trace, kept per thread; each ? and each return of a caught error adds where it passed, with its note. main may return (void | errors...): when it returns an error, the program prints it, the notes (outermost first) and the trace, and exits with status 1. A failing x! prints the same.

lora 
// aborts: error: cannot parse "127.0.0.x:8080" as an IP address and port: a character that cannot be there, at byte 8
use net;
use netip;

export fn main() (void | nomem | net::error | netip::invalid) = {
	let l = net::listen_at("127.0.0.x:8080") ? "starting the server";
}

With a valid address whose port is taken, it says:

text

  while starting the server

    net::listen  lib/net.lora:760:23  error made here
    main         app.lora:5:31

// aborts: error occurred: cannot parse line 3
type parse_error = !struct { line: int } "cannot parse line {line}";

Optionals (?T and ??)

let sq = @comptime(squares()); let r = @comptime(bounds()); const shout = @comptime(strings::toupper("abc")!); // other modules too assert(FIB20 == 6765 && len(table) == 8 && sq[4] == 16 && r.hi == 55); assert(shout == "ABC"); }

text 

The interpreter runs locals and assignment, `if`, `match` (every pattern,
guards, `?` and `!`), every kind of `for`, `yield`, `return`, `assert`,
calls (recursion, other modules' functions), arithmetic, comparisons and
casts, over integers, floats, bools, runes, strings, arrays, structs,
tuples, tagged unions and slices. Pointers into locals, elements, fields and
`alloc`ed memory work, `append` grows slices, and globals read their
initial values.

What cannot run at compile time:

```lora
@symbol("abs") fn c_abs(x: i32) i32;
def X: i32 = @comptime(unsafe { c_abs(-1) }); // error: This function has no body that can run at compile time (a C function, say)
export fn main() void = void;
lora 
fn mk() ^[2]int = alloc([1, 2])!;
export fn main() void = {
	let p = @comptime(mk()); // error: The result of @comptime can't hold pointers or slices into memory made at compile time
}
lora 
fn d() int = { defer void; return 1; } // error: defer cannot be evaluated at compile time
export fn main() void = { let p = @comptime(d()); }
  • C functions, system calls and I/O.
  • defer.
  • Results holding pointers or slices into memory made at compile time; return values (arrays, structs, strings) instead.
  • Reading memory as an unrelated type (reading a str as []u8, as strings does, works).
  • More than 10 million steps or 512 nested calls: evaluation stops with an error.

17. Reflection

Valid Usage & Examples

Tagged unions with ... spread, is/as checks, and subset widening

Unions automatically flatten nested unions via ..., deduplicate members, and widen from subset (A | B) to (A | B | C).

lora Allowed 
type Signed = (i8 | i16 | i32 | i64 | int);
type Unsigned = (u8 | u16 | u32 | u64 | uint);
type Integer = (...Signed | ...Unsigned);

export fn main() void = {
	let sub: (i8 | i16) = 42i8;
	let wide: (i8 | i16 | i32) = sub; // subset widens implicitly
	assert(wide is i8 && wide as i8 == 42i8);

	let n: Integer = 10i;
	assert(n is int);
}

Optionals (?T), ?? coalescing, and error propagation (?, !, or)

Use ?T with ?? for absent values and !-marked error types with ? propagation or ! assertions.

lora Allowed 
type not_found = !void;

fn find(xs: []int, target: int) ?usize = {
	for (let i = 0z; i < len(xs); i += 1) {
		if (xs[i] == target) return i;
	}
	return void;
}

fn require_item(xs: []int, target: int) (usize | not_found) = {
	let idx = find(xs, target) ?? return not_found;
	return idx;
}

export fn main() void = {
	let xs = [5, 3, 9];
	assert(find(xs, 9) ?? 99z == 2z);
	assert(find(xs, 4) ?? 99z == 99z);
	assert(require_item(xs, 3)! == 1z);
	assert(require_item(xs, 8) is not_found);
}

Scoped enums with custom storage and pattern-constrained scalars

Enums default to int storage or accept any integer/rune base; pattern types enforce range invariants on construction.

lora Allowed 
type Mode = enum u16 {
	READ = 1,
	WRITE = 2,
	EXEC = 4,
}

type Port = u16 is 1..=65535;

export fn main() void = {
	let m: Mode = .WRITE;
	assert(@u16(m) == 2u16);
	let p: Port = 8080;
	assert(p == 8080);
}

Disallowed Forms & Diagnostics

Silently ignoring an error-typed value or union containing an error

Expressions with ! error types cannot be discarded as statements (L0003); handle them with ?, !, or, match, or explicit let _ = ....

L0003: Unhandled error value cannot be ignored
lora Rejected 
type my_err = !void;
fn fail() (int | my_err) = my_err;

export fn main() void = {
	fail(); // error[L0003]: unhandled error
}
lora Allowed 
type my_err = !void;
fn fail() (int | my_err) = my_err;

export fn main() void = {
	let v = fail() or 0; // ok: handles error with fallback value
	assert(v == 0);
}

Single-member unions, narrowing assignments, or mismatched ?? fallback types

A union must have at least two distinct members ((u8 | u8) is invalid), and ?? requires a ?T or nullable *T left-hand side with matching fallback type.

Compile error: Cannot reduce tagged union to a single member / incompatible ?? operands
lora Rejected 
export fn main() void = {
	let a: (u8 | u8) = 42u8; // error: single-member union
}
lora Allowed 
export fn main() void = {
	let o: ?int = void;
	let y = o ?? 42; // ok: ?int with matching int fallback
	assert(y == 42);
}

Runtime Aborts

Failed `as T` tag assertion or `!` error unwrap aborts cleanly

Casting a tagged union with as T when another variant is active, or unwrapping an error with !, terminates the process with a diagnostic.

lora Aborts 
// aborts
type my_err = !void;
fn fail() (int | my_err) = my_err;

export fn main() void = {
	let v = fail()!; // abort: unhandled error in `!`
}
lora Allowed 
type my_err = !void;
fn fail() (int | my_err) = my_err;

export fn main() void = {
	let v = fail() or |_| 0; // ok: handle error fallback instead of aborting with !
	assert(v == 0);
}

Constraints & Limits

Tag Width
32-bit type ID
Every tagged union carries a 4-byte tag + max member alignment.
Enum Storage
Integers or `rune`
Floats and composite types cannot back an `enum`.
?? Precedence
Looser than arithmetic
`a ?? 1 + 2` parses as `a ?? (1 + 2)`.
  • Exported functions (other than main) must spell out their error union explicitly rather than using (T | !).
