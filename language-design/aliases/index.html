Language Design

Aliases & Type Declarations

Every type name = ... declaration defines how values are typed, compared, converted, and passed across module boundaries — distinguishing structural types, transparent aliases, and strict nominal newtypes.

Overview

Lora categorizes type declarations into three semantic kinds:

DeclarationKindImplicit Conversion Rules
type meters = intNewtype (over scalar/bool/rune/str)Does not convert implicitly to/from int or seconds; requires @meters(n) / @int(m)
type point = struct { x: int, y: int }Composite / Structural DeclarationImplicitly converts to/from anonymous/matching struct literal shape; not between two separate struct declarations
type coord = pointNamed Type AliasSame underlying nominal identity as point

Syntax

lora 
type identifier = type_expression ;
export type identifier[TypeParams] = type_expression ;

Newtypes Over Primitives

Declaring a type over a numeric type, bool, rune, or str creates a distinct newtype. Two different newtypes over the same primitive cannot be mixed in assignments, function arguments, or arithmetic — eliminating unit, ID, and index mix-ups at zero runtime cost.

Untyped constants still fit any newtype whose base bounds hold them (let d: meters = 100; or d + 50).

Aliases vs Identical Definitions

Two separate type declarations with identical struct bodies (type rect = struct { w: f64, h: f64 } and type square = struct { w: f64, h: f64 }) remain distinct nominal types unless explicitly defined as an alias (type box = rect). Explicit @rect(sq) converts between them safely when layouts match.

Function Type Declarations

A function signature without a body inside type creates a callable prototype; function values pass as pointers to it (*binop).

Specification: Declared Types & Function Types

type name = T; declares a type. Each declaration is a type of its own: Lora's types are nominal, so two declarations are different types even when their definitions are identical. Between two declarations, it takes an explicit @T(x), and a value goes into a tagged union only if its type is a member.

A declaration over a number, a bool, a rune or a string is a newtype: its values are its own, apart from its base's too. meters and int don't mix, in assignments, calls or arithmetic, but by @meters(n) and @int(m); a constant fits it, as it fits any type that holds it (let m: meters = 3, let n: name = "ann"), and two meters add up to a meters. So a distance can't be passed where a count is wanted, or an id where a port is. A declaration over a struct, a union or a tagged union converts implicitly to and from what it is defined as, and type b = a is an a.

lora 
type meters = int;
type seconds = int;

fn speed(d: meters, t: seconds) int = @int(d) / @int(t);

export fn main() void = {
	let d: meters = 100;
	let t: seconds = 20;
	let farther = d + 50;                    // meters, with a constant
	assert(speed(farther, t) == 7);
}
lora 
type meters = int;
type seconds = int;
fn speed(d: meters, t: seconds) int = @int(d) / @int(t);
export fn main() void = { let d: meters = 1; let t: seconds = 1; speed(t, d); } // error: Argument type seconds is not assignable to parameter type meters
lora 
type meters = int;
export fn main() void = { let d: meters = 1; let n: int = 2; let x = d + n; } // error: Cannot combine a meters and an int here

The examples below are of declarations over structures:

lora 
type circle = struct { r: f64 }
type rect = struct { w: f64, h: f64 }
type square = struct { w: f64, h: f64 }
type shape = (circle | rect);

fn area(s: shape) f64 = match s {
	let c: circle => 3.0 * c.r * c.r,
	let r: rect => r.w * r.h,
}

export fn main() void = {
	let s = square { w = 2.0, h = 3.0 }
	assert(area(@rect(s)) == 6.0);          // converted explicitly
	assert(area(@shape(s)) == 6.0);         // to the member defined alike
}
lora 
type rect = struct { w: f64, h: f64 }
type square = struct { w: f64, h: f64 }
type shape = (rect | void);

fn area(s: shape) f64 = 0.0;

export fn main() void = {
	area(square { w = 2.0, h = 3.0 }); // error: Argument type square is not assignable to parameter type shape
}
lora 
type meters = int;
type seconds = int;

fn walk(d: meters) void = void;

export fn main() void = {
	let t: seconds = 10;
	walk(t); // error: Argument type seconds is not assignable to parameter type meters
}

The same goes for pointers: a *square is not a *rect.

A function type is written like a declaration without a body. Function values are pointers to it:

lora 
type celsius = f64;
type binop = fn(a: int, b: int) int;

fn add(a: int, b: int) int = a + b;

export fn main() void = {
	let t: celsius = 21.5;
	let f: *binop = &add;
	assert(f(2, 3) == 5 && t > 21.0);
}

Valid Usage & Examples

Strict nominal newtypes over primitives with explicit @Target conversions

Wrapping a scalar, bool, rune, or str in type name = base creates a distinct nominal type with zero runtime overhead (size_of and align match the base type).

lora Allowed 
type meters = int;
type seconds = int;

fn speed(dist: meters, dt: seconds) f64 = @f64(@int(dist)) / @f64(@int(dt));

export fn main() void = {
	let d: meters = 150;        // untyped constant fits meters
	let t: seconds = 3;
	let d2: meters = d + 50;    // arithmetic with untyped constant stays meters
	assert(@int(d2) == 200);
	assert(speed(d, t) == 50.0);
	static assert(size_of(meters) == size_of(int));
}

Transparent type aliases, composite types, and pointer indirection

Aliases to structs, arrays, slices, tagged unions, and pointers preserve layout and allow breaking recursive cycles through *T or nullable ^T.

lora Allowed 
type Point = struct { x: int, y: int }
type Coord = Point; // transparent alias: same nominal type as Point

type Node = struct {
	val: int,
	next: nullable *Node,
}

export fn main() void = {
	let p = Point { x = 10, y = 20 }
	let c: Coord = p; // ok: Coord is an alias for Point
	assert(c.x == 10 && c.y == 20);

	let tail = Node { val = 2, next = null }
	let head = Node { val = 1, next = &tail }
	assert((head.next as *Node).val == 2);
}

Function type prototypes and generic type aliases

A type name = fn(...) R declaration defines a callable prototype passed by pointer (*binop), and generic aliases bind concrete monomorphizations.

lora Allowed 
type binop = fn(a: int, b: int) int;
type Box[T] = struct { item: T }
type IntBox = Box[int];

fn add(a: int, b: int) int = a + b;

fn apply(op: *binop, x: int, y: int) int = op(x, y);

export fn main() void = {
	let b = IntBox { item = apply(&add, 20, 22) }
	assert(b.item == 42);
}

Disallowed Forms & Diagnostics

Mixing two distinct newtypes or passing a newtype where the base type is expected

Newtypes never implicitly convert to their underlying type or to another newtype over the same base.

Type mismatch: Cannot assign or pass `seconds` where `meters` is expected
lora Rejected 
type meters = int;
type seconds = int;

export fn main() void = {
	let d: meters = 10;
	let t: seconds = 5;
	let bad: meters = t; // error: type mismatch (meters vs seconds)
}
lora Allowed 
type meters = int;
type seconds = int;

export fn main() void = {
	let d: meters = 10;
	let t: seconds = 5;
	let converted: meters = @meters(@int(t)); // ok: explicit conversion
	assert(@int(d) + @int(converted) == 15);
}

By-value cyclic type definitions without pointer/slice indirection

A struct or tagged union cannot embed itself directly by value; use *T, nullable *T, ^T, or []T.

Compile error: Cyclic type definition: direct value recursion has infinite size
lora Rejected 
type node = struct { val: int, next: node } // error: recursive type without indirection
export fn main() void = void;
lora Allowed 
type Node = struct { val: int, next: nullable ^Node } // ok: pointer indirection breaks the cycle
export fn main() void = {
	let head = Node { val = 1, next = null }
}

Constraints & Limits

Type Nesting Limit
MAX_TYPE_DEPTH
Compiler rejects pathologically nested type expressions cleanly.
Generic Alias Rule
Same instance identity
`type ints = box[int]` names the exact monomorphized `box[int]` type.
  • Recursive types require indirection (*, ^, or []).
  • Newtypes lose access to unrelated newtype values unless explicitly converted with @Target(expr).
