Language Design

Values, Owners, Pointers, Arrays, Slices & Strings

Comprehensive specification of value storage, ^T owners, *T / nullable *T / *const T pointers, *T.{fields} partial struct borrows, fixed arrays [N]T, checked slices []T / @*[N]T(s), and UTF-8 str.

Overview

Lora makes storage, ownership, and mutability explicit in the type itself:

TypeSizeOwnership & NullabilityKey Guarantee
Tsize_of(T)Value (stack/inline)Copied by value unless T contains ^U
^T8 bytesAffine unique heap ownerFreed once at scope end or moved; never null
*T / *const T8 bytesNon-null borrowed pointerCannot dangle or alias mutably
nullable *T8 bytesNullable borrowed pointerMust narrow with is *T / if (let p: *T = ...) before deref
*T.{a, const b}8 bytesPartial struct field borrowAccesses only named fields; const fields are read-only
[N]T / []T / strN*sizeof(T) / 24B / 24BArray / fat slice / UTF-8 stringBounds-checked indexing; str checks UTF-8 slice boundaries

Pointers, Partial Borrows, Arrays, Slices & Strings

Pointers

FormMeaning
*Ta pointer that is never null
nullable *Ta pointer that may be null; must be checked before use
*const Ta pointer through which T is not changed (for C)
*opaquea pointer to anything (like C's void *)
*[*]Ta pointer to an array of unknown length; can be indexed, unchecked
lora 
type point = struct { x: int, y: int }

export fn main() void = {
	let p = point { x = 1, y = 2 }
	let ptr = &p;
	ptr.x = 10;                 // fields are reached through pointers directly
	assert((*ptr).x == 10 && p.x == 10);

	let maybe: nullable *point = null;
	assert(maybe == null);
	maybe = ptr;                // *T converts to nullable *T
	let sure = maybe as *point; // checked: aborts if null
	assert(sure.y == 2);

	let a = [1, 2, 3];
	let many: *[*]int = &a;     // no bounds checks through *[*]T,
	assert(unsafe { many[2] } == 3); // so indexing it is unsafe
}

A nullable pointer cannot be dereferenced until it has been checked, with match, if let, as or ??:

lora 
let p: nullable *int = null;
let v = *p; // error: Cannot dereference a nullable pointer
lora 
let p: *int = null; // error: Initializer of type null is not assignable to binding type *int

Pointer arithmetic moves a pointer by whole elements: p + n, n + p, p - n, p += n, p++. The distance between two pointers of the same type, p - q, is an element count of type i64, and pointers can be ordered with <, <=, > and >=. Nothing is bounds-checked, so it is unsafe: keep pointers inside the array they point into (slices and indexing are checked, and are usually the better choice).

lora 
type pt = struct { x: i64, y: i64 }

export fn main() void = unsafe {
	let a = [10, 20, 30, 40];
	let p = &a[0];
	let q = p + 2;                    // two ints along
	assert(*q == 30 && *(q - 1) == 20 && q - p == 2);
	p += 3;
	p--;
	assert(*p == 30 && p > &a[0]);
	let pts = [pt { x = 1, y = 2 }, pt { x = 3, y = 4 }];
	let second = &pts[0] + 1;         // moves by size_of(pt) bytes
	assert(second.x == 3);
}

Arithmetic needs a non-nullable pointer to something with a size, and cannot add two pointers:

lora 
let a = 1;
let o: *opaque = &a;
let o2 = o + 1; // error: Cannot do arithmetic on this pointer: what it points to has no size
lora 
let a = 1;
let n: nullable *int = &a;
let m = n + 1; // error: Cannot do arithmetic on this pointer: a nullable pointer may be null

Partial borrows

A view, *T.{fields}, is a pointer to a struct or union through which only the fields it names can be reached: a borrow of part of a value. const before a field lets it be read but not changed, and *const T.{a, b} is *T.{const a, const b}. A pointer to the whole converts to a view implicitly, and a view to a view of fewer fields; &x.{fields} names the view where it is taken.

lora 
type foo = struct { a: usize, b: u32, label: str }

fn increment_b(f: *foo.{b}) void = {
	f.b += 1;
}

fn total(f: *foo.{const a, const b}) usize = f.a + @usize(f.b);

export fn main() void = {
	let x = foo { a = 101, b = 42, label = "x" }
	let a = &x.a;
	increment_b(&x);         // &x is *foo; it narrows to *foo.{b}
	*a += 1;                 // the call could not reach x.a
	increment_b(&x.{b});     // the view, named
	assert(x.a == 102 && x.b == 44 && total(&x) == 146);
}

Through a view, other fields cannot be read or changed, the whole value cannot be dereferenced or passed on as *T, and const fields cannot be changed. @*T(view) converts back explicitly, outside these rules.

lora 
type foo = struct { a: usize, b: u32 }

fn peek(f: *foo.{b}) usize = f.a; // error: `a` is not part of the view *foo.{b}: a view reaches only the fields it names
fn grab(f: *foo.{b}) *foo = f; // error: Expression result type *foo.{b} is not assignable to function result type *foo
fn reset(f: *foo.{const b}) void = { f.b = 0; } // error: Cannot change this: the view it is reached through has 'const b'
export fn main() void = void;

A view promises its callee that the fields it names are reached no other way during the call, so one call cannot also pass a pointer that reaches one of them, if either can change it. Disjoint fields are fine:

lora 
type foo = struct { a: usize, b: u32 }

fn both(f: *foo.{b}, a: *usize) void = { f.b += 1; *a += 1; }
fn twice(f: *foo.{b}, b: *u32) void = void;

export fn main() void = {
	let x = foo { a = 1, b = 2 }
	both(&x, &x.a);   // x.b and x.a: disjoint
	twice(&x, &x.b); // error: Arguments 1 and 2 both reach 'x.b', and one can change it
}

An interface method can take a view of its receiver, as in fn step(c: *counter.{n}) void, so it is known to change only n.

Arrays

[N]T is a fixed-size array. It is a value: assigning or passing it copies all its elements. [_]T takes the length from the initializer, and [v...] fills the rest of an array with v:

lora 
let a: [_]int = [1, 2, 3];            // [3]int
let zeros: [64]u8 = [0...];
let grid: [3][3]int = [[0...]...];    // arrays of arrays
grid[1][2] = 5;
let b = a;                            // a copy
b[0] = 99;
assert(a[0] == 1 && len(a) == 3 && grid[1][2] == 5);
let c: [len(a)]int = [0...];          // len of an array is a constant
assert(len(c) == 3);

Indexing is bounds-checked. A constant index past the end is a compile error, any other one aborts at run time:

lora 
let a = [1, 2, 3];
let x = a[5]; // error: Index must be less than the array's length
lora 
// aborts
let a = [1, 2, 3];
let i = 5z;
let x = a[i];     // slice or array access out of bounds

Slices

[]T is a view of an array: a pointer, a length and a capacity. Slicing (a[lo..hi], either end optional) makes a view that shares the elements:

lora 
let a = [1, 2, 3, 4];
let s = a[1..3];      // [2, 3]
s[0] = 20;
assert(a[1] == 20 && len(s) == 2);
let all = a[..];
let tail = a[2..];
assert(len(all) == 4 && tail[0] == 3);

Slices that own heap memory are grown with append and insert, shrunk with delete and released with free (see Memory).

A slice is a span: it views elements it does not own, and the compiler tracks what it points into, so a view never outlives its array (L0608). Three forms say more about what a view may do:

FormWhat it is
[]const Ta view that only reads: no assigning, & gives *const T, no append or delete
@*[n]T(s)a view of exactly n elements, checked once: indexing it needs no more checks
at(s, i)element i of a slice or array as a pointer, or null when there is none

[]T and arrays pass where []const T is wanted, and not the other way:

lora 
fn total(xs: []const int) int = {
	let t = 0;
	for (let x .. xs) t += x;
	return t;
}

export fn main() void = {
	let v = [1, 2, 3, 4];
	assert(total(v) == 10 && total(v[1..]) == 9);
	let four = @*[4]int(v[..]);       // aborts unless len is 4
	four[0] = 7;
	assert(v[0] == 7);
	match (at(v, 9)) {
		let p: *int => *p = 0,
		null => void,                     // no element 9: handled, not a stop
	}
}
lora 
let xs: []const int = [1, 2];
xs[0] = 1; // error: Cannot change this: it is an element of a []const slice.
lora 
let xs: []const int = [1, 2];
let p = @*[2]int(xs); // error: A []const slice is only read through, and so is a view of it.

A view of a []const T is @*const [n]T(s), and at on one gives nullable *const T. Returning at(a, i) or @*[n]T(a) of a local array is L0608, as returning a[..] is.

Strings

A str is UTF-8 bytes. len(s) counts bytes. Strings compare with == and !=, and the strings module does everything else:

lora 
use strings;

export fn main() void = {
	let s = "héllo";
	assert(len(s) == 6);                         // bytes, not characters
	assert(strings::runecount(s) == 5);
	assert(s == "héllo" && s != "hello");
	let bytes = strings::to_bytes(s);
	assert(bytes[0] == @u8('h'));
	let up = strings::toupper(s)!;
	defer free(up);
	assert(strings::has_prefix(up, "H"));
}

s[a..b] is the bytes a to b of a string, as a str that borrows them: no copy is made. A bound may not fall inside a character, which would leave invalid UTF-8: that is a compile error for a constant string and bounds, and aborts at run time otherwise, saying where.

lora 
export fn main() void = {
	let s = "héllo";
	assert(s[..3] == "hé" && s[3..] == "llo");   // é is two bytes
	let n = 1z;
	assert(s[n..3] == "é");
}
lora 
let s = "héllo"[..2]; // error: This slice 0..2 cuts a character: byte 2 is inside a multi-byte UTF-8 character.

What strings cannot do:

lora 
let s = "abc";
let c = s[0]; // error: Can only index into an array or a slice, but this is str
lora 
let s = "a" + "b"; // error: Cannot do arithmetic on a str
lora 
let lt = "a" < "b"; // error: Cannot order values of a str with <, >, <= or >=

Use strings::to_bytes(s)[i] or strings::at(s, i) for bytes, strings::concat or interpolation to join, and strings::compare to order.

Valid Usage & Examples

Affine heap ownership (^T), non-null pointers (*T), and nullable narrowing

Allocate on the heap with alloc(...), borrow with &x, and narrow nullable *T safely with if (let p: *T = ...) or ??.

lora Allowed 
export fn main() void = {
	let owned: ^int = alloc(42)!;
	let p: *int = &*owned;
	*p += 8;
	assert(*owned == 50);

	let maybe: nullable *int = null;
	let fallback = 7;
	assert(*(maybe ?? &fallback) == 7);

	maybe = p;
	if (let nonnull: *int = maybe) {
		assert(*nonnull == 50);
	}
}

Partial struct borrows (*T.{fields}) for disjoint field access

Restrict a function to only the fields it needs and mark read-only fields const, allowing callers to borrow disjoint fields simultaneously.

lora Allowed 
type State = struct {
	count: int,
	limit: int,
	label: str,
}

fn step(s: *State.{count, const limit}) bool = {
	if (s.count >= s.limit) return false;
	s.count += 1;
	return true;
}

export fn main() void = {
	let st = State { count = 0, limit = 3, label = "ok" }
	assert(step(&st) && st.count == 1);
}

Fixed arrays, checked slices, sub-slicing, and UTF-8 strings

Arrays coerce to slices []T, sub-slices [start..end] are bounds-checked, and str slices validate UTF-8 rune boundaries.

lora Allowed 
export fn main() void = {
	let arr: [4]int = [10, 20, 30, 40];
	let sl: []int = arr[1..3];
	assert(len(sl) == 2z && sl[0] == 20 && sl[1] == 30);

	let s = "hello, lora";
	assert(s[0..5] == "hello" && len(s) == 11z);
}

Disallowed Forms & Diagnostics

Dereferencing an unchecked nullable pointer or mutating a const view field

Dereferencing nullable *T without narrowing is rejected, and writing to a const field in *T.{const f} triggers L0202.

L0202: Cannot assign to `const` field in partial view `*T.{const f}`
lora Rejected 
type Pair = struct { a: int, b: int }
fn bad(p: *Pair.{a, const b}) void = {
	p.b = 10; // error[L0202]: b is const in this view
}
export fn main() void = void;
lora Allowed 
type Pair = struct { a: int, b: int }
fn good(p: *Pair.{a, const b}) void = {
	p.a = p.b + 1; // ok: a is mutable, b is readable
}
export fn main() void = {
	let pr = Pair { a = 0, b = 5 }
	good(&pr);
	assert(pr.a == 6);
}

Using an affine ^T owner after it has been moved

Moving a ^T into another binding or function consumes the source binding (L0600).

L0600: `p` was moved and can no longer be used
lora Rejected 
export fn main() void = {
	let p = alloc(10)!;
	let q = p;
	assert(*p == 10); // error[L0600]: p was moved to q
}
lora Allowed 
export fn main() void = {
	let p = alloc(10)!;
	let q = p;
	assert(*q == 10); // ok: use new owner q after moving from p
}

Runtime Aborts

Out-of-bounds slice/array indexing or mid-rune string slicing aborts

Indexing xs[i] with i >= len(xs) or slicing a str inside a multi-byte UTF-8 sequence aborts cleanly.

lora Aborts 
// aborts
export fn main() void = {
	let xs = [1, 2, 3];
	let _ = xs[5]; // abort: index 5 out of bounds for length 3
}
lora Allowed 
export fn main() void = {
	let xs = [1, 2, 3];
	let idx = 5z;
	let v = if (idx < len(xs)) xs[idx] else 0; // ok: bounds-checked before indexing
	assert(v == 0);
}
