Standard Library

xml — XML 1.0 with namespaces

Module xml (lib/xml.lora) exports 47 declarations. Import with use xml;.

Overview

The xml module provides a namespace-aware streaming XML reader (new_reader, stream_reader), streaming XML writer (new_writer, stream_writer), and tag-driven struct marshal / unmarshal.

Tokens yielded by xml::next form a tagged union: start, end, chardata, comment, proc_inst, and directive. By default (options.strict = true, options.namespaces = true), xml enforces well-formedness, resolves xmlns prefix bindings, validates XML names and characters, and reports errors with 1-based line and column numbers.

Struct fields support @xml(...) tags with name (including a>b>c element paths), space, attr, chardata, innerxml, comment, omit_empty, and skip.

Valid Usage & Examples

Pull-parse namespaced XML tokens

Use xml::new_reader and xml::next to inspect elements, resolved namespace URIs, attributes, and character data.

lora Allowed 
use xml;

export fn main() void = {
	let doc = "<note xmlns=\"urn:n\" id=\"7\"><to>Ada &amp; Bob</to></note>";
	let rd = xml::new_reader(doc);
	let s = xml::next(&rd)! as xml::start;
	assert(s.name.space == "urn:n" && s.name.local == "note");
	assert(s.attrs[0].name.local == "id" && s.attrs[0].value == "7");

	let to = xml::next(&rd)! as xml::start;
	assert(to.name.local == "to");
	let txt = xml::next(&rd)! as xml::chardata;
	assert(txt.text == "Ada & Bob");
}

Marshal and unmarshal structs with @xml path and attribute tags

Map attributes (attr), text content (chardata), and nested paths (a>b) via @xml tags.

lora Allowed 
use expanse;
use xml;

type book = struct {
	@xml("isbn", attr) isbn: str,
	@xml("meta>title") title: str,
	@xml(chardata) summary: str,
}

export fn main() void = {
	let b = book { isbn = "978-0", title = "Lora", summary = "Systems" };
	let out = xml::marshal(&b, "book")!;
	defer free(out);

	let reg = expanse::auto();
	defer expanse::finish(&reg);
	let back = xml::unmarshal::[book](&reg, out)!;
	assert(back.isbn == "978-0" && back.title == "Lora" && back.summary == "Systems");
}

Write formatted XML with xml::writer

Use xml::new_writer with indent, put_header, put_start, put_text, and put_end to emit well-formed XML.

lora Allowed 
use strings;
use xml;

export fn main() void = {
	let out: ^[]u8 = [];
	defer free(out);
	let wr = xml::new_writer(&out, xml::options { indent = "  ", ... });
	xml::put_header(&wr)!;
	xml::put_start(&wr, xml::name { space = "", local = "msg" }, [])!;
	xml::put_text(&wr, "a < b & c")!;
	xml::put_end(&wr)!;
	xml::flush(&wr)!;
	assert(strings::contains_str(strings::from_bytes(out), "a &lt; b &amp; c"));
}

Disallowed Forms & Diagnostics

Unbound namespace prefix or mismatched closing tag

With namespaces = true (the default), using an undeclared prefix or mismatched end tag fails with xml::invalid.

xml::invalid: invalid XML at line 1, column 1: a prefix no xmlns attribute binds
lora Rejected 
use xml;

export fn main() void = {
	let rd = xml::new_reader("<p:item/>");
	let _ = xml::next(&rd)!; // error: undeclared namespace prefix 'p'
}
lora Allowed 
use xml;

export fn main() void = {
	let rd = xml::new_reader("<p:item xmlns:p=\"urn:p\"/>"); // ok: binds prefix 'p' with xmlns:p
	let s = xml::next(&rd)! as xml::start;
	assert(s.name.space == "urn:p" && s.name.local == "item");
}

Constraints & Limits

Single root element
Required
Multiple root elements or text outside root fail with `reason::outside_root` or `reason::no_root`.
Comment syntax
No `--` inside
`--` inside `<!-- ... -->` is rejected per XML 1.0 (`reason::bad_comment`).
Error field name
48 bytes
`mismatch.field` and `missing.field` truncate at 48 bytes.

Module Guide & Examples

XML 1.0, with namespaces: a reader of tokens, from text or from a file as it comes, a writer, and structs read and written whole by @xml tags.

let rd = xml::new_reader(text); for (true) match (xml::next(&rd)?) { done => break, let s: xml::start => ..., // s.name.space, s.name.local, s.attrs let t: xml::chardata => ..., // good until the next call ... };

type item = struct { @xml(attr) id: int, name: str, @xml("tags>tag") tags: []str }; let it = xml::unmarshal::[item](&region, text)?; let text = xml::marshal(&it)?; // ......

Reading is strict, as XML is: one root element, names and entities as the grammar has them, every element closed by its own end tag, no prefix that is not bound. Errors give the line and column of the byte at fault.

Reading is strict, as XML is: one root element, names and the five entities and character references as the grammar has them, attribute values in quotes and never given twice, every element closed by its own end tag, <?xml ...?> only at the start, no -- in a comment, no prefix that is not bound. invalid says why and gives the line and column. Line breaks are read as \n, and in attribute values as spaces. With namespaces, a name's space is the URL its prefix (or the default) is bound to; xml is bound to XML_NAMESPACE. A text and a file are read alike.

The writer escapes text and attribute values, declares a default namespace where an element's space changes (a space of "" keeps the default), reuses a prefix bound in scope for an attribute's namespace or binds one, and refuses names, comments and characters XML does not have.

marshal and unmarshal write and read a struct as an element (named by root, or its type's name), field by field; elements no field takes are skipped, and a field nothing gave is left zero, void if optional, or missing if zero is not one of its type's values. Fields are strings, []u8, bool, integers, floats, enums by member name, time::datetime, types with a text form, structs, (T | void), and slices of these, an element each. Tags:

lora 
type person = struct {
	@xml(attr) id: int,                     // <person id="7">
	name: str,                              // <name>...</name>
	@xml("contact>phone") phones: []str,    // <contact><phone>1</phone><phone>2</phone></contact>
	@xml(chardata) text: str,               // the element's own text
	@xml(innerxml) body: str,               // its contents, as XML, as they are
	@xml(comment) note: str,                // <!--...-->
	@xml(omit_empty) nick: str,             // left out when "", 0, false, empty or void
	@xml(space = "urn:x") x: str,           // an element in a namespace
	@xml(skip) cache: int,
}

A type that writes or reads itself implements xml::marshaler or xml::unmarshaler. Tags that contradict one another, and two fields of one element or attribute name, are refused when compiling.
