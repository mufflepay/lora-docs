Standard Library

thread — OS threads, mutexes, condition variables, atomics

Module thread (lib/thread.lora) exports 33 declarations. Import with use thread;.

Overview

OS threads, mutexes, condition variables, lock-guarded values, and 64-bit atomic operations.

thread::thread is a move-only @sealed handle (impl drop) wrapping a rt::pthread_t. A thread that is neither joined nor detached before being dropped is automatically detached by its drop implementation so its OS resources do not leak. Because a spawned thread may outlive the caller's stack frame, spawn only accepts a closure() void that captures owned or copied values, while spawn_with[T](v, body) moves an owned value v: T (such as an arc::arc[T]) onto the heap and passes it to the new thread.

Each OS thread lazily initializes its own @threadlocal scratch region (thread_scratch()) and installs an alternate crash-reporting signal stack (rt::alt_stack_begin()), automatically cleaning up the scratch region when the thread exits.

Valid Usage & Examples

Spawning threads with arc-shared atomic state

Share an atomic counter across OS threads using arc::new, arc::share, thread::spawn_with, and thread::join_all.

lora Allowed 
use arc;
use thread;

export fn main() void = {
	let hits = arc::new(thread::new_atomic(0u64))!;
	let workers: ^[]thread::thread = [];
	for (let i = 0z; i < 4z; i += 1z) {
		let t = thread::spawn_with(arc::share(&hits), fn(a: arc::arc[thread::atomic]) void = {
			for (let j = 0u64; j < 1000u64; j += 1u64) {
				thread::add(arc::get(&a), 1u64);
			}
		})!;
		append(workers, t)!;
	}
	thread::join_all(&workers);
	assert(thread::load(arc::get(&hits)) == 4000u64);
}

Protecting shared state with shared[T] and with

Wrap mutable state in thread::shared[T] and access it exclusively inside thread::with closures, which acquire and release the internal mutex via defer.

lora Allowed 
use arc;
use thread;

export fn main() void = {
	let total = arc::new(thread::new_shared(0))!;
	let t1 = thread::spawn_with(arc::share(&total), fn(s: arc::arc[thread::shared[int]]) void = {
		thread::with(arc::get(&s), fn(v: *int) void = {
			*v += 10;
		});
	})!;
	let t2 = thread::spawn_with(arc::share(&total), fn(s: arc::arc[thread::shared[int]]) void = {
		thread::with(arc::get(&s), fn(v: *int) void = {
			*v += 32;
		});
	})!;
	thread::join(t1);
	thread::join(t2);
	thread::with(arc::get(&total), fn(v: *int) void = {
		assert(*v == 42);
	});
}

Coordinating threads with mutex and cond

Use thread::mutex and thread::cond to block a consumer thread until a producer signals readiness.

lora Allowed 
use arc;
use thread;

type gate = struct {
	mu: thread::mutex,
	cv: thread::cond,
	ready: bool,
}

export fn main() void = {
	let g = arc::new(gate {
		mu = thread::new_mutex(),
		cv = thread::cond { ... },
		ready = false,
	})!;
	let t = thread::spawn_with(arc::share(&g), fn(gp: arc::arc[gate]) void = {
		let p = arc::get(&gp);
		thread::lock(&p.mu);
		p.ready = true;
		thread::signal(&p.cv);
		thread::unlock(&p.mu);
	})!;

	let p = arc::get(&g);
	thread::lock(&p.mu);
	for (!p.ready) {
		thread::wait(&p.cv, &p.mu);
	}
	thread::unlock(&p.mu);
	thread::join(t);
}

Disallowed Forms & Diagnostics

Capturing a non-Send stack reference in thread::spawn

An OS thread can outlive the caller frame, so thread::spawn rejects closures that borrow local stack variables by pointer; move owned state via thread::spawn_with and arc instead.

E_CLOSURE_ESCAPE: cannot capture local variable by reference in a closure passed to thread::spawn
lora Rejected 
use thread;

export fn main() void = {
	let count = 0;
	let t = thread::spawn(fn() void = { // error: cannot capture local stack variable by reference
		count += 1;
	})!;
	thread::join(t);
}
lora Allowed 
use arc;
use thread;

export fn main() void = {
	let count = arc::new(thread::new_atomic(0u64))!;
	let t = thread::spawn_with(arc::share(&count), fn(a: arc::arc[thread::atomic]) void = { // ok: moves owned arc handle into thread
		thread::add(arc::get(&a), 1u64);
	})!;
	thread::join(t);
}

Constraints & Limits

64-bit (u64)
thread::atomic wraps a single u64 word; use sync for typed atomic_bool, atomic_i64, atomic_usize, and atomic_ptr[T].
Thread drop behavior
Auto-detach
Dropping an unjoined, undetached thread calls pthread_detach instead of blocking.
Lock failure
Aborts on OS error
mutex_init, lock, unlock, cond_init, wait, signal, and broadcast assert 0 return from pthread calls.

Module Guide & Examples

OS threads, mutexes, condition variables and atomic counters.

let total = arc::new(thread::atomic { ... })!; let t = thread::spawn_with(arc::share(&total), fn(n: arc::arc[thread::atomic]) void = { thread::add(arc::get(&n), 1); })!; thread::join(t);

A thread may outlive the code that started it, so it takes only what it owns, which the compiler checks: copies its closure captures, and a value given to spawn_with, such as an arc share of what it works on. Work that uses a function's own locals belongs in @all or @scope (see coro), which run it in parallel on worker threads and wait for it.

Threads are pthreads. A thread runs a closure, which copies what it captures, so give it pointers to shared data and make that data thread-safe: an atomic, a shared[T], or data changed only between lock and unlock. The compiler reports threads changing other shared data (L0700, see "Data races" in the language reference). The atomics are sequentially consistent (ldaddal/casal on arm64, lock xadd/cmpxchg on x86_64).

A thread is joined or detached once: it is moved, never copied, and one dropped with neither is detached, to finish on its own. Keep several in a ^[]thread and join_all them. The types here are @sealed: an atomic's value is reached by its functions, a shared value through its lock. Each zero value is ready to use: mutex { ... } and cond { ... }, an atomic { ... } holding 0, and thread { ... }, no thread, which join and detach leave alone.
