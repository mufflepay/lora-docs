otp — RFC 4226 HOTP and RFC 6238 TOTP

Module otp (lib/otp.lora) exports 17 declarations. Import with use otp;.

Overview

otp implements RFC 4226 HOTP (counter-based) and RFC 6238 TOTP (time-based) one-time passwords, Base32 secret encoding/decoding, constant-time code verification, and otpauth:// provisioning URI formatting and parsing.

HMAC digests inside hotp are wiped with defer crypto::wipe(mac[..]) before returning, and both verify_totp_at and verify_hotp compare candidate codes using crypto::equal to avoid timing leaks.

Valid Usage & Examples

Generating and verifying TOTP codes with clock skew

Compute a zero-padded TOTP code at a Unix timestamp with totp_code_at and verify it within a skew window using verify_totp_at.

lora Allowed 
use otp;
use strings;

export fn main() (void | otp::bad_otp | nomem) = {
	let key = strings::to_bytes("12345678901234567890");
	let code = otp::totp_code_at(key, 59u64, 30u64, 8u8, otp::algorithm::sha1)?;
	assert(code == "94287082");

	let ok = otp::verify_totp_at(key, code, 75u64, 1u64, 30u64, 8u8, otp::algorithm::sha1)?;
	assert(ok);
}

HOTP verification with lookahead counter resynchronization

verify_hotp scans counter .. counter + lookahead and returns the next expected counter (matched + 1) on success or void on mismatch.

lora Allowed 
use otp;
use strings;

export fn main() (void | otp::bad_otp | nomem) = {
	let key = strings::to_bytes("12345678901234567890");
	let expected_2 = otp::hotp_code(key, 2u64)?;
	assert(expected_2 == "359152");

	match (otp::verify_hotp(key, "359152", 0u64, 3u64)?) {
		let next_counter: u64 => assert(next_counter == 3u64),
		void => abort("expected HOTP match"),
	}
}

Building and parsing `otpauth://` provisioning URIs

Generate a random 20-byte secret, format an otpauth:// URI with format_uri, and round-trip it through parse_uri.

lora Allowed 
use otp;
use strings;

export fn main() (void | otp::bad_otp | nomem) = {
	let sec = otp::generate_secret(20z)?;
	let issuer = strings::clone("LoraApp")?;
	let account = strings::clone("alice@example.com")?;
	let cfg = otp::config {
		kind = otp::kind::totp,
		issuer = issuer,
		account = account,
		secret = sec,
		alg = otp::algorithm::sha256,
		digits = 6u8,
		period = 30u64,
		counter = 0u64,
	};
	let uri = otp::format_uri(&cfg)?;
	let parsed = otp::parse_uri(uri)?;
	assert(parsed.issuer == "LoraApp" && parsed.digits == 6u8);
}

Disallowed Forms & Diagnostics

Discarding `bad_otp | nomem` from `hotp_code` or `verify_totp`

OTP functions validate secrets, digit counts (6..10), periods (> 0), and skew/lookahead bounds (<= 1000), returning bad_otp on invalid inputs (L0003).

L0003: Unhandled error: (otp::bad_otp | nomem) must be propagated or handled
lora Rejected 
use otp;
use strings;

export fn main() void = {
	let code = otp::hotp_code(strings::to_bytes("secret"), 0u64); // error: unhandled error union
}
lora Allowed 
use otp;
use strings;

export fn main() (void | otp::bad_otp | nomem) = {
	let code = otp::hotp_code(strings::to_bytes("12345678901234567890"), 0u64)?; // ok: propagate bad_otp | nomem
	assert(len(code) == 6z);
}

Constraints & Limits

Code digits
6 to 10 digits
`digits < 6 || digits > 10` returns `bad_otp`.
Skew / lookahead cap
≤ 1000 steps
`verify_totp_at` (`skew > 1000`) and `verify_hotp` (`lookahead > 1000`) return `bad_otp` to bound CPU work.
Secret length
≥ 1 byte (default 20 bytes)
Empty secrets return `bad_otp`; `generate_secret` defaults to 20 bytes (160 bits).
TOTP period
≥ 1 second (default 30s)
`period == 0` returns `bad_otp`.
  • decode_secret strips spaces, hyphens, tabs, and = padding and normalizes ASCII to uppercase before Base32 decoding.
  • verify_totp_at evaluates every step in [base_step - skew, base_step + skew] without early return so timing does not leak which offset matched.
