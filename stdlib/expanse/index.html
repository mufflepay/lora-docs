expanse — memory that grows in place

Module expanse (lib/expanse.lora) exports 34 declarations. Import with use expanse;.

Overview

expanse implements virtual-memory region allocators that reserve a large address range up front (mmap with PROT_NOACCESS) and commit pages on demand (mprotect with PROT_RW). Because the virtual range never moves, pointers and slices into a region or array[T] remain valid until reset, rewind, or finish.

Valid Usage & Examples

Stable pointers across page commits with reserve

Reserving virtual address space (even gigabytes) commits physical pages lazily as objects are allocated, so linked structures never move.

lora Allowed 
use expanse;

type node = struct { value: int, next: nullable *node }

export fn main() void = {
	let r = expanse::reserve(4 * expanse::GIB)!;
	defer expanse::finish(&r);

	let first = expanse::new(&r, node { value = 1, next = null })!;
	let second = expanse::new(&r, node { value = 2, next = null })!;
	first.next = second;

	assert(expanse::contains(&r, first));
	assert(first.next != null && (@*node(first.next)).value == 2);
}

Self-sizing auto() region with checkpoints and shrink

expanse::auto() reserves AUTO (64 MiB) on first use and chains doubled ranges as needed. here/rewind reclaim temporary work across range boundaries.

lora Allowed 
use expanse;

export fn main() void = {
	let r = expanse::auto();
	defer expanse::finish(&r);
	let kept = expanse::copy(&r, "persistent")!;
	assert(kept == "persistent");
	let used_before = expanse::used(&r);
	let m = expanse::here(&r);

	let tmp = expanse::make::[u8](&r, 2 * expanse::MIB)!;
	tmp[0] = 42;
	expanse::rewind(&r, m);

	assert(expanse::used(&r) == used_before);
	expanse::reset(&r);
	expanse::shrink(&r)!;
	assert(expanse::committed(&r) == 0);
}

Pointer-stable growable array[T]

expanse::array[T] grows in place without copying elements, so pointers returned by push stay valid as more elements are added.

lora Allowed 
use expanse;

export fn main() void = {
	let a = expanse::array_new::[int](1000000)!;
	defer expanse::array_finish(&a);

	let first = expanse::push(&a, 10)!;
	for (let i = 0; i < 10000; i += 1) {
		expanse::push(&a, i)!;
	}
	assert(*first == 10);
	let all = expanse::items(&a);
	assert(len(all) == 10001 && &all[0] == first);
	assert(expanse::pop(&a) as int == 9999);
}

Disallowed Forms & Diagnostics

Storing owning types in a region or expanse::array

Regions free all memory in bulk without running element destructors, so new, make, and push reject types that own heap memory.

Compile error: A region frees everything at once and drops nothing, so what it holds can't own memory
lora Rejected 
use expanse;
use strings;

export fn main() void = {
	let r = expanse::auto();
	let s = strings::concat("a", "b")!;
	let p = expanse::new(&r, s)!; // error: region rejects @owns(T) values
}

Use expanse::copy to copy string data directly into the region as a borrowed str.

lora Allowed 
use expanse;

export fn main() void = {
	let r = expanse::auto();
	let s = expanse::copy(&r, "ab")!; // ok: copies bytes into region as borrowed str
	assert(s == "ab");
}

Constraints & Limits

Commit step
1 MiB minimum
Pages are committed in steps of max(1 MiB, page_size) + 50% of current used size.
Auto range sizing
64 MiB to 1 TiB
expanse::auto() starts at AUTO (64 MiB) and doubles up to LARGEST (1 TiB) per chained range.
take alignment
Power of 2 <= page
expanse::take requires alignment to be a power of two and no larger than the OS page size.
Thread safety
Single-threaded
A region is not synchronised; wrap or isolate per thread.

Module Guide & Examples

Memory that grows in place. A region reserves a large range of address space up front, far more than it will ever need, without committing it: that costs next to nothing. As it fills, it commits more pages at the end of the range, so it grows without moving, and a pointer into it stays good until the region is reset or finished.

let r = expanse::reserve(64 * expanse::GIB)!; defer expanse::finish(&r); let n = expanse::new(&r, node { value = 1 })!; // n never moves

Everything in a region is freed at once, with reset or finish; nothing in it is freed alone. It suits data that lives and dies together: a request, a frame, a parse tree, a compiler pass.

A region from auto has no size to choose: it reserves AUTO of address space when it is first used, and when that fills, another range twice as large, and so on. What it holds still never moves.

An array[T] is a growable array in a region of its own: unlike a slice grown with append, it never copies its elements, so pointers to them stay good as it grows.

A region is for one thread at a time. What goes in it is plain data: owners stored in it are not dropped.

As it fills, it commits more pages at the end of the range, so it grows without moving: a pointer into it stays good until the region is reset or finished, and growing never copies.

expanse::auto() chooses no size: it reserves nothing until something is put in it, then AUTO (64 MiB) of address space, which takes no memory until pages are used. When that fills it reserves another range, twice as large (or as large as one thing asked for), and goes on there: what it holds never moves, and thousands of auto regions can be in use at once. A region owned by a block, a coroutine's body or a request lives as long as it does, with no size to guess:

lora 
use expanse;

fn names(n: int) usize = {
	let r = expanse::auto();               // freed when the function ends
	let total = 0z;
	for (let i = 0; i < n; i += 1) {
		let s = expanse::copy(&r, "a name")!;
		total += len(s);
	}
	return total;
}

export fn main() void = assert(names(1000) == 6000);

What a region holds is a view of it, checked as any view is: it can't be stored where it outlives the region, nor used after reset, rewind, shrink or finish (L0608, L0609). Taking more from a region ends nothing taken before. Its fields are this module's alone (@sealed): its zero value, region { ... }, which blank tells, holds nothing, and anything asked of it fails as full. A struct can hold a region with views of what it holds, as json::document does: moving the region moves no memory.

use expanse;

type node = struct { value: int, next: nullable *node }

export fn main() void = {
	let r = expanse::reserve(64 * expanse::GIB)!;   // takes no memory yet
	defer expanse::finish(&r);
	let first = expanse::new(&r, node { value = 1, next = null })!;
	for (let i = 2; i <= 100000; i += 1) {
		expanse::new(&r, node { value = i, next = null })!;
	}
	assert(first.value == 1);                       // first never moved

	let a = expanse::array_new::[int](1000000000)!; // room for 10^9
	defer expanse::array_finish(&a);
	let p = expanse::push(&a, 7)!;
	for (let i = 0; i < 100000; i += 1) expanse::push(&a, i)!;
	assert(*p == 7 && len(expanse::items(&a)) == 100001);
}

Sizes. KIB, MIB, GIB and TIB are a kibibyte, a mebibyte, a gibibyte and a tebibyte in bytes (1024, 1024², 1024³, 1024⁴), the units reserve is given its size in: expanse::reserve(64 * expanse::GIB) rather than 68719476736. AUTO, the address space an auto region reserves when it is first used, is 64 MIB; each range after is twice the last, up to a TIB at a time. A region commits pages at least one MIB at a time. KIB suits a small region: expanse::reserve(64 * expanse::KIB).

When to use one. For data that lives and dies together: a request, a frame, a parse tree, a compiler pass. Measured on an M-series Mac, for ten million small nodes:

makefreetotal
alloc and free165 ms115 ms280 ms
expanse::new and finish85 ms2 ms87 ms

For a large growing array, push is about 20% slower than append, which macOS can often grow in place too: use array when something points into it, since a slice's append may move every element. Five thousand auto regions in use at once take 30 ms to make, and memory only for the pages they use.

make clears only memory that may hold old values, after rewind or reset: fresh pages are zero already, so a large make on a new region touches nothing (50 of 256 MiB each take 4 ms, where clearing them took 7 s), and copy writes each byte once.

How it works. reserve maps the range with no access (mmap with PROT_NONE), and committing makes the next pages usable (mprotect), so touching memory past what is committed faults instead of corrupting anything. Page size comes from the system (16 KiB on Apple Silicon). Commits grow with the region, so they are rare. shrink replaces pages with fresh inaccessible ones, which gives them back. An auto region's ranges each start with a few bytes that link them; rewind and reset keep the later ranges, so filling the region again costs no system call, and shrink gives them back.

Rules.

  • Choose a reservation far bigger than you expect to need: it is the most the region can ever hold (full), and costs next to nothing.
  • Nothing in a region is freed alone: never free a pointer from one.
  • reset, rewind and finish end what they give back, and the compiler does not follow pointers past them. reset_poisoned makes a stale pointer read 0xcc at once, for finding such bugs.
  • Store plain data: owners (^T) put in a region are not dropped.
  • A region is for one thread at a time; the compiler reports threads changing one they share (L0700).
  • The compiler reports pointers to locals stored in a region (L0104).

new, make and push refuse a type that owns memory: a region frees everything at once, and drops nothing.
