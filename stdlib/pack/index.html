Standard Library

pack — values as bytes that describe themselves

Module pack (lib/pack.lora) exports 20 declarations. Import with use pack;.

Overview

The pack module is Lora's self-describing binary serialization format for arbitrary Lora types: primitives, str, []u8, time::datetime, uuid::uuid, enum, struct, slices, arrays, optionals ((T | void)), and custom types implementing encoding::binary_encoder / binary_decoder.

Each encoder stream writes a type descriptor before a type's first value, so subsequent values of the same type reuse compact type IDs. Decoders validate wire types, UTF-8 strings, enum members, and nesting depth, and support forward/backward field evolution: unknown struct fields are skipped and missing optional/zeroable fields take their zero value.

Valid Usage & Examples

Round-trip a rich struct with pack::marshal and pack::unmarshal

Serialize structs containing strings, slices, optionals, enums, and nested structs into an expanse::region.

lora Allowed 
use expanse;
use pack;

type role = enum { reader, writer }
type account = struct {
	id: u64,
	name: str,
	role: role,
	nick: (str | void),
}

export fn main() void = {
	let m = expanse::reserve(expanse::MIB)!;
	defer expanse::finish(&m);

	let a = account { id = 9, name = "Ada", role = role::writer, nick = void };
	let bytes = pack::marshal(&a)!;
	defer free(bytes);

	let back = pack::unmarshal::[account](&m, bytes)!;
	assert(back.id == 9 && back.name == "Ada" && back.nick is void);
}

Stream multiple typed messages over one encoder/decoder

Use pack::new_encoder and pack::new_decoder to send multiple values while describing each type only once.

lora Allowed 
use expanse;
use pack;

type point = struct { x: i32, y: i32 }

export fn main() void = {
	let buf: ^[]u8 = [];
	defer free(buf);
	let enc = pack::new_encoder(&buf);
	pack::encode(&enc, &point { x = 1, y = 2 })!;
	pack::encode(&enc, &point { x = 3, y = 4 })!;

	let m = expanse::auto();
	defer expanse::finish(&m);
	let dec = pack::new_decoder(buf);
	let p1 = pack::decode::[point](&dec, &m)! as point;
	let p2 = pack::decode::[point](&dec, &m)! as point;
	assert(p1.x == 1 && p2.y == 4);
	assert(pack::decode::[point](&dec, &m)! is done);
}

Disallowed Forms & Diagnostics

Exceeding MAX_DEPTH or trailing bytes in unmarshal

Values nested past pack::MAX_DEPTH (64) fail with pack::too_deep on encode or pack::invalid (reason::too_deep) on decode.

pack::invalid: more in a message after its value
lora Rejected 
use expanse;
use pack;

export fn main() void = {
	let m = expanse::auto();
	defer expanse::finish(&m);
	let b = pack::marshal(&42i32)!;
	defer free(b);
	append(b, 0xffu8)!; // trailing garbage after message
	let _ = pack::unmarshal::[i32](&m, b)!; // error: trailing bytes return pack::invalid
}
lora Allowed 
use expanse;
use pack;

export fn main() void = {
	let m = expanse::auto();
	defer expanse::finish(&m);
	let b = pack::marshal(&42i32)!;
	defer free(b);
	assert(pack::unmarshal::[i32](&m, b)! == 42); // ok: exact message buffer without trailing bytes
}

Constraints & Limits

Max message size
64 MiB (`MAX_MESSAGE`)
Streams reject messages exceeding `64 * 1024 * 1024` bytes.
Max nesting depth
64 (`MAX_DEPTH`)
Enforced on both encode (`too_deep`) and decode (`reason::too_deep`).

Module Guide & Examples

pack: values as compact bytes that describe themselves. A stream says what each type is, once, before its first value; a reader matches struct fields and enum members by name, so the two ends may differ: fields one has and the other not are skipped or left zero, and integers of any width read as any other they fit.

let out: ^[]u8 = []; { let e = pack::new_encoder(&out); pack::encode(&e, &order { id = 1, items = ... })?; pack::encode(&e, &order { id = 2, items = ... })?; // its type is not sent again }; let d = pack::new_decoder(out[..]); for (true) match (pack::decode::[order](&d, &region)?) { done => break, let o: order => ..., };

The code that writes and reads each type is made while compiling.

The bytes: a stream is messages, each its length (a uvarint) and then a varint: a type's number, negated, before its description, or a type's number before a value of it. Numbers below 32 are the types every stream has; the rest are described: a struct (its name, and each field's name and type), a slice, an array (its length), an optional, or an enum (its name and its members' names). A value is a bool as a byte; an int as a zigzag varint, a uint as a uvarint; a float as its bits, bytes reversed, as a uvarint; a string or bytes as their length and themselves; a time as its Unix milliseconds; a slice or array as its count and elements; an optional as 0, or 1 and its value; an enum as its member's number; a struct as its fields that are not zero, each the difference from the last field's number and then its value, and a 0 at the end.

A stream describes each type once, before its first value: a struct's name and its fields' names and types, an enum's members' names, a slice's, array's or optional's elements. So a reader needs no schema but its own types, and the two ends may differ: struct fields are matched by name, a field the reader lacks is skipped, one the stream lacks is left zero (void if optional, missing if zero is not one of its type's values); enum members are matched by name; integers of any width and sign read as any other they fit, else out_of_range; an optional reads as what it holds. Values are bools, integers, floats, str, []u8, time::datetime, types with a text form, enums, structs, slices, arrays and optionals of them, and a type may hold itself through a slice. Strings and slices are put in the region. invalid says why and at which byte of the stream, and names the field. Each message is limited to MAX_MESSAGE bytes, and counts and lengths to what the message holds, so a stream can't make the reader take more memory than it sent. Values nested deeper than MAX_DEPTH (64) are invalid too, so a stream can't make it run out of stack either.

The bytes: a message is its length and a varint, a type's number before a value of it, or negated before its description. An int is a zigzag varint, a uint a uvarint, a float its bits reversed as a uvarint, a string or bytes its length and itself, a struct its non-zero fields as the difference from the last field's number and the value, then 0.
