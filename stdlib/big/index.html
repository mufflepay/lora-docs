Standard Library

big — integers, rationals and floats of any size

Module big (lib/big.lora) exports 125 declarations. Import with use big;.

Overview

big implements arbitrary-precision integer, exact rational ratio, and arbitrary-precision binary float arithmetic.

Each value owns its underlying 64-bit limbs (^[]u64), and every operation returns a new value so values are never aliased or mutated under a caller. Multiplication automatically switches from schoolbook to Karatsuba above KARATSUBA = 24 limbs. All three types implement encoding::text_encoder and encoding::text_decoder.

Valid Usage & Examples

Arbitrary-precision integer arithmetic and base-62 formatting

Parse large integers, multiply and exponentiate, and convert between base 10 and base 62.

lora Allowed 
use big;

export fn main() (void | big::invalid | nomem) = {
	let a = big::parse("123456789012345678901234567890", 10)?;
	let b = big::from_i64(-42)?;
	let p = big::mul(&a, &b)?;

	let s = big::text(&p, 10)?;
	defer free(s);
	assert(s == "-5185185138518518513851851851380");

	let b62 = big::text(&a, 62)?;
	defer free(b62);
	let back = big::parse(b62, 62)!;
	assert(big::equal(&a, &back));
}

Number theory: modular exponentiation, inverse, and primality

Compute x^e mod m, modular inverse, extended GCD, and Miller-Rabin primality testing.

lora Allowed 
use big;

export fn main() (void | big::invalid | nomem) = {
	let m = big::parse("170141183460469231731687303715884105727", 10)?; // 2^127 - 1
	assert(big::probably_prime(&m, 20)?);

	let x = big::from_i64(7)?;
	let e = big::from_i64(13)?;
	let p = big::exp_mod(&x, &e, &m)? as big::integer;

	let inv = big::mod_inverse(&x, &m)? as big::integer;
	let prod = big::mul(&x, &inv)?;
	let rem = big::rem(&prod, &m)?;
	assert(big::to_i64(&rem) as i64 == 1i64);
}

Exact rationals (`ratio`) and high-precision `big::float`

Perform exact rational arithmetic and 256-bit binary floating-point square roots.

lora Allowed 
use big;

export fn main() (void | big::invalid | nomem) = {
	let r1 = big::parse_ratio("1/3")?;
	let r2 = big::parse_ratio("1/6")?;
	let sum = big::ratio_add(&r1, &r2)?;
	let txt = big::ratio_text(&sum, true)?;
	defer free(txt);
	assert(txt == "1/2");

	let two = big::float_from_i64(2, 256u32)?;
	let root = big::float_sqrt(&two)?;
	let out = big::float_text(&root, 'f', 10)?;
	defer free(out);
	assert(out == "1.4142135624");
}

Disallowed Forms & Diagnostics

Passing an invalid base (> 62 or < 2) or malformed text to `big::parse`

big::parse supports bases 2..62 (MAX_BASE = 62) and returns (integer | invalid | nomem).

L0301: cannot assign `(big::integer | big::invalid | nomem)` to `big::integer`
lora Rejected 
use big;

export fn main() void = {
	let n: big::integer = big::parse("123", 63); // error: unhandled invalid | nomem
}
lora Allowed 
use big;

export fn main() void = {
	assert(big::parse("123", 63) is big::invalid); // ok: check for invalid on out-of-range base
}

Every value owns its digits, and every operation returns a new value, so nothing a caller holds ever changes under it.

Integers.

  • Multiplication switches to Karatsuba's method once both numbers pass 24 limbs. Division is Knuth's algorithm D for divisors under 60 limbs, and Burnikel and Ziegler's recursive division above that, which works through multiplications and so gains from Karatsuba's method.
  • Text and parsing split a large number in halves by powers of the base, so they also cost a few multiplications and divisions rather than one pass per digit chunk: hundreds of thousands of digits take under a second.
  • Bitwise operations treat negatives as infinite two's complement, so -1 is all ones.
  • probably_prime combines Miller–Rabin to base 2, n more random bases, and an extra strong Lucas test. Together that's Baillie–PSW, which no composite number is known to pass.
  • Text uses bases 2 to 62, with digits past 9 written a–z then A–Z. With base 0, the prefix chooses the base, and _ may separate digits.
  • divide rounds the quotient toward zero, down, to the nearest or up, and returns the remainder that goes with it.

Rationals stay in lowest terms, with a positive denominator. Every finite f64 is a rational exactly, and ratio_to_f64 rounds once to the nearest, subnormals and infinity included.

Floats keep their precision in bits, a rounding mode, and the accuracy of the operation that produced them: exact, or rounded below or above. An operation's result takes the larger of its operands' precisions and the first operand's rounding mode. It is computed exactly to enough bits, then rounded once. with_prec rounds to another precision or mode.

Infinities follow IEEE 754. There is no NaN, so inf − inf, 0 × inf, 0 / 0, inf / inf and the square root of a negative number abort. Past exponent 2³¹ a result is ±inf, and below −2³¹ it is ±0.

parse_float reads decimals; parse_float_base also takes mantissas in base 2, 8 or 16, by a 0b, 0o or 0x prefix with base 0, and an exponent of p for a power of 2: 0x1.8p3 is 12. With base 0, _ may separate digits. An exponent too large to compute exactly gives ±inf or ±0 at once, or rounds through a power of ten made 128 bits beyond the precision. float_to_i64 and float_to_u64 cut toward zero and clamp to the type's range, with the accuracy saying which way the result lies from x.

float_text makes only the decimal digits it writes, each correct: one division gives the leading digits, with a note of whether anything follows them, so a float's exponent costs little however large it is. With digits of −1 it writes the fewest digits that read back as the same float at its precision, found between the halfway points to the float's neighbours; for 53 bits that is the same as a shortest f64. Fixed digits are rounded half to even.
