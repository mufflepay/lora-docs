Standard Library

flag — command-line flags

Module flag (lib/flag.lora) exports 37 declarations. Import with use flag;.

Overview

Typed command-line flag parser with aliases, environment fallbacks, required flags, custom validators, and formatted usage output.

Define a flag::set with flag::new(name, interspersed), register typed flags via add_bool, add_int, add_i64, add_u64, add_float, add_str, add_duration, add_list, add_count, add_text[T], add_checked, add_func, or add_bool_func, then call flag::parse(&s, args) and read values with flag::get(&s, id).

A set stores borrowed str views of names, usage strings, defaults, and parsed arguments, so those strings must outlive the set. Defining a flag with an empty name or duplicate name/alias aborts as a programmer error. When -h, -help, or --help is passed and not overridden by a user flag, parse returns flag::help.

Valid Usage & Examples

Parsing CLI flags, aliases, and positional arguments

Register typed flags with flag::add_*, add an alias, handle flag::help, and read positional arguments returned by flag::parse.

lora Allowed 
use flag;
use time;

export fn main() void = {
	let s = flag::new("serve");
	let port = flag::add_int(&s, "port", 8080, "listen `port`")!;
	let verbose = flag::add_count(&s, "verbose", "increase verbosity")!;
	let timeout = flag::add_duration(&s, "timeout", 5 * time::SECOND, "request timeout")!;
	flag::alias(&s, "verbose", "v")!;

	let args = ["--port=9090", "-v", "-v", "-timeout", "1m30s", "app.conf"];
	let rest = flag::parse(&s, args)!;
	assert(flag::get(&s, port) == 9090);
	assert(flag::get(&s, verbose) == 2u64);
	assert(flag::get(&s, timeout) == 90 * time::SECOND);
	assert(len(rest) == 1z && rest[0] == "app.conf");
}

Required flags, env fallback, and checked validators

Enforce mandatory flags with flag::require, fall back to environment variables with flag::from_env, and validate values with flag::add_checked.

lora Allowed 
use flag;

export fn main() void = {
	let s = flag::new("tool");
	let mode = flag::add_checked(&s, "mode", "fast", "run mode",
		fn(v: str) (void | flag::invalid) = {
			if (v != "fast" && v != "safe") {
				return flag::invalid { why = "must be fast or safe" };
			}
		})!;
	flag::require(&s, "mode");
	flag::from_env(&s, "mode", "TOOL_MODE");

	let _ = flag::parse(&s, ["-mode=safe"])!;
	assert(flag::get(&s, mode) == "safe");
}

Generating usage text and inspecting parsed flags

Use flag::usage, flag::given, and flag::lookup to format help output and inspect which flags were supplied.

lora Allowed 
use flag;
use strings;

export fn main() void = {
	let s = flag::new("cli");
	let dry = flag::add_bool(&s, "dry-run", false, "do not write changes")!;
	let _ = flag::parse(&s, ["-dry-run"])!;
	assert(flag::given(&s, "dry-run"));
	assert(flag::get(&s, dry));

	let help = flag::usage(&s)!;
	assert(strings::contains_str(help, "Usage of cli:"));
	assert(strings::contains_str(help, "-dry-run"));
}

Disallowed Forms & Diagnostics

Registering two flags with the same name

Defining a flag whose name or alias is already taken (or empty) aborts immediately as a programmer error.

E_ABORT: duplicate flag name "port"
lora Rejected 
use flag;

export fn main() void = {
	let s = flag::new("dup");
	let _ = flag::add_int(&s, "port", 80, "")!;
	let _ = flag::add_int(&s, "port", 443, "")!; // error: duplicate flag name "port" aborts
}
lora Allowed 
use flag;

export fn main() void = {
	let s = flag::new("ok");
	let _ = flag::add_int(&s, "port", 80, "")!;
	let _ = flag::add_int(&s, "tls-port", 443, "")!; // ok: distinct flag name
}

Module Guide & Examples

Command-line flags: a set says which flags a program takes, parse reads them from its arguments, and get gives each one's value.

let args = os::args()!; let flags = flag::new("serve"); let port = flag::add_int(&flags, "port", 8080, "the port to listen on")!; let quiet = flag::add_bool(&flags, "quiet", false, "say nothing")!; flag::alias(&flags, "quiet", "q")!; let files = match (flag::parse(&flags, args[1..])) { let rest: ^[]str => rest, flag::help => { let text = flag::usage(&flags)!; io::write_all(&io::stderr, strings::to_bytes(text))!; os::exit(0); }, let e: (flag::error | nomem) => return e, } serve(flag::get(&flags, port), flag::get(&flags, quiet), files);

A flag is written -name or --name; one that takes a value as -name=value or -name value, and a bool flag as -name, or -name=false. Flags come before the other arguments: the first that is not a flag, or "--", ends them, unless the set is interspersed, when they may come anywhere before "--". "-" alone is not a flag. A flag given twice takes the later value, except a list, which keeps every one, and a count, which counts.

A set keeps views of what it is given: its names, usage and defaults, and the arguments parse reads, which must outlive it. Defining a flag with a name that is taken, or that is no name, aborts: it is a mistake in the program, not in what it was given.

lora 
use flag;
use time;

export fn main() void = {
	let s = flag::new("serve");
	let port = flag::add_int(&s, "port", 8080, "the `port` to listen on")!;
	let wait = flag::add_duration(&s, "wait", 30 * time::SECOND, "how long to wait")!;
	let verbose = flag::add_count(&s, "v", "say more")!;
	let rest = flag::parse(&s, ["-port", "0x50", "-wait=1m30s", "-v", "-v", "site/"])!;
	assert(flag::get(&s, port) == 80);
	assert(flag::get(&s, wait) == 90 * time::SECOND);
	assert(flag::get(&s, verbose) == 2);
	assert(len(rest) == 1 && rest[0] == "site/");
}

Syntax.

  • A flag is written -name or --name.
  • One that takes a value is written -name=value or -name value.
  • A bool flag is written -name alone, or -name=false, but not -name false: there, false is the next argument.
  • The flags end at the first argument that isn't one, or at --. In an interspersed set, flags may come anywhere before --, and parse returns everything else.
  • - alone is an argument, not a flag.
  • A flag given twice takes the later value. A list keeps every value given, and a count counts them.

Values.

  • Integers may be decimal, 0x hexadecimal, 0o or 0 octal, or 0b binary, with _ between digits. They must fit their type.
  • Floats may begin with + or a point, or end with one. inf and nan are accepted too.
  • Durations are read by time::parse_duration.
  • A bool reads 1, t, T, true, TRUE or True as true, and the matching forms as false.
  • add_text takes text that T decodes, such as a netip::addr. parse refuses text that doesn't decode, and get decodes it.
  • add_checked takes text that its function accepts. When the function refuses a value, it says why.

add_func calls its function each time the flag is given, as parse reads it, with a pointer to the program's own state and the value: to gather -I directories, or to set several things from one flag. It holds no value itself. add_bool_func is the same for a flag that may be given alone, with "true". The function is a plain function, not a closure. A closure may reach and change anything, including the arguments parse is reading, while a function changes only what it is handed. The set keeps the state, so the compiler checks that the state outlives the set. The value it is handed is a view of the argument, so a function that keeps it copies it.

lora 
use flag;
use strings;

type includes = struct { dirs: ^[]^str }

fn include(s: *includes, dir: str) (void | flag::invalid) = {
	let copy = strings::clone(dir) or return flag::invalid { why = "out of memory" };
	append(s.dirs, copy) or return flag::invalid { why = "out of memory" };
};

export fn main() void = {
	let inc = includes { dirs = [] };
	let s = flag::new("cc");
	flag::add_func(&s, "I", "add a `dir` to search", &inc, &include)!;
	let rest = flag::parse(&s, ["-I", "lib", "-I=vendor", "main.c"])!;
	assert(len(inc.dirs) == 2 && inc.dirs[1] == "vendor" && rest[0] == "main.c");
}

Help and errors.

  • -h, -help and --help give help unless the set defines a flag of that name. The program then prints usage.
  • A flag that is not given takes its environment variable's value, from the environment the program started with, if from_env gave it one.
  • A flag that require names must be given, or parse fails with problem::missing.
  • Defining a flag twice, or with a name that is empty, begins with - or holds =, aborts: that is a mistake in the program, not in its arguments.

usage lists the flags by name:

text 
Usage of serve:
  -port port
    	the port to listen on (default 8080)
  -v	say more
  -wait duration
    	how long to wait (default 30s)

A word in backquotes in a usage string names the flag's value. Otherwise the value is named by its kind: int, uint, float, string, duration or value.

A set keeps views of what it is given: names, usage, defaults, and the arguments parse reads. The compiler checks that each outlives the set. A command with subcommands uses one set per command and parses each command's arguments with its own set.
