Standard Library

asn1 — DER

Module asn1 (lib/asn1.lora) exports 94 declarations. Import with use asn1;.

Overview

The asn1 module implements strict ASN.1 DER (Distinguished Encoding Rules) parsing and writing, including universal tags (BOOLEAN, INTEGER, BIT_STRING, OCTET_STRING, NULL, OBJECT_IDENTIFIER, ENUMERATED, SEQUENCE, SET, string types, UTC_TIME, GENERALIZED_TIME), OID manipulation, and struct-level marshal / unmarshal.

DER requires canonical encodings: shortest-form lengths and tags, primitive encoding for primitive types, minimal-byte integers, 0x00/0xff booleans, zero-padded unused bits in bit strings, and canonical timestamps. asn1::value borrows zero-copy body and raw slices from the input DER buffer.

Valid Usage & Examples

Parse a DER SEQUENCE with nested elements

Use asn1::parse, asn1::enter, and asn1::next to walk constructed DER values without copying.

lora Allowed 
use asn1;

export fn main() void = {
	let out: ^[]u8 = [];
	defer free(out);
	let w = asn1::new_writer(&out);
	asn1::begin(&w, asn1::SEQUENCE)!;
	asn1::put_int(&w, 42)!;
	asn1::put_bool(&w, true)!;
	asn1::end(&w)!;

	let seq = asn1::parse(out)!;
	assert(asn1::universal(&seq, asn1::SEQUENCE));
	let p = asn1::enter(&seq)!;
	let v1 = asn1::next(&p)! as asn1::value;
	let v2 = asn1::next(&p)! as asn1::value;
	assert(asn1::integer(&v1)! == 42);
	assert(asn1::boolean(&v2)! == true);
}

Encode and parse an OBJECT IDENTIFIER

Parse dotted OID strings with asn1::parse_oid and encode/decode them in DER.

lora Allowed 
use asn1;

export fn main() void = {
	let id = asn1::parse_oid("1.2.840.113549.1.1.11") as asn1::oid;
	let out: ^[]u8 = [];
	defer free(out);
	let w = asn1::new_writer(&out);
	asn1::put_oid(&w, &id)!;

	let v = asn1::parse(out)!;
	let back = asn1::object_identifier(&v)!;
	assert(asn1::oid_equal(&id, &back));
}

Disallowed Forms & Diagnostics

Accepting non-canonical BER encodings in DER parser

Indefinite lengths, non-minimal integer encodings, or non-00/ff booleans are rejected by asn1 as asn1::invalid.

asn1::invalid: a boolean that is not 00 or ff
lora Rejected 
use asn1;

export fn main() void = {
	// Boolean with value 0x01 instead of DER-canonical 0xff
	let v = asn1::parse([0x01u8, 0x01u8, 0x01u8])!;
	let _ = asn1::boolean(&v)!; // error: non-00/ff boolean fails DER validation
}
lora Allowed 
use asn1;

export fn main() void = {
	let v = asn1::parse([0x01u8, 0x01u8, 0xffu8])!; // ok: DER-canonical 0xff for true
	assert(asn1::boolean(&v)! == true);
}

Constraints & Limits

Max nesting depth
64 (`MAX_DEPTH`)
Deeply nested DER structures fail with `reason::too_deep`.
Max OID arcs
24 (`MAX_ARCS`)
OIDs with more than 24 components fail with `reason::bad_oid`.
Error field name
48 bytes
`invalid.field` stores up to 48 bytes of the failing field name.

Module Guide & Examples

ASN.1 in DER (X.690), as certificates, keys and signatures are written: a reader of elements, a writer, and structs read and written whole, laid out by @asn1 tags.

type point = struct { x: i64, y: i64, @asn1(tag = 0, optional) label: (str | void) }; let der = asn1::marshal(&point { x = 1, y = 2, label = void })?; let p = asn1::unmarshal::[point](&region, der[..])?;

let p = asn1::new_parser(der); let seq = asn1::next(&p)? as asn1::value; let inner = asn1::enter(&seq)?; let n = asn1::integer(&(asn1::next(&inner)? as asn1::value))?;

Reading is strict: DER has one encoding for each value, and anything else (an indefinite or long-winded length, an integer with a needless leading byte, a boolean that is neither 00 nor ff, unused bits that are not zero) is invalid, with the byte where it begins.

Example: λexamples/pem_asn1.lora; a short one in encodings.md.

Reading is strict, as DER is: a length or tag in more bytes than it needs, an indefinite length, an integer with a needless leading byte, a boolean other than 00 or ff, unused bits that are not zero, a time in any other form, a default written out: each is invalid, with the reason, the byte where the element begins, and the field being read. Ending a SET puts its elements in order, as DER has them.

marshal and unmarshal read and write a type whole, the code for it made while compiling: a struct is a SEQUENCE, a slice or array a SEQUENCE OF; bool, integers, enums (ENUMERATED), str (UTF8String unless the tag says), []u8 (OCTET STRING), bitstring, oid, time::datetime, raw (an element kept as it is), and (T | void) for what may be absent. A type with its own form implements asn1::marshaler and asn1::unmarshaler. Strings and slices are put in the region. Fields are tagged:

lora 
type extension = struct {
	id: asn1::oid,
	@asn1(default = false) critical: bool,
	value: []u8,
}
type tbs = struct {
	@asn1(tag = 0, explicit, default = 0) version: int,
	serial: asn1::raw,
	@asn1(sets) issuer: [][]attribute,          // SEQUENCE OF SET OF
	@asn1(tag = 3, explicit, optional) extensions: ([]extension | void),
	...
}

tag = n gives a context tag, IMPLICIT unless explicit, of the application or private class if asked; optional and default let a field be absent; set makes a SET or SET OF; string (printable, ia5, numeric, visible) and time (utc, generalized) choose the form; omit_empty leaves out an empty slice; skip leaves a field out. Tags that contradict one another are refused when compiling.
