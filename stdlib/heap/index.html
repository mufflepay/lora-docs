Standard Library

heap — binary heap and in-place heapsort

Module heap (lib/heap.lora) exports 23 declarations. Import with use heap;.

Overview

heap implements a binary heap priority queue (heap::heap[T]) and in-place slice heap algorithms.

Use new_min / new_max for ordered types, new_by for custom comparators, or from_slice_min / from_slice_max / from_slice_by to build a heap in O(n) time from an existing slice. The module also exports low-level slice helpers (heapify_by, sift_up_by, sift_down_by, heap_sort_by) that operate directly on []T without allocating.

SymbolPurpose
new_min / new_max / new_byCreate an empty min-heap, max-heap, or custom-ordered heap
from_slice_min / from_slice_max / from_slice_byBuild a heap in O(n) from a copy of a slice
push / pop / peekInsert in O(log n), remove top in O(log n), or inspect top in O(1)
replace / push_popCombined pop+push or push+pop with a single sift
remove / fixRemove an arbitrary index or restore heap order after mutation
heapify_by / heap_sort_byIn-place O(n) heapify and O(n log n) heapsort on slices

Valid Usage & Examples

Priority queue with custom comparator and in-place fix

Order structs by priority using heap::new_by and update an element in place with heap::fix.

lora Allowed 
use heap;

type task = struct {
	prio: int,
	id: int,
}

fn task_less(a: task, b: task) bool = a.prio < b.prio;

export fn main() void = {
	let q = heap::new_by::[task](&task_less);
	defer heap::finish(&q);

	heap::push(&q, task { prio = 20, id = 1 })!;
	heap::push(&q, task { prio = 5, id = 2 })!;
	heap::push(&q, task { prio = 15, id = 3 })!;

	assert((heap::peek(&q) as *task).id == 2);
	q.items[2].prio = 1;
	heap::fix(&q, 2z);
	assert((heap::peek(&q) as *task).prio == 1);
}

O(n) heap construction and in-place heapsort

Build a max-heap from a slice in linear time, or sort a slice in place with heap::heap_sort_by.

lora Allowed 
use heap;

export fn main() void = {
	let mx = heap::from_slice_max::[int]([4, 1, 7, 3, 9, 2])!;
	assert(heap::replace(&mx, 5)! as int == 9);
	assert(heap::pop(&mx) as int == 7);

	let arr = [5, 2, 9, 1, 6, 3];
	heap::heap_sort_by(arr[..], fn(a: int, b: int) bool = a < b);
	assert(arr[0] == 1 && arr[5] == 9);
}

Disallowed Forms & Diagnostics

Storing owning ^T elements in a heap

heap::heap[T] only frees its backing slice, so elements that own memory are rejected at compile time.

@error: A heap frees its backing slice, not its elements, so T can't own memory: store indices or handles instead
lora Rejected 
use heap;

fn less_str(a: ^str, b: ^str) bool = a < b;

export fn main() void = {
	let h = heap::new_by::[^str](&less_str); // error: @owns(T) rejected at compile time
}
lora Allowed 
use heap;

export fn main() void = {
	let h = heap::new_min::[int](); // ok: int does not own heap memory
	heap::push(&h, 42)!;
}

Constraints & Limits

Time complexity
O(log n) push/pop
`peek` is O(1); `from_slice_*` and `heapify_by` are O(n); `heap_sort_by` is O(n log n).
Ownership
Non-owning T
`@owns(T)` fails compilation.
Stability
Not stable
Equal elements are not guaranteed to preserve insertion order.

Module Guide & Examples

Binary heap (priority queue) and in-place heap operations on slices.

Supports min-heaps and max-heaps over ordered types as well as custom comparators via new_by. Push and pop are O(log n); peek is O(1); building from an existing slice (from_slice_* / heapify_by) is O(n).

let h = heap::new_min::int; defer heap::finish(&h); heap::push(&h, 5)!; heap::push(&h, 1)!; assert(heap::pop(&h) as int == 1);

heap[T] provides min-heaps, max-heaps, and custom-comparator priority queues (new_min, new_max, new_by, from_slice_*, push, pop, replace, push_pop, fix, remove) plus in-place heapify_by and heap_sort_by.

lora 
let h = heap::new_min::[int]();
heap::push(&h, 5)!;
heap::push(&h, 1)!;
assert(heap::pop(&h) as int == 1);
