Standard Library

coro — coroutines (green threads), channels, select, non-blocking I/O

Module coro (lib/coro.lora) exports 103 declarations. Import with use coro;.

Overview

M:N work-stealing coroutine scheduler, kqueue-backed non-blocking I/O, structured concurrency primitives, and coroutine channels.

Coroutines are lightweight cooperative tasks multiplexed across OS worker threads (coro::run() spawns coro::cpus() workers, or coro::run_on(n) chooses n). Each coroutine gets a 256 KiB stack with a 16 KiB guard page; context switching saves/restores callee-saved registers, and blocking on I/O or timers parks the task on kqueue so the worker thread can run other ready coroutines.

In normal Lora code, structured concurrency blocks (@all, @first, @scope, @go) compile to calls against coro::scope, coro::results, coro::arrivals, and coro::group. You can also use coro directly for channels (chan[T], select), detached tasks (detach), timers (sleep, sleep_for, ticker, run_after), mutual exclusion (serial[T]), priorities (priority), and coroutine-local bindings (local[T]).

Valid Usage & Examples

Producer-consumer pipeline with coro::chan and select

Spawn concurrent coroutines inside @scope, communicate over buffered coro::chan[int], and multiplex two channels with coro::select.

lora Allowed 
use coro;

export fn main() void = {
	let ch1 = coro::chan_new::[int](2z);
	let ch2 = coro::chan_new::[int](2z);
	defer coro::chan_finish(&ch1);
	defer coro::chan_finish(&ch2);
	let p1 = &ch1;
	let p2 = &ch2;
	let sum = 0;
	let ps = &sum;

	@scope {
		@go {
			let _ = coro::send(p1, 10);
			coro::close(p1);
		};
		@go {
			let _ = coro::send(p2, 20);
			coro::close(p2);
		};
		@go {
			let open = 2;
			for (open > 0) {
				let v1 = 0;
				let v2 = 0;
				let (idx, ok) = coro::select([
					coro::recv_case(p1, &v1),
					coro::recv_case(p2, &v2),
				]);
				if (!ok) {
					open -= 1;
				} else if (idx == 0z) {
					*ps += v1;
				} else {
					*ps += v2;
				}
			}
		};
	}!;
	assert(sum == 30);
}

Periodic work with ticker and cooperative sleep

Use coro::new_ticker, coro::tick, and coro::sleep_for inside a coroutine without blocking the underlying OS worker thread.

lora Allowed 
use coro;
use time;

export fn main() void = {
	@scope {
		let tk = coro::new_ticker(5 * time::MILLISECOND);
		let ticks = 0;
		for (ticks < 3) {
			let _ = coro::tick(&tk);
			ticks += 1;
		}
		assert(ticks == 3);
		coro::sleep_for(2 * time::MILLISECOND);
	}!;
}

Protecting shared state with serial[T] and task-local bindings

Use coro::serial[T] to serialize coroutine access to shared data without holding an OS mutex across yields, and coro::local[T] for dynamic task-local bindings.

lora Allowed 
use coro;

let req_id: coro::local[int] = coro::local { name = "req_id" };

export fn main() void = {
	let counter = coro::serial_new(0);
	@scope {
		coro::bind(&req_id, 77, fn() void = {
			let v = coro::lookup(&req_id);
			assert(v is int && v as int == 77);
			coro::with(&counter, fn(n: *int) void = {
				*n += 1;
			});
		});
	}!;
	coro::with(&counter, fn(n: *int) void = {
		assert(*n == 1);
	});
}

Disallowed Forms & Diagnostics

Calling coro::select with an empty case slice

coro::select enforces requires(len(cases) > 0, "coro: select needs a case"); passing an empty slice fails the contract check and aborts.

E_REQUIRES_FAILED: coro: select needs a case
lora Rejected 
use coro;

export fn main() void = {
	let empty: []coro::case = [];
	let _ = coro::select(empty); // error: requires(len(cases) > 0) fails at runtime
}
lora Allowed 
use coro;

export fn main() void = {
	let ch = coro::chan_new::[int](1z);
	let _ = coro::send(&ch, 1);
	let out = 0;
	let (idx, ok) = coro::select([coro::recv_case(&ch, &out)]); // ok: non-empty case slice
	assert(idx == 0z && ok && out == 1);
}

Module Guide & Examples

Coroutines: lightweight, cooperative tasks that many OS threads share. They are started by @all, @first and @scope, which wait for them (see --- structured concurrency ---), or by detach, which does not:

let (profile, orders) = @all(get_profile(id), get_orders(id))?;

@scope { for (true) { let c = coro::accept(l.fd)?; @go serve(c); // others run meanwhile }; }?;

A coroutine runs on a worker thread until it reaches a suspension point: yield_now, sleep, waiting for a file descriptor, or waiting on a channel. Suspending frees the thread to run other coroutines. run starts a worker per processor (run_on picks the number), and the workers share one queue of ready coroutines, so a coroutine resumes on whichever worker is free: many coroutines take turns on each thread, and one coroutine may move between threads over its life. run_on(1) keeps them all on one thread.

Each coroutine has its own 256 KiB stack, with a guard page below it, and switching between coroutines saves and restores only callee-saved registers, so thousands can run at once. Waiting on file descriptors and timers uses kqueue.

Code running in coroutines on several workers runs in parallel: protect data they share with a mutex (thread::mutex), atomics, or channels.

Coroutines are lightweight, cooperative tasks, not OS threads. run starts a worker thread per processor and runs coroutines on them many-to-many. Each worker hosts any number of coroutines, taking turns, and a coroutine can move to another worker whenever it resumes. run_on(1) keeps everything on one thread (many-to-one).

A coroutine runs until it reaches a suspension point, which frees its thread for other coroutines:

Suspension point

Channels, select cases, groups, scopes and serial values are @sealed: the scheduler trusts their fields, so only this module reads and writes them. A case is made by recv_case or send_case; a channel's zero value, chan::[T] { ... }, is an unbuffered one, and a group's, a scope's and a serial value's are ready to use, as their _new functions give.

lora 
let pages = @all(max = 8) for (let u .. urls) fetch(u);
@scope {
	@go for (true) {
		let v = 0, quit = false;
		match coro::select([
			coro::recv_case(&results, &v),
			coro::recv_case(&stop, &quit),
		]) {
			(0, true) => handle(v),
			_ => break, // stopped, or cancelled: (len(cases), false)
		}
	}
}?;

Scheduling. Each worker has its own run queue and runs from it first. A coroutine readied on a worker (spawned, woken, yielding) goes on that worker's queue. Workers check a global queue every 61 turns and right after a yield, and steal half of another worker's queue when they run dry, which balances load and moves coroutines between threads. One worker at a time waits on kqueue. When a coroutine suspends, its worker carries out the suspension (requeueing it, releasing a channel lock, registering an event) only after the coroutine's registers are saved, so other threads can never resume it too early. 1000 coroutines × 1000 yields take 0.19s on 8 workers.

Stacks. Each coroutine has a fixed 256 KiB stack (detach_sized for more) with a guard page. Only touched pages use memory. Stacks do not grow: overflowing one faults on the guard page. The compiler reports a coroutine or thread whose code needs more stack than it gets as an error, and warns when it calls a recursive function (see "Stack overflow check" in tooling.md).

Rules. Code in coroutines on different workers runs in parallel, so protect shared data with thread::mutex, atomics or channels. If every remaining coroutine is waiting on a channel or group, run aborts with a deadlock message. λexamples/coro_echo.lora is a TCP echo server with a coroutine per connection.
