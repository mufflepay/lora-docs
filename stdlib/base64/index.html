Standard Library

base64 — bytes as text

Module base64 (lib/base64.lora) exports 23 declarations. Import with use base64;.

Overview

The base64 module implements RFC 4648 Base64 encoding and strict decoding across four variants selected via base64::coding: std (A-Z, a-z, 0-9, +, /, padded with =), url (- and _, padded), raw_std (unpadded), and raw_url (unpadded URL-safe, suited for tokens and JWTs).

Decoding is canonical and strict: characters outside the chosen alphabet, misplaced padding, non-canonical trailing lengths (n % 4 == 1), or non-zero unused low bits in a partial final quantum all fail with base64::invalid { at: usize }. Both one-shot helpers (encode, decode, encode_into, decode_into) and incremental encoder / decoder streams are provided.

Valid Usage & Examples

Encode and decode standard and raw URL-safe Base64

Use base64::encode for standard padded Base64 and base64::coding::raw_url for unpadded URL-safe tokens.

lora Allowed 
use base64;
use strings;

export fn main() void = {
	let payload = strings::to_bytes("hello, lora!");
	let std_txt = base64::encode(payload)!;
	defer free(std_txt);
	let tok = base64::encode_with(base64::coding::raw_url, [0xfbu8, 0xff, 0x01])!;
	defer free(tok);

	let back = base64::decode(std_txt)!;
	defer free(back);
	assert(strings::from_bytes(back) == "hello, lora!");
}

Stream-decode line-wrapped Base64 chunks

Use base64::new_decoder, decoder_write, and decoder_close to decode wrapped text arriving in arbitrary chunks.

lora Allowed 
use base64;
use strings;

export fn main() void = {
	let out: ^[]u8 = [];
	defer free(out);
	let dec = base64::new_decoder(base64::coding::std, &out);
	base64::decoder_write(&dec, "SGVs\r\nbG8s")!;
	base64::decoder_write(&dec, "IHdvcmxkIQ==")!;
	base64::decoder_close(&dec)!;
	assert(strings::from_bytes(out) == "Hello, world!");
}

Disallowed Forms & Diagnostics

Decoding URL-safe input with standard Base64

Using base64::decode (which defaults to coding::std) on URL-safe - or _ characters or unpadded input returns base64::invalid rather than silently accepting mixed alphabets.

base64::invalid: invalid base64 at byte 0 (and missing padding for std)
lora Rejected 
use base64;

export fn main() void = {
	let _ = base64::decode("_-8")!; // error: std alphabet rejects URL-safe '-' and '_' and missing padding
}
lora Allowed 
use base64;

export fn main() void = {
	let raw = base64::decode_with(base64::coding::raw_url, "_-8")!; // ok: raw_url accepts unpadded URL-safe input
	defer free(raw);
	assert(len(raw) == 2);
}

Constraints & Limits

Expansion ratio
4 chars per 3 bytes
`encoded_len` rounds up to 4-char blocks when padded.
Non-zero unused bits
Rejected
Strict RFC 4648 canonical check rejects non-zero padding bits.
Line breaks
Skipped only in streams / `lines = true`
`decode` and `decode_with` reject `\r` and `\n`; `decoder_write` skips them.

Module Guide & Examples

Base64 (RFC 4648), in four encodings: the standard alphabet and the URL-safe one (- and _ for + and /), each with padding or without it ("raw").

let text = base64::encode(bytes)?; // standard let token = base64::encode_with(base64::coding::raw_url, bytes)?; let bytes = base64::decode(text)?;

Decoding is strict: a character outside the alphabet, padding where it can't be, or unused low bits that aren't zero is invalid, so that every value has one encoding.

Example: λexamples/encodings.lora; a short one in encodings.md.

// base32: std (A-Z 2-7), hex (0-9 A-V, sorts as the bytes do), raw_std, raw_hex
	the same functions as base64
// ascii85: four bytes as five characters ! to u, four zero bytes as z

base64 and base32 decode strictly: a character outside the alphabet, padding where it can't be, or unused low bits that aren't zero is invalid, with the byte where, so that every value has one encoding. ascii85 skips whitespace, and reads z only between groups. An encoder or decoder works on bytes or text as they come, a group at a time, and gives what one call on the whole would.
