Standard Library

dns — names, addresses and records

Module dns (lib/dns.lora) exports 76 declarations. Import with use dns;.

Overview

dns implements both a wire-format DNS message codec (decode, new_builder, add_question, add_answer, add_edns) and a stub resolver (system, with_servers) that reads /etc/hosts and /etc/resolv.conf, queries servers over UDP with automatic TCP fallback on truncation, and sorts returned addresses per RFC 6724 (sort_addrs).

In addition to host lookups (lookup_host, lookup_addr), it supports lookup_mx, lookup_srv, lookup_txt, lookup_ns, lookup_cname, and dns::dial (happy-eyeballs-style connection over resolved addresses).

Valid Usage & Examples

Resolve hostnames and MX records with the system resolver

Create a system resolver, look up IP addresses sorted by RFC 6724 preference, and query MX records.

lora Allowed 
use dns;
use fmt;
use netip;

export fn main() void = {
	let r = dns::system()!;
	let addrs = dns::lookup_host(&r, "example.com")!;
	defer free(addrs);
	let buf: [netip::TEXT_MAX]u8 = [0...];
	for (let a .. addrs) {
		fmt::println(netip::text(&a, buf[..]))!;
	}
}

Build and decode a DNS wire message

Construct a DNS response packet with A, TXT, and EDNS0 OPT records and decode it back into structured records.

lora Allowed 
use dns;
use netip;

export fn main() void = {
	let out: ^[]u8 = [];
	defer free(out);
	let b = dns::new_builder(&out, dns::header { id = 42, response = true, ... })!;
	dns::add_question(&b, "example.test", dns::A)!;
	dns::add_answer(&b, &dns::record {
		name = "example.test",
		kind = dns::A,
		class = dns::INET,
		ttl = 60,
		data = netip::v4(192, 0, 2, 1),
	})!;
	dns::add_edns(&b, 1232)!;

	let msg = dns::decode(out)!;
	assert(msg.head.id == 42 && len(msg.answers) == 1);
}

Disallowed Forms & Diagnostics

Add DNS sections out of order in a builder

DNS wire sections must be written in order: questions, answers, authorities, then additionals. Adding a question after an answer fails with dns::invalid.

problem::out_of_order: invalid DNS message: a section is written after a later one
lora Rejected 
use dns;
use netip;

export fn main() void = {
	let out: ^[]u8 = [];
	let b = dns::new_builder(&out, dns::header { ... })!;
	dns::add_answer(&b, &dns::record {
		name = "a.test", kind = dns::A, class = dns::INET, ttl = 60,
		data = netip::v4(1, 2, 3, 4),
	})!;
	dns::add_question(&b, "b.test", dns::A)!; // error: question added after answer (out of order)
}

Module Guide & Examples

The Domain Name System: names to addresses, addresses to names, and the other records a name keeps (mail servers, services, text), asked of the servers /etc/resolv.conf names after /etc/hosts.

let r = dns::system()?; let addrs = dns::lookup_host(&r, "example.com")?; // RFC 6724 order let mail = dns::lookup_mx(&r, "example.com")?; // by preference let c = dns::dial(&r, "example.com", 443)?; // net::conn

A query goes over UDP, and over TCP when the answer does not fit; each server is asked in turn, a few times, each time within its timeout. In a coroutine the waiting lets the others run. Names a server should not answer (those ending in .local, which hosts on the link answer for themselves) are asked of the system instead, as is everything when no configuration can be read.

Messages are values too: decode reads one, keeping its names and data in memory the message owns, and a builder writes one.

A resolver asks the servers /etc/resolv.conf names, after /etc/hosts: over UDP, and over TCP when the answer does not fit, each server in turn, attempts times, within timeout_ms each. A short name is tried in the search domains (before or after it is tried as it is, by ndots). In a coroutine the waiting lets the others run. Names ending in .local, which hosts on the link answer for themselves, are asked of the system, as is everything when no configuration can be read (use_system).

lookup_srv orders servers as RFC 2782 asks: by priority, then at random in proportion to weight. sort_addrs puts first what this host can reach, then those whose source address shares their scope and kind, then IPv6 before IPv4, the smaller scope, and the longer prefix in common with the source; it finds each source without sending anything.

Messages are values too. decode reads one, keeping its names (as text, with \. for a dot in a label and \DDD for other bytes) and data in a region the message owns; compressed names may only point backward, and counts a message cannot hold are refused before anything is kept. A builder writes one, section by section, to a buffer the caller owns.

lora 
use dns;
use netip;

export fn main() void = {
	let h = dns::parse_hosts("192.0.2.7 box box.lan\n")!;
	let found: ^[]netip::addr = [];
	dns::hosts_addrs(&h, "BOX.lan", &found)!;
	assert(len(found) == 1);
	let rev = dns::reverse_name(netip::parse("192.0.2.7")!)!;
	assert(rev == "7.2.0.192.in-addr.arpa");
}

dns::sort_addrs 
fn sort_addrs(addrs: []netip::addr) void

Sorts addresses as RFC 6724 asks: those reachable first, then those whose source has their scope and label, then by precedence (IPv6 before IPv4, natively), smaller scope, and the longest prefix in common with the source; otherwise as they were. A source is what this host would send from, which the system says without sending anything.
