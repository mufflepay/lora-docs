Standard Library

zip — ZIP archives

Module zip (lib/zip.lora) exports 19 declarations. Import with use zip;.

Overview

zip reads and writes ZIP archives with Store (method::store = 0) and DEFLATE (method::deflate = 8) compression, including full ZIP64 support for archives exceeding 4 GiB or 65,535 entries.

  • Reading: zip::open(src, length) accepts any io::reader_at and parses the central directory at the end of the archive. Use count(&a), file_at(&a, i), raw(&a, &f) (compressed section), and entry(&raw, &f) (inflating io::reader that verifies uncompressed length and CRC-32 at EOF).
  • Writing: zip::new_writer(dst) streams entries in a single pass to any io::writer using data descriptors, writing the central directory and ZIP64 end records on zip::close(&w).

Valid Usage & Examples

Creating a multi-entry ZIP archive in one pass

Use zip::new_writer, set_comment, create (with method::deflate or method::store), io::write_all, and zip::close.

lora Allowed 
use io;
use strings;
use zip;

export fn main() (void | io::failure | nomem) = {
	let buf = io::new_buffer();
	let w = zip::new_writer(&buf);
	zip::set_comment(&w, "created by lora")?;

	zip::create(&w, &zip::file_header {
		name = "assets/",
	})?;

	zip::create(&w, &zip::file_header {
		name = "assets/hello.txt",
		method = zip::method::deflate,
	})?;
	io::write_all(&w, strings::to_bytes("hello zip archive!"))?;
	zip::close(&w)?;
}

Opening a ZIP archive and extracting entries with CRC-32 verification

Open an archive from an io::reader_at, iterate 0..zip::count(&a), obtain zip::raw and zip::entry, and read to EOF so CRC-32 and length are checked.

lora Allowed 
use io;
use zip;

fn list_and_verify(src: io::reader_at, total_len: u64) (void | io::failure | nomem) = {
	let a = zip::open(src, total_len)?;
	for (let i = 0z; i < zip::count(&a); i += 1z) {
		let f = zip::file_at(&a, i);
		if (zip::is_dir(&f)) continue;
		let raw = zip::raw(&a, &f)?;
		let r = zip::entry(&raw, &f)?;
		let plain = io::read_all(&r, 1 << 26)?;
		assert(@u64(len(plain)) == f.uncompressed);
	}
}

Inspecting raw compressed data offsets

Use zip::raw and zip::data_offset when you need the byte offset or stored bytes without inflating.

lora Allowed 
use io;
use zip;

fn inspect_stored(a: *const zip::archive, i: usize) (u64 | io::failure) = {
	let f = zip::file_at(a, i);
	let s = zip::raw(a, &f)?;
	return zip::data_offset(&s);
}

Disallowed Forms & Diagnostics

Writing bytes to `zip::writer` before calling `zip::create` (or writing to a directory)

Calling write on zip::writer without an active entry—or writing non-empty data after create with a trailing / directory name—fails with io::invalid.

io::invalid: Runtime io::failure: data written before any file was created
lora Rejected 
use io;
use strings;
use zip;

export fn main() (void | io::failure | nomem) = {
	let buf = io::new_buffer();
	let w = zip::new_writer(&buf);
	io::write_all(&w, strings::to_bytes("orphan"))?; // error: returns io::invalid (no file created)
	zip::close(&w)?;
}

use strings;
use zip;

Constraints & Limits

Name / comment length
≤ 65,535 bytes
`set_comment` and `create` reject names or comments longer than 65,535 bytes with `io::invalid`.
End-of-central-dir search
Last `22 + 65,535` bytes
`zip::open` scans the tail window (`END_SEARCH`) for the End of Central Directory signature.
ZIP64 threshold
≥ `0xffff` files or ≥ 4 GiB
Automatically emits ZIP64 extra fields, 64-bit descriptors, and ZIP64 end/locator records.
Encryption & methods
Store (0) & Deflate (8) only
Encrypted entries (`flags & 1 != 0`) and other compression methods return `io::invalid`.
  • zip::file strings (name, comment, extra) borrow the zip::archive's central directory buffer and remain valid as long as the archive is alive.
  • zip::entry checks uncompressed length and CRC-32 only when the stream reaches done; partial reads do not validate the trailer.

Module Guide & Examples

ZIP archives: files stored or deflated, each named in a central directory at the end. Reads them from anything that reads at an offset, ZIP64 included (more than 4 GiB, or 65535 files); writes them to any writer, in one pass.

let a = zip::open(&file, size)?; for (let i = 0z; i < zip::count(&a); i++) { let f = zip::file_at(&a, i); // good while a is let raw = zip::raw(&a, &f)?; // the data as stored let r = zip::entry(&raw, &f); // as it was: io::reader, io::copy(&out, &r)?; // its CRC-32 checked at the end };

let w = zip::new_writer(&out); zip::create(&w, &zip::file_header { name = "a.txt", ... })?; io::write_all(&w, data)?; zip::close(&w)?;

lora 
use io;
use strings;
use zip;

export fn main() void = {
	let out = io::new_buffer();
	let w = zip::new_writer(&out);
	zip::create(&w, &zip::file_header { name = "hello.txt", ... })!;
	io::write_all(&w, strings::to_bytes("hello, hello, hello"))!;
	zip::close(&w)!;
	let src = io::new_bytes_reader(io::bytes_of(&out));
	let a = zip::open(&src, @u64(len(io::bytes_of(&out))))!;
	let f = zip::file_at(&a, 0);
	let raw = zip::raw(&a, &f)!;
	let r = zip::entry(&raw, &f)!;
	let buf: [64]u8 = [0...];
	let n = r.read(buf[..])! as usize;
	assert(strings::from_bytes(buf[..n]) == "hello, hello, hello");
}

Reading:

  • open finds the end record, and ZIP64's where there is one, which covers files past 4 GiB and more than 65535 of them.
  • Times come from MS-DOS's fields (taken as UTC), or more exactly from the extended timestamp or NTFS's field where a file has one.
  • A file's mode is read from Unix's attributes, or made from MS-DOS's.
  • raw checks the local header, and entry reads the data, stored or deflated. At the end it checks the length and CRC-32 against the central directory's; a mismatch is io::invalid. Encrypted files, and methods other than store and deflate, are refused.
  • A file's strings are views into the archive.

Writing:

  • create begins a file, and what is written to the writer then is its data, until the next create or close.
  • Sizes and CRC-32 go in a descriptor after the data, so nothing needs to seek back.
  • Names and comments that are not ASCII are flagged as UTF-8. The time goes in an extended timestamp as well as MS-DOS's fields.
  • close writes the central directory, with ZIP64's records where sizes, offsets or the number of files need them.
