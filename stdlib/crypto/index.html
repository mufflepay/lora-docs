Standard Library

crypto — hashes, MACs, ciphers and signatures

Module crypto (lib/crypto.lora) exports 254 declarations. Import with use crypto;.

Overview

crypto is Lora's pure-Lora cryptographic primitives library. It provides constant-time implementations, explicit error unions for malformed keys/tags/signatures, and explicit *_wipe helpers for sensitive key material:

  • Hashes & XOFs: sha256, sha224, sha512, sha384, sha512_224, sha512_256, sha3_224..sha3_512, shake128, shake256, cshake128, cshake256, blake2b, blake2s, plus legacy sha1 and md5. All standard hashes implement the crypto::hash interface (write, sum, reset, size, block_size).
  • MACs & KDFs: Generic hmac[H], hmac_sha256/384/512, poly1305, hkdf_extract/hkdf_expand, pbkdf2, scrypt, argon2 / argon2id, and bcrypt_hash / bcrypt_check.
  • Symmetric & AEAD: chacha20, chacha20poly1305_seal/open, xchacha20poly1305_seal/open, secretbox_seal/open, aes_new + aes_gcm_seal/open/seal_random, plus cbc_*, ctr_new, cfb_*, ofb_new, and legacy des/des3/rc4.
  • Asymmetric & Post-Quantum: x25519 / box_*, ed25519_*, ec_generate / ecdh / ecdsa_sign / ecdsa_verify (P-256, P-384, P-521), rsa_* (PKCS #1 v1.5, PSS, OAEP), dsa_*, and ML-KEM (mlkem512, mlkem768, mlkem1024).
  • Utilities: CSPRNG (random, random_below, random_text), constant-time primitives (equal, select, copy_if, wipe), and hex.

Valid Usage & Examples

Streaming SHA-256 and keyed BLAKE2b digests

Use sha256_new() via the hash interface (write, sum, reset) and keyed blake2b_new(32, key).

lora Allowed 
use crypto;
use strings;

export fn main() (void | crypto::bad_blake2) = {
	let h = crypto::sha256_new();
	h.write(strings::to_bytes("hello, "));
	h.write(strings::to_bytes("lora"));
	let d1: [32]u8 = [0...];
	h.sum(d1[..]);

	let d2 = crypto::sha256_of(strings::to_bytes("hello, lora"));
	assert(crypto::equal(d1[..], d2[..]));

	let key = strings::to_bytes("my-secret-mac-key");
	let b2 = crypto::blake2b_new(32, key)?;
	b2.write(strings::to_bytes("message"));
	let mac: [32]u8 = [0...];
	b2.sum(mac[..]);
}

Authenticated encryption with ChaCha20-Poly1305 and AES-GCM

Encrypt and authenticate in place with chacha20poly1305_seal / open or aes_gcm_seal / open, always wiping keys afterward.

lora Allowed 
use crypto;
use strings;

export fn main() (void | crypto::bad_key | crypto::forged) = {
	let key: [32]u8 = [0...];
	crypto::random(key[..]);
	defer crypto::wipe(key[..]);

	let nonce: [12]u8 = [0...];
	crypto::random(nonce[..]);

	let aad: [9]u8 = ['h', 'e', 'a', 'd', 'e', 'r', '-', 'v', '1'];
	let buf: [11]u8 = ['s', 'e', 'c', 'r', 'e', 't', '-', 'd', 'a', 't', 'a'];
	let tag = crypto::chacha20poly1305_seal(&key, &nonce, aad[..], buf[..]);

	crypto::chacha20poly1305_open(&key, &nonce, aad[..], buf[..], tag[..])?;
	assert(strings::from_bytes(buf[..]) == "secret-data");
}

Password hashing with Argon2id and key derivation with HKDF

Derive password hashes with argon2id and expand shared secrets with hkdf_extract + hkdf_expand.

lora Allowed 
use crypto;
use strings;

export fn main() (void | crypto::bad_argon2 | crypto::too_long | nomem) = {
	let salt: [16]u8 = [0...];
	crypto::random(salt[..]);

	let dk: [32]u8 = [0...];
	defer crypto::wipe(dk[..]);
	crypto::argon2id(strings::to_bytes("correct-horse-battery"), salt[..], 3, 65536, 1, dk[..])?;

	let prk: [32]u8 = [0...];
	defer crypto::wipe(prk[..]);
	crypto::hkdf_extract(crypto::sha256_new(), salt[..], dk[..], prk[..]);

	let subkey: [32]u8 = [0...];
	defer crypto::wipe(subkey[..]);
	let info: [7]u8 = ['e', 'n', 'c', '-', 'k', 'e', 'y'];
	crypto::hkdf_expand(crypto::sha256_new(), prk[..], info[..], subkey[..])?;
}

Ed25519 signatures and X25519 key agreement

Generate an Ed25519 signing keypair, sign a message, verify it, and perform an X25519 Diffie-Hellman exchange.

lora Allowed 
use crypto;
use strings;

export fn main() (void | crypto::bad_signature) = {
	let sk = crypto::ed25519_generate();
	defer crypto::ed25519_wipe(&sk);
	let pk = crypto::ed25519_public(&sk);

	let msg = strings::to_bytes("signed payload");
	let sig = crypto::ed25519_sign(&sk, msg);
	crypto::ed25519_verify(&pk, msg, sig[..])?;

	let a_priv: [32]u8 = [0...];
	let b_priv: [32]u8 = [0...];
	crypto::random(a_priv[..]);
	crypto::random(b_priv[..]);
	defer { crypto::wipe(a_priv[..]); crypto::wipe(b_priv[..]); }

	let a_pub = crypto::x25519_public(&a_priv);
	let b_pub = crypto::x25519_public(&b_priv);
	let s1 = crypto::x25519(&a_priv, &b_pub);
	let s2 = crypto::x25519(&b_priv, &a_pub);
	assert(crypto::equal(s1[..], s2[..]));
}

Post-quantum ML-KEM-768 key encapsulation

Query parameter sizes with mlkem_sizes, generate a keypair, encapsulate a shared secret, and decapsulate it.

lora Allowed 
use crypto;

export fn main() (void | crypto::bad_ciphertext) = {
	let (_pk_len, _sk_len, ct_len) = crypto::mlkem_sizes(crypto::mlkem_level::mlkem768);
	let sk = crypto::mlkem_generate(crypto::mlkem_level::mlkem768);
	defer crypto::mlkem_wipe(&sk);
	let pk = crypto::mlkem_public_of(&sk);

	let ct: [1088]u8 = [0...];
	let ss_enc = crypto::mlkem_encapsulate(&pk, ct[..ct_len]);
	let ss_dec = crypto::mlkem_decapsulate(&sk, ct[..ct_len])?;
	assert(crypto::equal(ss_enc[..], ss_dec[..]));
}

Disallowed Forms & Diagnostics

Ignoring AEAD authentication (`forged`) or signature (`bad_signature`) errors

Error unions returned by chacha20poly1305_open, aes_gcm_open, ed25519_verify, etc. cannot be silently discarded (L0003).

Constraints & Limits

Max standard digest
`MAX_SIZE = 64` bytes
Covers SHA-512, SHA3-512, and BLAKE2b-512.
HKDF output ceiling
`255 × HashLen` bytes
`hkdf_expand` returns `too_long` if `len(out) > 255 * h.size()`.
bcrypt password & cost
≤ 72 bytes, cost 4..31
Default cost `BCRYPT_DEFAULT_COST = 12`; longer passwords or out-of-range cost return `bad_bcrypt`.
Argon2 minimums
tag ≥ 4B, salt ≥ 8B, time ≥ 1
Lanes `1..2^24 - 1`, memory `≥ 8 KiB` per lane.
RSA key sizes
2048..4096 bits
`rsa_generate` and signing enforce 2048–4096-bit moduli (`bad_key_size`).
  • Key wiping: Key structs (ed25519_private, mlkem_private, dsa_private, stream[B]) do not implement automatic drop; always call ed25519_wipe, mlkem_wipe, dsa_wipe, stream_wipe, or crypto::wipe in a defer block.
  • Legacy algorithms: sha1, md5, des, des3, and rc4 are provided only for interoperability with legacy formats/protocols; prefer sha256/sha3/blake2b and chacha20poly1305/aes_gcm.

Module Guide & Examples

Cryptography: hashes, message authentication, key derivation, secure randomness and comparisons that take the same time whatever the bytes.

Every hash has one interface, hash: write as often as needed, then sum, which leaves the state as it was so more may follow. HMAC, HKDF and PBKDF2 work over any of them:

let d = crypto::sha256_of(data); // [32]u8 let mac = crypto::hmac_sha256(key, message); // [32]u8 let m = crypto::hmac_new(crypto::sha384_new(), key); // any hash crypto::hmac_write(&m, message); let out: [48]u8 = [0...]; crypto::hmac_sum(&m, out[..]);

SHA-256, SHA-224, SHA-512, SHA-384 (FIPS 180-4) are for new work. SHA-1 and MD5 are broken for signatures and collisions: they are here for protocols that still name them (UUID version 5, old password schemes), never for new secrets.

All written in Lora, constant time where secrets are involved, with the processor's AES instructions (ARMv8 aese and aesd, x86 AES-NI) for AES.

Sealing encrypts data in place and gives the tag; opening checks the tag before it decrypts, and leaves data as it was when the tag is wrong.

SHA-3 and SHAKE are Keccak (FIPS 202), and cSHAKE adds a function name and customization string (SP 800-185). A SHAKE reads out as many bytes as wanted; once read, it takes no more writes. BLAKE2b and BLAKE2s (RFC 7693) take a key, salt and personalization, and every hash here works through the one hash interface, so HMAC, HKDF and PBKDF2 take them all.

Ed25519 (RFC 8032) signs deterministically. Verification refuses an S that is not reduced and a public key that is not encoded canonically, so a signature has one form only. ed25519_options gives Ed25519ctx (a context of up to 255 bytes) and Ed25519ph (the message's SHA-512 digest signed in its place).

ECDSA's nonces are RFC 6979's, made from the key and digest, so signing needs no randomness. P-521's points and scalars are 66 bytes, and its signatures in DER at most 139. Keys and ECDH work in constant time on all three curves. RSA keys are 2048 to 4096 bits:

  • rsa_generate sieves 2048 odd numbers at a time by the primes below 2¹⁶, and tests what is left by Miller–Rabin in constant time: a 2048-bit key takes about 50 ms, a 4096-bit one about half a second.
  • Montgomery multiplication, nearly all the time of RSA and the curves, is the runtime's assembly (arm64 and x86-64), on 64-bit limbs where the modulus has an even number of 32-bit ones: a 2048-bit signature takes 1.5 ms.
  • A key with its primes signs and decrypts by the CRT, four times faster than with d alone.
  • Every private operation is checked with the public key before its result is given.
  • OAEP decryption makes all its checks in constant time.
  • PKCS #1 v1.5 decryption is for old protocols: how it fails can tell an attacker something, which rsa_decrypt_pkcs1_key avoids for session keys.

ML-KEM (FIPS 203) agrees on a 32-byte secret that a quantum computer cannot recover. One side encapsulates to the other's public key and sends the ciphertext; the other decapsulates it. A ciphertext that was not made for the key gives a secret no one else has, rather than an error, so how decapsulation fails says nothing about the key. A key is kept as its 64-byte seed. ML-KEM-768 is the usual choice, and nothing in its arithmetic on secrets divides or branches.

XChaCha20-Poly1305, and NaCl's secretbox and box, take 24-byte nonces, long enough to choose at random. A box is sealed with the shared key of two X25519 keys, so it shows who sealed it. A sealed box from box_seal_anonymous comes from a key made for it alone, so it shows nothing of the sender.

Passwords are kept as Argon2id, scrypt or bcrypt hashes, each slow and salted on purpose:

  • Argon2id (RFC 9106) is for new work. Its time, memory and lanes set the cost; argon2 also gives Argon2i and Argon2d, with a secret key and associated data.
  • scrypt (RFC 7914) costs 128·n·r bytes of memory.
  • bcrypt writes the $2b$ form, reads $2a$, $2b$ and $2y$, and refuses a password of more than 72 bytes rather than cut it. Its Blowfish reads tables by secret indices, as every bcrypt does, so it is not constant time.

DSA (FIPS 186-4) and RC4 are for keys and data old systems made. DSA is withdrawn from FIPS 186-5, and its signatures here take RFC 6979's nonces, so signing needs no randomness. A domain from outside is checked: its sizes, q dividing p − 1, and g of order q. RC4's output can be told from random, and its table is read at secret indices.

CBC, CTR, CFB and OFB work over any block. None of them authenticates, so pair them with a MAC, or use GCM or ChaCha20-Poly1305. CBC keeps iv as the last ciphertext block, so a message can be done in parts. DES and triple DES are for reading what old systems wrote: DES falls to search, and both have a 64-bit block. Their S-boxes are read whole, like AES's fallback, so the time they take says nothing of the key.
