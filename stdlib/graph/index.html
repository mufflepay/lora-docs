Standard Library

graph — Adjacency-list graphs and iterative graph algorithms

Module graph (lib/graph.lora) exports 24 declarations. Import with use graph;.

Overview

graph provides an adjacency-list graph (graph::graph) with u32 vertex IDs and f64 edge weights, along with iterative implementations of classic graph algorithms.

Directed and undirected graphs share the same representation (new_directed / new_undirected). Every traversal and pathfinder is iterative (using explicit heap queues/stacks rather than recursion), so deep graphs will not overflow the call stack. Invalid vertex indices, non-finite weights, cycles in topo_sort, negative weights in dijkstra, and negative-weight cycles in bellman_ford return graph::graph_error.

Valid Usage & Examples

Weighted shortest paths with Dijkstra

Build an undirected weighted graph, find a shortest path with graph::dijkstra, and compute all-target distances with graph::dijkstra_all.

lora Allowed 
use graph;
use math;

export fn main() void = {
	let g = graph::new_undirected(5)!;
	graph::add_edge(&g, 0, 1, 4.0)!;
	graph::add_edge(&g, 0, 2, 1.0)!;
	graph::add_edge(&g, 2, 1, 2.0)!;
	graph::add_edge(&g, 1, 3, 1.0)!;

	let res = graph::dijkstra(&g, 0, 3)! as graph::path_result;
	assert(res.dist == 4.0);
	assert(len(res.nodes) == 4z); // [0, 2, 1, 3]

	// Vertex 4 is disconnected
	let no_path = graph::dijkstra(&g, 0, 4)!;
	assert(no_path is void);
	let dists = graph::dijkstra_all(&g, 0)!;
	assert(math::is_inf(dists[4], 1));
}

Topological sort and strongly connected components

Run graph::topo_sort on a DAG and graph::strongly_connected_components on a directed graph.

lora Allowed 
use graph;

export fn main() void = {
	let g = graph::new_directed(4)!;
	graph::add_edge(&g, 0, 1)!;
	graph::add_edge(&g, 1, 2)!;
	graph::add_edge(&g, 2, 3)!;

	let order = graph::topo_sort(&g)!;
	assert(order[0] == 0 && order[3] == 3);

	// Add back-edge 2 -> 1 to form SCC {1, 2}
	graph::add_edge(&g, 2, 1)!;
	assert(graph::has_cycle(&g)!);
	let sccs = graph::strongly_connected_components(&g)!;
	assert(len(sccs) == 3z);
}

Disallowed Forms & Diagnostics

Running Dijkstra on a graph with negative edge weights

graph::dijkstra rejects negative weights with graph::graph_error; use graph::bellman_ford when negative weights are present.

graph::graph_error: graph error: dijkstra requires non-negative weights
lora Rejected 
use graph;

export fn main() void = {
	let g = graph::new_directed(3)!;
	graph::add_edge(&g, 0, 1, 5.0)!;
	graph::add_edge(&g, 1, 2, -3.0)!;
	let res = graph::dijkstra(&g, 0, 2)!; // error: returns graph::graph_error on negative weights
}
lora Allowed 
use graph;

export fn main() void = {
	let g = graph::new_directed(3)!;
	graph::add_edge(&g, 0, 1, 5.0)!;
	graph::add_edge(&g, 1, 2, -3.0)!;
	let res = graph::bellman_ford(&g, 0, 2)! as graph::path_result; // ok: bellman_ford supports negative edge weights
	assert(res.dist == 2.0);
}

Constraints & Limits

Vertex IDs
u32 (< ~0u32)
`~0u32` is reserved as an internal sentinel.
Edge weights
Finite f64
`NaN` and `+/-Inf` are rejected with `graph::graph_error`.
Direction constraints
Algorithm-specific
`topo_sort` and `strongly_connected_components` require directed graphs; `mst_kruskal` requires undirected.
