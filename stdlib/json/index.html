Standard Library

json — JSON text, documents and types

Module json (lib/json.lora) exports 66 declarations. Import with use json;.

Overview

The json module provides strict RFC 8259 / RFC 7493 JSON validation, streaming token reading/writing (reader, writer), DOM tree parsing (parse -> document + value), JSON Pointer (RFC 6901) lookup (at), formatting (compact, indent, canonical), and tag-driven struct marshal / unmarshal into an expanse::region.

By default, json::options is strict: duplicate object keys, trailing commas, unescaped control characters, invalid UTF-8, and NaN/Infinity are rejected. Errors (invalid, mismatch, missing, unknown) carry a place with byte offset and truncated RFC 6901 JSON Pointer path.

Valid Usage & Examples

Marshal and unmarshal structs with @json field tags

Use @json tags (name, omit_empty, omit_zero, skip, string, format, inline, unknown) with json::marshal and json::unmarshal backed by an expanse::region.

lora Allowed 
use expanse;
use json;

type user = struct {
	@json("user_id", string) id: u64,
	name: str,
	@json(omit_empty) bio: str = "",
	@json(skip) secret: str = "",
}

export fn main() void = {
	let u = user { id = 42, name = "Ada", bio = "", secret = "tok" };
	let txt = json::marshal(&u)!;
	defer free(txt);

	let reg = expanse::auto();
	defer expanse::finish(&reg);
	let back = json::unmarshal::[user](&reg, txt)!;
	assert(back.id == 42 && back.name == "Ada");
}

Parse a JSON document and query with JSON Pointer

Use json::parse and json::at to navigate nested objects and arrays, freeing the document with json::finish.

lora Allowed 
use json;

export fn main() void = {
	let doc = json::parse(`{"users":[{"name":"Ada"},{"name":"Lin"}]}`)!;
	defer json::finish(&doc);

	let name = json::at(doc.root, "/users/1/name") as str;
	assert(name == "Lin");
}

Stream tokens with json::reader and json::writer

Process large JSON payloads incrementally with new_reader and new_writer without materializing a DOM.

lora Allowed 
use json;
use strings;

export fn main() void = {
	let rd = json::new_reader(`{"ok":true,"n":7}`);
	assert(json::next(&rd)! as json::delim == json::delim::BEGIN_OBJECT);
	assert(json::next(&rd)! as str == "ok");
	assert(json::next(&rd)! as bool == true);
	assert(json::next(&rd)! as str == "n");
	let num = json::next(&rd)! as json::number;
	assert(json::as_i64(num) as i64 == 7);

	let out: ^[]u8 = [];
	defer free(out);
	let wr = json::new_writer(&out);
	json::put(&wr, json::delim::BEGIN_ARRAY)!;
	json::put_int(&wr, 7)!;
	json::put(&wr, json::delim::END_ARRAY)!;
	assert(strings::from_bytes(out) == "[7]");
}

Disallowed Forms & Diagnostics

Duplicate object keys under default strict options

By default options.allow_duplicates is false (RFC 7493). Duplicate keys fail with json::invalid (NAME_TWICE).

json::invalid: invalid JSON at byte 9 (/a): a member's name given twice
lora Rejected 
use json;

export fn main() void = {
	let doc = json::parse(`{"a": 1, "a": 2}`)!; // error: duplicate key fails under default strict options
	json::finish(&doc);
}
lora Allowed 
use json;

export fn main() void = {
	let doc = json::parse(`{"a": 1, "a": 2}`, json::options { allow_duplicates = true, ... })!; // ok: allow_duplicates permits repeated keys
	defer json::finish(&doc);
}

Module Guide & Examples

JSON (RFC 8259), strict as RFC 7493 asks unless options relax it: valid UTF-8, no repeated names, no NaN or infinity, one value per text.

Three layers, each usable alone:

reader, writer tokens, read from text or a file and written back document, value a parsed tree, read with get and at, written by to_str marshal, any type with a JSON form, converted directly by code unmarshal made while compiling, and steered by @json tags:

type user = struct { @json("id") id: int, @json("name", omit_empty) name: str, @json(skip) pw_hash: str, };

let text = json::marshal(&u)?; let u = json::unmarshal::[user](&region, text)?;

Strict by default, as RFC 7493 asks of RFC 8259 JSON: text must be valid UTF-8, an object must not repeat a name, NaN and infinity have no form, and a text is one value. options relaxes or extends each of these.

lora 
type options = struct {
	reject_unknown: bool = false,     // a member no field takes is an error
	ignore_case: bool = false,        // names match ignoring case, - and _
	allow_duplicates: bool = false,   // a repeated name: the last one wins
	allow_invalid_utf8: bool = false, // bad bytes read and written as U+FFFD
	max_depth: usize = 128,           // arrays and objects nested deeper: an error
	numbers_as_strings: bool = false, // numbers written as "42", and read so
	indent: str = "",                 // "" for one line; else one item a line
	space_after_comma: bool = false,
	sorted: bool = false,             // members by name: the same bytes each time
	escape_html: bool = false,        // <, > and & escaped
	empty_as_null: bool = false,      // empty slices written as null
	omit_zero: bool = false,          // every field as if tagged omit_zero
}

Writing refuses a value nested deeper than json::WRITE_DEPTH (128) with an error, rather than running out of stack: a document read with a larger max_depth can hold one.

Errors

Each says where: the byte, and the JSON pointer (RFC 6901) to the value. Errors own and view nothing, so they outlive the text.

ErrorMessage
invalidinvalid JSON at byte 14 (/users/2): expected ',' or ']'
mismatchcannot read int from JSON at byte 30 (/age): expected an integer
missinguser.email is missing from the JSON object at byte 0
unknownuser has no field for the JSON member at byte 41 (/nickname)

json::path(&e.at) is the pointer, e.at.pos the byte; invalid's why is a reason, with reason_text.

A reader checks what it reads and a writer what it writes, at once: a string in an object is a member's name, and a name given twice is an error. A string or number a reader gives is good until its next call. A reader of a file reads a stream of values, one after another, as they are asked for.

Numbers are written in the shortest form that reads back as the same number (1, 0.1, 1e+21), and read exactly: an integer that does not fit its type is an error, never a wrapped or rounded number.

A document keeps its values in a region of its own: they are views into it, good while it lives, and dropping it frees them all at once. Objects keep their members' order, unless written sorted.

marshal and unmarshal expand into code for each type while compiling, with no reflection at run time: a type with no JSON form is a compile error. Every integer and float type (range-checked when read), bool, str, enums (by their members' names), optionals, arrays, slices, structs, map::map[str, V] (an object), []u8 (base64), time::datetime (RFC 3339), value and raw have a form.

A type of your own takes a form of its own by implementing encoder and decoder, whose methods take it as *const T and *T:

lora 
type encoder = interface { fn encode_json(w: *writer) (void | invalid | io::failure); }
type decoder = interface { fn decode_json(rd: *reader, r: *expanse::region) (void | ...); }

The tag's other options:

  • format: base64 (the default), base64url, base64raw or base64url_raw for a []u8; rfc3339 (the default), unix_ms or unix for a time::datetime.
  • inline: a struct whose fields are this object's, as if they were its own.
  • unknown: a json::value that takes the members no field takes, and writes them back in their place.
lora 
use expanse;
use json;

type user = struct {
	@json("id") id: int,
	@json("display_name") name: str,
	@json("email", omit_empty) email: str,   // left out when empty
	@json(skip) pw_hash: str,                // never read or written
	tags: []str,                             // no tag: its own name
}

export fn main() void = {
	let u = user { id = 1, name = "ada", email = "", pw_hash = "x", tags = [] }
	let text = json::marshal(&u)!;
	let r = expanse::reserve(expanse::GIB)!;
	defer expanse::finish(&r);
	let back = json::unmarshal::[user](&r, text)!;
	assert(back.name == "ada");
}

unmarshal reads tokens straight into the value, with no tree between, and copies strings and slices into the region, where they live until it is reset. A field absent from the text is an error (missing) unless it is skip, optional, omit_empty or omit_zero; a member with no field is skipped, or an error with reject_unknown.
