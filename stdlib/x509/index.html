Standard Library

x509 — certificates

Module x509 (lib/x509.lora) exports 21 declarations. Import with use x509;.

Overview

x509 parses DER and PEM X.509 certificates and private keys, loads system root CAs (system_roots, pool_from_file), and verifies RFC 5280 certificate chains for TLS servers (verify) and clients (verify_client). It checks RSA (PKCS #1 v1.5) and ECDSA (P-256, P-384, P-521) signatures, validity windows, CA basic constraints and path length, extended key usage, and SAN/hostname/IP matching (for_host).

Valid Usage & Examples

Verify a leaf + intermediate chain against a custom root pool

Decode PEM certificates, parse leaf and intermediate certs, and verify the chain for a hostname at the current Unix timestamp.

lora Allowed 
use strings;
use time;
use x509;

export fn main() void = {
	let roots = x509::pool_from_file("/etc/ssl/cert.pem")!;
	defer x509::pool_finish(&roots);
	// Given DER slices leaf_der and inter_der:
	// let chain = [x509::parse(leaf_der)!, x509::parse(inter_der)!];
	// let now = @i64(time::unix_ms() / 1000);
	// x509::verify(chain[..], &roots, "example.com", now)!;
}

Load system roots and inspect parsed certificates

Load the OS root bundle with x509::system_roots and check certificate fields such as common_name and is_ca.

lora Allowed 
use fmt;
use x509;

export fn main() void = {
	let sys = x509::system_roots()!;
	defer x509::pool_finish(&sys);
	let first = x509::parse(sys.ders[0][..])!;
	fmt::printfn("root={} is_ca={}", first.common_name, first.is_ca)!;
}

Parse a PEM private key for TLS server use

Load a PEM-encoded private key from disk using private_key_from_file.

lora Allowed 
use fs;
use x509;

export fn main() void = {
	match (x509::private_key_from_file("/etc/ssl/private/key.pem")) {
		let k: x509::private_key => void,
		let e: (x509::invalid | nomem) => void,
		let e: fs::error => void,
	}
}

Disallowed Forms & Diagnostics

Verify a certificate chain without its intermediate or outside validity

x509::verify fails with x509::invalid if the chain cannot reach a trusted root or if now is outside [not_before, not_after].

x509::invalid: certificate refused: certificate is not yet valid
lora Rejected 
use x509;

export fn main() void = {
	let sys = x509::system_roots()!;
	defer x509::pool_finish(&sys);
	let c = x509::parse(sys.ders[0][..])!;
	x509::verify([c], &sys, "example.com", 0)!; // error: timestamp 0 is before certificate NotBefore
}
lora Allowed 
use time;
use x509;

export fn main() void = {
	let sys = x509::system_roots()!;
	defer x509::pool_finish(&sys);
	let c = x509::parse(sys.ders[0][..])!;
	let now = @i64(time::unix_ms() / 1000);
	x509::verify([c], &sys, "", now)!; // ok: current timestamp within validity; "" skips hostname check
}

Constraints & Limits

DER tag length
1-byte tags
der_next rejects multi-byte ASN.1 tags.
Error text
96 bytes
Reason text stored inline in x509::invalid.
Signature algorithms
RSA PKCS#1 v1.5, ECDSA P-256/384/521
Ed25519 X.509 cert signatures are not verified.

Module Guide & Examples

X.509 certificates (RFC 5280): DER and PEM, and verifying a chain up to a trusted root, for a TLS server: each signature, the times it is good for, that what signs is a CA (and its path length), that the leaf may serve TLS, and the host's name or address. Signatures: RSA (PKCS #1 v1.5) and ECDSA on P-256, P-384 and P-521.

let roots = x509::system_roots()?; // /etc/ssl/cert.pem defer x509::pool_finish(&roots); x509::verify(chain, &roots, "db.example", now)?;

lora 
fn parse(der: []u8) (cert | invalid)          // views of der
	fn pem_certs(text: []u8) (^[]^[]u8 | invalid | nomem)
	fn pool_from_file(path: str) (pool | invalid | fs::error | nomem)
	fn system_roots() (pool | invalid | fs::error | nomem)  // /etc/ssl/cert.pem
	fn verify(chain: []cert, roots: *pool, host: str, now: i64) (void | invalid | nomem)
	fn for_host(c: *cert, host: str) bool

verify checks each signature up to a root in the pool, the dates, the issuers' basic constraints and key usage, the leaf's extended key usage, and, when host is not "", that the leaf is for it: a DNS name (one leading *. label as a wildcard) or an IPv4 or IPv6 address. A critical extension it does not know is refused. Keys: RSA, ECDSA P-256 and P-384.
