Standard Library

smtp — sending mail

Module smtp (lib/smtp.lora) exports 37 declarations. Import with use smtp;.

Overview

smtp implements an RFC 5321 SMTP client (dial, dial_tls, new_client, start_tls, authenticate, mail, rcpt, data, quit, send_mail, send_message) and an RFC 5322/MIME email composer (compose, message, attachment) with UTF-8 header encoding, quoted-printable bodies, plain/HTML alternatives, and attachments.

Authentication supports plain, login, cram_md5, and xoauth2. To protect credentials, authenticate refuses to send plaintext secrets over unencrypted non-loopback connections (problem::not_secure). Server 4xx/5xx refusals return smtp::rejected with is_temporary(&e) distinguishing 4xx transient failures.

Valid Usage & Examples

Compose and send a message with send_message

Build an smtp::message with plain text and HTML alternatives and send it over TLS/STARTTLS with PLAIN auth.

lora Allowed 
use smtp;

export fn main() void = {
	let m = smtp::message {
		from = "Ana <ana@example.com>",
		to = ["bo@example.com"],
		subject = "Hello",
		text = "Hi Bo.",
		html = "<p>Hi Bo.</p>",
		...
	};
	let a = smtp::plain { user = "ana@example.com", password = "secret", ... };
	match (smtp::send_message("mail.example.com", 587, a, &m)) {
		void => void,
		let e: (smtp::error | nomem) => void,
	}
}

Step through an SMTP session and inspect server rejections

Dial a client, check extensions, issue MAIL/RCPT/DATA, and distinguish 4xx temporary errors from 5xx permanent errors.

lora Allowed 
use smtp;
use strings;

export fn send_one(c: *smtp::client) void = {
	smtp::hello(c)!;
	smtp::mail(c, "a@example.com")!;
	match (smtp::rcpt(c, "b@example.com")) {
		void => void,
		let e: smtp::rejected => {
			if (smtp::is_temporary(&e)) { /* retry later */ }
			return;
		},
		let e: (smtp::error | nomem) => return,
	}
	smtp::data(c, strings::to_bytes("Subject: test\r\n\r\nhello"))!;
	smtp::quit(c)!;
}

Disallowed Forms & Diagnostics

Inject CR/LF or angle brackets in envelope addresses

mail and rcpt validate addresses and reject embedded line breaks or angle brackets with problem::bad_address.

problem::bad_address: an address with a line break or angle brackets
lora Rejected 
use smtp;

export fn main() void = {
	let c = smtp::dial("127.0.0.1", 587)!;
	smtp::rcpt(&c, "x@example.com>\r\nRSET")!; // error: angle bracket and CR/LF rejected as bad_address
}
lora Allowed 
use smtp;

export fn main() void = {
	let c = smtp::dial("127.0.0.1", 587)!;
	smtp::rcpt(&c, "x@example.com")!; // ok: bare envelope address without CR/LF or angle brackets
}

Module Guide & Examples

Sending mail over SMTP (RFC 5321), and writing the messages it sends (RFC 5322, with MIME for text that is not ASCII, HTML and attachments).

let m = smtp::message { from = "Ana ana@example.com", to = ["bo@example.com"], subject = "Hello", text = "Hi Bo.", ... }; let a = smtp::plain { user = "ana@example.com", password = secret, ... }; smtp::send_message("mail.example.com", 587, a, &m)?;

A client speaks the protocol a command at a time: hello (EHLO, or HELO for a server that does not know it), start_tls, authenticate, mail, rcpt, data and quit. Each waits for its reply within the client's time limit; a reply that refuses is rejected, with the server's code and text. Secrets go only over TLS, or to this machine.

A client for SMTP (RFC 5321), and the messages it sends (RFC 5322, with MIME).

Connecting. dial connects to port 587 (submission) unless told, and dial_tls to a server that speaks TLS from the start (465). new_client takes a connection already made. Each reads the server's greeting.

Commands. Each sends one command and waits for its reply, within timeout_ms:

  • hello sends EHLO and learns the extensions the server offers (extension_of), or sends HELO to a server that does not know EHLO. The other commands say hello first if it has not been done.
  • start_tls starts TLS (STARTTLS), checking the certificate as verify and roots say, then says hello again. Bytes that come between its reply and the handshake are refused, as anyone on the way could have sent them.
  • authenticate uses plain, login, cram_md5 or xoauth2, if the server offers it. A password or token goes only over TLS, or to this machine; CRAM-MD5 sends neither.
  • mail, rcpt and data (or data_from, from a reader) send a message. MAIL asks for 8-bit bodies, and for SMTPUTF8 for addresses that are not ASCII, where the server takes them. Lines of the body may end in "\n" or "\r\n", and a line that starts with "." gets another.
  • reset, noop, verify and quit send RSET, NOOP, VRFY and QUIT.

A reply that refuses is rejected, with its code and text; is_temporary says whether it is a 4xx, worth trying again later. Addresses with line breaks or angle brackets are refused before they are sent.

Sending at once. send_mail connects, starts TLS where the server offers it, authenticates if given an auth, sends, and quits. send_message composes a message and sends it to all of its to, cc and bcc.

Composing. compose writes a message with these:

  • Header. Date, From, Reply-To, To, Cc, Subject, a Message-ID (made from random bytes and the sender's domain unless given) and MIME-Version. Bcc is never written.
  • Text that is not ASCII. In a subject or a name it becomes encoded words; in the body, quoted-printable.
  • Parts. Text and HTML go as alternatives. Attachments go in base64, with a name that is not ASCII given as RFC 2231 has it.
  • No added headers. A value with a line break in it is refused, so that it cannot add a header of its own.
