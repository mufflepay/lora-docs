Standard Library

textproto — lines, headers and replies of text protocols

Module textproto (lib/textproto.lora) exports 28 declarations. Import with use textproto;.

Overview

textproto implements line-oriented Internet text protocols (HTTP, SMTP, NNTP, MIME headers): CRLF/LF line reading, RFC-style folded header continuation lines, canonicalized Key: value headers, dot-stuffed message bodies (read_dot_bytes, dot_writer), and 3-digit status replies (read_reply).

Header keys are canonicalized ("content-TYPE" -> "Content-Type") and looked up case-insensitively. set and add sanitize CR/LF characters in header values to prevent header injection.

Valid Usage & Examples

Parse folded headers and prevent header injection on write

Read a multi-line header block with obs-fold continuations, update fields, and write sanitized CRLF output.

lora Allowed 
use bufio;
use io;
use textproto;

export fn main() void = {
	let src = io::new_str_reader("content-TYPE: text/plain\r\nX-Note: one\r\n  two\r\n\r\n");
	let buf: [256]u8 = [0...];
	let br = bufio::new_reader(&src, buf);
	let tp = textproto::new_reader(&br);

	let h = textproto::read_header(&tp)!;
	assert(textproto::get(&h, "CONTENT-type") as str == "text/plain");
	assert(textproto::get(&h, "x-note") as str == "one two");

	textproto::set(&h, "x-note", "updated")!;
	let out = io::new_buffer();
	textproto::write_header(&out, &h)!;
}

Read multi-line SMTP/FTP replies and dot-stuffed bodies

Expect a 2xx reply code and round-trip a dot-stuffed body.

lora Allowed 
use bufio;
use io;
use strings;
use textproto;

export fn main() void = {
	let src = io::new_str_reader("250-hello\r\n250 ok\r\n");
	let buf: [128]u8 = [0...];
	let br = bufio::new_reader(&src, buf);
	let tp = textproto::new_reader(&br);
	let (code, msg) = textproto::read_reply(&tp, 2)!;
	assert(code == 250 && msg == "hello\nok");

	let w = io::new_buffer();
	let dw = textproto::new_dot_writer(&w);
	io::write_all(&dw, strings::to_bytes(".dotline\nend"))!;
	textproto::finish_dot(&dw)!;
	assert(io::str_of(&w) == "..dotline\r\nend\r\n.\r\n");
}

Disallowed Forms & Diagnostics

Exceed header field count or byte limits

read_header enforces textproto::limits (fields and bytes) and rejects headers exceeding them with problem::header_too_big.

problem::header_too_big: a header larger than allowed
lora Rejected 
use bufio;
use io;
use textproto;

export fn main() void = {
	let src = io::new_str_reader("a: 1\r\nb: 2\r\nc: 3\r\n\r\n");
	let buf: [128]u8 = [0...];
	let br = bufio::new_reader(&src, buf);
	let tp = textproto::new_reader(&br);
	let h = textproto::read_header(&tp, textproto::limits { fields = 2, ... })!; // error: 3 fields exceeds limit of 2
}

Module Guide & Examples

Text protocols of lines, as HTTP, SMTP and mail have them: lines that end in CRLF (or LF), lines that go on onto the next (folded), headers of "Key: value" lines up to a blank line, bodies ended by a line of ".", and replies of a three-digit code ("250-first", "250 last").

let tp = textproto::new_reader(&buffered); let h = textproto::read_header(&tp)?; textproto::get(&h, "content-type") // "text/plain", whatever the key's case let (code, msg) = textproto::read_reply(&tp, 2)?; // a 2xx reply, or an error

A header's keys are kept in their canonical form, Content-Type, and looked up ignoring case. Reading is bounded: a line by the buffer under the reader, a header by limits.

What HTTP, SMTP and mail share: lines ending in CRLF (or LF), folded lines, headers of Key: value lines up to a blank line, bodies ended by a line of ., and replies of three-digit codes.
