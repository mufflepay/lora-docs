Standard Library

math — numbers, functions and the parts of a float

Module math (lib/math.lora) exports 104 declarations. Import with use math;.

Overview

math provides IEEE 754 floating-point constants, elementary and special functions bound safely to the system's libm, IEEE 754 bit inspection/manipulation, and generic ordered helpers (min, max, clamp).

Special values follow IEEE 754 and C semantics: sqrt(-1.0) and log(-1.0) return NaN, log(0.0) returns -inf, and NaN propagates through arithmetic. For ordered generics, min and max use < / > directly, while minf and maxf follow strict IEEE 754 rules (handling -0.0 vs +0.0, NaN, and infinities).

Valid Usage & Examples

Elementary functions, tuple decompositions, and overflow-safe hypot

Compute trigonometric pairs with sincos, decompose floats with frexp/modf, and avoid overflow on large magnitudes with hypot.

lora Allowed 
use math;
use fmt;

export fn main() void = {
	let (s, c) = math::sincos(math::PI / 4.0);
	assert(math::fabs(s - c) < 1e-15);

	// hypot scales internally so 1e300 doesn't overflow to +inf
	let h = math::hypot(3.0e300, 4.0e300);
	assert(math::is_finite(h) && math::fabs(h - 5.0e300) < 1.0e286);

	let (frac, exp) = math::frexp(12.0);
	assert(frac == 0.75 && exp == 4);
	assert(math::ldexp(frac, exp) == 12.0);

	let (whole, part) = math::modf(-3.25);
	assert(whole == -3.0 && part == -0.25);
	fmt::println("ok")!;
}

IEEE 754 special values, signed zero, and bit inspection

Inspect NaN, infinities, signed zeros, and exact IEEE 754 bit representations.

lora Allowed 
use math;

export fn main() void = {
	let pinf = math::inf(1);
	let ninf = math::inf(-1);
	let qnan = math::nan();

	assert(math::is_inf(pinf, 1) && math::is_inf(ninf, -1));
	assert(math::is_nan(qnan) && !math::is_finite(qnan));
	assert(math::signbit(-0.0) && !math::signbit(0.0));

	// IEEE 754 minf/maxf distinguish -0.0 from +0.0 and propagate NaN
	assert(math::signbit(math::minf(0.0, -0.0)));
	assert(!math::signbit(math::maxf(-0.0, 0.0)));
	assert(math::is_nan(math::maxf(qnan, 1.0)));

	// Round-trip IEEE 754 bits
	let bits = math::f64bits(1.0);
	assert(bits == 0x3ff0000000000000u64);
	assert(math::f64frombits(bits) == 1.0);
}

Special functions: gamma, error function, erfinv, and Bessel

Evaluate gamma, lgamma, erf/erfinv round-trips, and Bessel functions.

lora Allowed 
use math;

export fn main() void = {
	assert(math::gamma(5.0) == 24.0);
	let (lg, sign) = math::lgamma(-0.5);
	assert(sign == -1 && math::fabs(lg - math::log(2.0 * math::SQRT_PI)) < 1e-14);

	// erfinv inverts erf across [-1, 1]
	let y = 0.95;
	let x = math::erfinv(y);
	assert(math::fabs(math::erf(x) - y) < 1e-14);
	assert(math::is_inf(math::erfinv(1.0), 1));
	assert(math::is_nan(math::erfinv(1.5)));

	// Generic ordered clamp and safe integer abs
	assert(math::clamp(15, 0, 10) == 10);
	assert(math::abs(math::MIN_I64) == 9223372036854775808u64);
}

Disallowed Forms & Diagnostics

Passing a non-ordered type or mismatched types to generic min/max/clamp

math::min, math::max, and math::clamp constrain T: ordered and require all arguments to share the exact same type T.

L0301: type mismatch: cannot unify `f64` and `int` for generic parameter `T`
lora Rejected 
use math;

export fn main() void = {
	let m = math::max(1.5, 2); // error: f64 vs int
}
lora Allowed 
use math;

export fn main() void = {
	let m = math::max(1.5, 2.0); // ok: both arguments have type f64
	let c = math::clamp(5, 0, 10); // ok: all arguments share type int
}

Module Guide & Examples

Mathematics on floating-point numbers: constants, the elementary and special functions, and the parts of an IEEE 754 number; with min, max and clamp for any ordered type. The functions of the C library's libm are bound to it, safely (they read and write nothing but their numbers), which every system Lora runs on has, correctly rounded or within an ulp or so; the rest are here.

Special values follow IEEE 754 and C: sqrt(-1) and log(-1) are NaN, log(0) is -inf, and NaN goes through whatever it reaches.

The C library's libm supplies the elementary and special functions; every system Lora runs on has it, and they are correctly rounded, or within about an ulp. They are bound to it safely, so calling them needs no unsafe. The rest are written here. Special values follow IEEE 754 and C: sqrt(-1) and log(-1) are NaN, log(0) is −inf, and a NaN carries through whatever it reaches.

min and max compare with <, so where a NaN is involved, which one comes back is undefined. minf and maxf follow IEEE 754 instead: NaN if either argument is NaN (an infinity of the right sign still wins), and −0 counts as less than +0.
