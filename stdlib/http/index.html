Standard Library

http — HTTP/1.1 messages

Module http (lib/http.lora) exports 139 declarations. Import with use http;.

Overview

http is Lora's full-featured HTTP/1.1 and HTTP/2 stack. It provides strict RFC 9110/9112 request and response parsing (read_request, read_response), streaming bodies (body implementing io::reader, drain, chunked_writer), a coroutine-per-connection server (server, serve, responder), a pattern router with path parameters and typed request binding (bind[T] with @path, @query, @header, @form, @body), static file_server, test recording (record), HTTP/2 server/client support (h2conn, push), and a pooled HTTP/1.1 + HTTP/2 client (get, post, fetch, send, proxy).

Message parsing rejects smuggling vectors (Content-Length + Transfer-Encoding, conflicting lengths, missing/duplicate Host, malformed chunk lines) with http::bad_message carrying the appropriate HTTP status code (400, 414, 501, 505).

Valid Usage & Examples

Route requests with path parameters and test with http::record

Register parameterized routes on http::router, extract path_value, and test the handler in-memory without opening a socket.

lora Allowed 
use fmt;
use http;
use strings;

fn get_user(w: *http::responder, req: *http::request) void = {
	let id = http::path_value(req, "id") as str;
	let msg = fmt::string("user:{}", id);
	defer free(msg);
	http::write_text(w, 200, msg)!;
}

export fn main() void = {
	let r = http::new_router();
	http::handle_func(&r, "GET /users/{id}", &get_user)!;

	let rec = http::record(&r, "GET", "/users/42")!;
	assert(rec.status == 200);
	assert(strings::from_bytes(rec.body) == "user:42");
}

Run an HTTP server with graceful stop

Bind a TCP listener, serve a router in a background coroutine, and stop it cleanly with a thread::atomic flag.

lora Allowed 
use coro;
use http;
use net;
use netip;
use thread;

fn hello(w: *http::responder, req: *http::request) void = {
	http::write_text(w, 200, "ok")!;
}

export fn main() void = {
	let r = http::new_router();
	http::handle_func(&r, "GET /health", &hello)!;
	let srv = http::new_server(&r);
	let l = net::listen_at("127.0.0.1:0")!;
	let addr = net::listener_addr(&l) as netip::addr_port;
	let stop = thread::atomic { ... };
	let psrv = &srv;
	let pl = &l;
	let pstop = &stop;

	@scope {
		@go {
			http::serve(psrv, pl, pstop) as void;
		};
		@go {
			let _ = addr;
			http::stop(pstop);
		};
	}!;
}

Bind request fields into a typed struct with bind[T]

Use @path, @query, and @header shorthand tags on a struct and populate it automatically with http::bind.

lora Allowed 
use http;

type user_req = struct {
	@http::path id: u64,
	@http::query verbose: bool = false,
	@http::header(name = "X-Request-Id") req_id: str = "",
}

fn handler(w: *http::responder, req: *http::request) void = {
	let args = match (http::bind[user_req](req)) {
		let v: user_req => v,
		let e: http::bind_error => {
			http::error(w, 400)!;
			return;
		},
		nomem => {
			http::error(w, 500)!;
			return;
		},
	};
	let _ = args.id;
	http::write_text(w, 200, "bound")!;
}

Fetch a URL with the pooled HTTP client

Use http::new_client and http::get or http::fetch to issue an HTTP request and inspect the response status and body.

lora Allowed 
use http;

export fn main() void = {
	let c = http::new_client();
	let res = http::get(&c, "http://127.0.0.1:8080/health");
	match (res) {
		let f: http::fetched => {
			assert(f.status == 200);
		},
		let e: (http::client_error | nomem) => void,
	}
}

Disallowed Forms & Diagnostics

Send both Content-Length and Transfer-Encoding in an HTTP/1.1 message

To prevent HTTP request smuggling, read_request rejects messages carrying both Content-Length and Transfer-Encoding with problem::both_lengths (status 400).

problem::both_lengths: bad_message { why = problem::both_lengths, status = 400 }
lora Rejected 
use bufio;
use http;
use io;

export fn main() void = {
	let raw = "POST / HTTP/1.1\r\nHost: a\r\nContent-Length: 3\r\nTransfer-Encoding: chunked\r\n\r\n";
	let src = io::new_str_reader(raw);
	let buf: [256]u8 = [0...];
	let br = bufio::new_reader(&src, buf);
	let req = http::read_request(&br)!; // error: both Content-Length and Transfer-Encoding present
}
lora Allowed 
use bufio;
use http;
use io;

export fn main() void = {
	let raw = "POST / HTTP/1.1\r\nHost: a\r\nContent-Length: 3\r\n\r\nabc";
	let src = io::new_str_reader(raw);
	let buf: [256]u8 = [0...];
	let br = bufio::new_reader(&src, buf);
	let req = http::read_request(&br)! as http::request; // ok: uses only Content-Length framing
	assert(req.content_length as u64 == 3);
}

Module Guide & Examples

HTTP/1.1 messages, as RFC 9110 and 9112 have them: requests and responses read from a stream and written to one, their headers, and their bodies as readers (of a known length, chunked, or to the end).

let br = bufio::new_reader(&conn, buf); let req = http::read_request(&br)?; url::path(&req.url) // "/a b" as written: "/a%20b" textproto::get(&req.header, "accept") let body = io::read_all(&req.body, 1 << 20)?;

Reading is strict where leniency lets two readers see different messages: a message with both Content-Length and Transfer-Encoding, lengths that disagree, a coding other than chunked, a Host missing or repeated, a chunk whose size or line ends are wrong, are each refused with a bad_message, which carries the status a server answers it with.

A server, serve, answers each connection in a coroutine of its own, one request after another, with what a handler writes to a responder.

Requests and responses as RFC 9110 and 9112 have them: read from a bufio::reader and written to an io::writer, with headers from textproto and bodies read as io::readers: of a known length, chunked (with trailers), or to the end of the connection.

Reading is strict where leniency lets two readers see different messages, as request smuggling uses: Content-Length with Transfer-Encoding, lengths that disagree, a coding other than chunked, a Host missing or repeated, a chunk size that is not hex or whose line or data does not end with CRLF. Each is a bad_message, which says the status a server answers with.

lora 
use bufio;
use http;
use io;
use textproto;
use url;

export fn main() void = {
	let src = io::new_str_reader("POST /notes?x=1 HTTP/1.1\r\nHost: example.com\r\nTransfer-Encoding: chunked\r\n\r\n5\r\nhello\r\n0\r\n\r\n");
	let buf: [512]u8 = [0...];
	let br = bufio::new_reader(&src, buf);
	let req = http::read_request(&br)! as http::request;
	assert(req.method == http::POST && url::path(&req.url) == "/notes");
	let body = io::read_all(&req.body, 1 << 20)!;
	assert(len(body) == 5);
}

A server answers each connection in a coroutine of its own, one request after another (keep-alive), with what a handler writes to a responder. What the handler writes first is buffered: a response that fits is sent with its Content-Length, a larger one in chunks (or until the connection closes, for HTTP/1.0), unless the handler set a Content-Length itself; a Date is added, and no body is sent for HEAD, 1xx, 204 and 304. A body the handler leaves unread is read off (up to drain_limit) so the next request can be read; a request that asks for 100 Continue gets it when the handler first reads its body. A message that is not HTTP is answered with its status, and the connection ends. serve stops when its stop is set, from any coroutine or thread, once each connection has finished the response it is writing.

With tls set, every connection is HTTPS: the TLS handshake comes first, within header_ms, and req.secure is true. A proxy then sets X-Forwarded-Proto: https.

HTTP/2. The server speaks HTTP/2 (RFC 9113) in three ways:

  • on a connection whose TLS chose h2 by ALPN (put "h2" in the TLS config's alpn);
  • without TLS, to a client that starts with HTTP/2's preface ("prior knowledge");
  • without TLS, to an HTTP/1.1 request that asks to upgrade (Upgrade: h2c with HTTP2-Settings, and no body). It gets 101 Switching Protocols, and is answered as stream 1. Set h2c to false to refuse.

Handlers are the same: req.major is 2.

  • Streams at once: each stream's request is answered by the handler in a coroutine of its own, so a slow one holds up no other. Up to 100 may be open at once.
  • One owner of the connection: the connection's coroutine alone reads and writes the connection. The handlers ask it, over channels, to send their heads and data and to give them the body that has come.
  • Flow control: windows are kept both ways. A handler's write returns once its data has gone out as the windows allow. The connection's window is given back as data comes, and a stream's as its body is read.
  • Push: http::push(w, path) promises the client a GET of path, as if it had come with the request being answered (RFC 9113 section 8.4). The handler answers it beside the request. It is no_push if the client takes no pushed responses or this is not HTTP/2.
  • Errors:
    • What breaks the protocol ends the connection with GOAWAY and its code.
    • A stream refused, or whose body its handler did not read, gets RST_STREAM.
    • A client that gives up a stream makes the handler's later writes fail with io::closed.
lora 
fn push(w: *responder, path: str) (void | no_push | io::failure | nomem)

With gzip set, a body is gzipped when all of these hold:

  • the request's Accept-Encoding takes gzip;
  • the status is 2xx (not 206);
  • the handler has set no Content-Encoding, Content-Length or Content-Range;
  • the Content-Type is text, JSON, JavaScript, XML or SVG (compressible says);
  • the body is 256 bytes or more, when its length is known.

The response then has Content-Encoding: gzip and Vary: Accept-Encoding, and is sent in chunks. flush sends all of the body written so far.

A handler may run for many requests at once, from many coroutines: what it shares between them must be thread-safe. See λexamples/http_server.lora.

The client

A client makes requests over HTTP and HTTPS, keeping connections open between them, a few to each server (max_idle, for idle_ms). It takes care of the following:

  • One time limit. timeout_ms covers connecting (TLS included), sending, and the response.
  • TLS. Certificates are checked against the system's roots, or roots, as verify says.
  • Redirects, up to max_redirects. 301, 302 and 303 make a POST a GET without its body (303, any method but HEAD); 307 and 308 keep both. A redirect to another server leaves Authorization and Cookie out.
  • Stale connections. A connection from the pool that the server has closed meanwhile is found when the request fails on it, and the request goes again on a new one.
  • Sharing. Its pool is guarded, so coroutines may share one client by *const.

Over HTTPS, the client offers HTTP/2 by ALPN unless http2 is false. With h2c set, it speaks HTTP/2 to http:// URLs from the first byte (the server must speak it so). A server that chooses it gets each request on a stream of a connection the pool keeps, as HTTP/1.1 connections are kept. r.major says which was spoken. Redirects, time limits and streamed bodies work the same.

fetch, get and post read the response whole. Unless the request sets Accept-Encoding, they ask for gzip and give the body decompressed, without its Content-Encoding and Content-Length. send reads its status and header into an exchange the caller keeps while it reads the body as a stream. release then gives the connection back to the pool (dropping the exchange closes it instead).

Testing handlers

Reverse proxy

A proxy is a handler that passes each request on to the server at base, through a client, and the response back:

  • The URL. The request's path, less strip_prefix if it starts with it, goes after base's path, with the request's query.
  • Fields. Those that belong to one connection (Connection and the fields it names, Keep-Alive, TE, Trailer, Transfer-Encoding, Upgrade, and Proxy-*) are left out both ways.
  • Where it came from. The client's address is added to X-Forwarded-For, and X-Forwarded-Host and X-Forwarded-Proto are set unless given.
  • Bodies. A request's body is read whole first, at most max_body bytes (more is 413). A response's body is passed on as it comes.
  • Redirects are passed back, not followed.
  • Failures. A server that cannot be reached is 502, and one that does not answer in the client's time is 504.

Serving files

A file_server is a handler that serves the files under a directory by the request's path:

  • What it sends. The type comes from the name's extension, or else from the first bytes, with X-Content-Type-Options: nosniff. The bytes go from the file to the connection as the system can.
  • Validators and conditions. It sends Last-Modified and a strong ETag, and answers If-None-Match, If-Modified-Since, If-Match and If-Unmodified-Since with 304 or 412, as RFC 9110 orders them.
  • Ranges. A single range is 206 with Content-Range; several are multipart/byteranges; one past the end is 416. A Range that is malformed, asks for many ranges, or asks for more than the file many times over gets the whole file instead. If-Range is honoured.
  • Directories. A directory is served by its index file. Otherwise it is listed if listing is on (names escaped), and is a 404 if not. A directory's path without its last / is redirected to it.
  • What it refuses. It serves only what is under root: each part of the path is opened in the directory before it, without following symbolic links (unless follow_symlinks, and then only to where root is). So .., an escaped /, or a link swapped in meanwhile cannot lead out. Names starting with . are 404 unless dotfiles is on. Methods other than GET and HEAD are 405.

	dotfiles: bool = false, follow_symlinks: bool = false, max_age: (u32 | void) = void }

Routing

A router is a handler that sends each request to the route its method and path match. A pattern is a path, after a method if it is for that method only: GET /users/{id} takes one segment as id, /static/{path...} the rest of the path, /docs/ the subtree under it, and /docs/{$} that path alone. When many match, the most specific wins: from the start, a literal segment over a wildcard over the rest, then a route for the method over one for any. A path that matches only for other methods is answered 405 with Allow; GET routes answer HEAD. A path with //, . or .. is redirected to its clean form (301, or 308 keeping the method), and /docs to /docs/ when only the subtree has routes. Two patterns of one method and shape are refused.

The request's region

http::region(req) is memory that lives as long as the request is served: whatever a handler makes while serving it goes there, and is freed all at once after the response. It sizes itself, and the server reuses one region per connection, emptied between requests, so a request costs no system call once the connection is warm. What is put in it can't outlive the request, and a handler that keeps anything of the request past it can't be made a handler.

lora 
use expanse;
use http;

type row = struct { id: i64, name: str }

fn list(w: *http::responder, req: *http::request) void = {
	let mem = http::region(req)!;
	let rows = expanse::make::[row](mem, 100)!;   // gone once it is answered
	rows[0] = row { id = 1, name = "ada" }
	http::write_text(w, 200, rows[0].name)!;
}

export fn main() void = {
	let h = http::handler_func(&list);
	let got = http::record(&h, http::GET, "/")!;
	assert(got.status == 200);
}

Binding requests to structs

bind fills a struct from a request, each field from where its tag says: @path("id"), @query("page"), @header("If-Match"), @form("email"), or @body, the request's JSON body read into the field's type (as json::unmarshal reads it, its strings kept in memory the request owns). Fields are str, int, i64, u64, bool, or ? of one; a ? field the request does not give is void, and any other is an error. A str views the request. The tags' rules are checked while compiling.

lora

type bind_error = !struct { from: source, why: bind_problem, ... }
// cannot bind query parameter page: not a number
lora 
use fmt;
use http;
use json;

type edit = struct {
	@path("id") id: int,
	@query("dry_run") dry_run: ?bool,
	@header("If-Match") etag: ?str,
	@body change: change,
}

type change = struct { @json("title") title: str }

fn edit_note(w: *http::responder, req: *http::request) void = {
	let e = match (http::bind::[edit](req)) {
		let e: edit => e,
		let err: http::bind_error => {
			let text = fmt::format("{}", err)!;
			http::write_text(w, 400, text)!;
			return;
		},
		nomem => abort("out of memory"),
	}
	http::write_text(w, 200, e.change.title)!;
}

export fn main() void = {
	let r = http::new_router();
	http::handle_func(&r, "PUT /notes/{id}", &edit_note)!;
}

The request's region: memory that lives as long as the request is served, for whatever a handler makes while serving it, freed all at once after.
