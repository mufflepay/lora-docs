Standard Library

csv — comma-separated values

Module csv (lib/csv.lora) exports 32 declarations. Import with use csv;.

Overview

The csv module implements RFC 4180 CSV reading, writing, and struct marshal / unmarshal. It supports both in-memory text (new_reader, new_writer) and io::reader / io::writer streams (stream_reader, stream_writer).

Options (csv::options) configure field delimiters (comma), comment prefix characters, lazy_quotes, trim_leading_space, expected fields per record (0 matches the first record, -1 allows variable lengths), crlf line endings, and header row handling for struct mapping. Struct fields can be customized with @csv("col", skip, format) tags.

Valid Usage & Examples

Read CSV records with custom delimiter and comments

Configure csv::options for semicolon-delimited data with # comments and variable field counts.

lora Allowed 
use csv;

export fn main() void = {
	let text = "# header comment\n a;\"b;c\"\nd\n";
	let rd = csv::new_reader(text, csv::options {
		comma = ';',
		comment = '#',
		trim_leading_space = true,
		fields = -1,
		...
	});
	let r1 = csv::read(&rd)! as []str;
	assert(len(r1) == 2 && r1[0] == "a" && r1[1] == "b;c");
	let r2 = csv::read(&rd)! as []str;
	assert(len(r2) == 1 && r2[0] == "d");
	assert(csv::read(&rd)! is done);
}

Marshal and unmarshal structs with @csv tags

Use @csv tags to rename columns or skip fields during csv::marshal and csv::unmarshal.

lora Allowed 
use csv;
use expanse;

type item = struct {
	@csv("item_id") id: u32,
	name: str,
	@csv(skip) internal: bool = false,
}

export fn main() void = {
	let rows: [2]item = [
		item { id = 1, name = "bolt", internal = true },
		item { id = 2, name = "nut, hex", internal = false },
	];
	let txt = csv::marshal(rows[..])!;
	defer free(txt);

	let reg = expanse::auto();
	defer expanse::finish(&reg);
	let parsed = csv::unmarshal::[item](&reg, txt)!;
	assert(len(parsed) == 2 && parsed[1].name == "nut, hex");
}

Stream-write CSV records to a buffer

Use csv::new_writer and csv::write to emit properly escaped RFC 4180 records.

lora Allowed 
use csv;
use strings;

export fn main() void = {
	let out: ^[]u8 = [];
	defer free(out);
	let wr = csv::new_writer(&out, csv::options { crlf = true, ... });
	csv::write(&wr, ["name", "quote"])!;
	csv::write(&wr, ["Ada", "say \"hi\""])!;
	csv::flush(&wr)!;
	assert(strings::contains_str(strings::from_bytes(out), "\"say \"\"hi\"\"\""));
}

Disallowed Forms & Diagnostics

Bare quote inside an unquoted field under strict options

By default lazy_quotes is false; a " inside an unquoted field returns csv::invalid (reason::bare_quote).

csv::invalid: invalid CSV at line 1, column 4: a quote in a field not in quotes
lora Rejected 
use csv;

export fn main() void = {
	let rd = csv::new_reader("a,b\"c\n");
	let _ = csv::read(&rd)!; // error: bare quote in unquoted field returns csv::invalid
}
lora Allowed 
use csv;

export fn main() void = {
	let rd = csv::new_reader("a,b\"c\n", csv::options { lazy_quotes = true, ... }); // ok: lazy_quotes allows bare quotes
	let row = csv::read(&rd)! as []str;
	assert(row[1] == "b\"c");
}

Constraints & Limits

Delimiter rules
Single ASCII byte
`options.comma` cannot be `"`, `\r`, `\n`, `0`, or `>= 0x80`.
Default field count check
Enforced (`fields = 0`)
Rows with a different column count than the first row fail with `reason::field_count` unless `fields = -1`.

Module Guide & Examples

Comma-separated values (RFC 4180): records of fields, a line each, a field in double quotes when it holds commas, quotes or line breaks.

let rd = csv::new_reader(text); for (true) match (csv::read(&rd)?) { done => break, let fields: []str => ..., // good until the next read };

type row = struct { name: str, @csv("age") years: int, email: (str | void) }; let rows = csv::unmarshal::[row](&region, text)?; // by the header let text = csv::marshal(rows)?;

Errors say where: the line and column of the byte at fault, and the line the record began on.

Example: λexamples/csv.lora; a short one in encodings.md.

type options = struct {
	comma: u8 = ',', comment: u8 = 0, lazy_quotes: bool = false,
	trim_leading_space: bool = false,

}

Records are read as RFC 4180 has them: a field in double quotes may hold the separator, doubled quotes and line breaks (\r\n in a field is read as \n); blank lines are skipped, and lines starting with comment. A text and a file are read alike, a file a piece at a time. invalid says why (bare_quote, quote, field_count, duplicate_column), at which line and column, and on which line the record began. The writer quotes what needs it: the separator, quotes, line breaks, a leading space, and a record of one empty field, written "" so that it is not a blank line.

unmarshal reads rows as structs by the header's names, in any order; a column no field takes is left, and a field with no column is missing unless it is optional. Fields are str, bool (true/false, any case, or 1/0), integers, floats (with NaN, +Inf, -Inf), enums by member name, time::datetime, types with a text form (encoding::text_decoder, as uuid::uuid), and (T | void), empty for void. A field that is not its type's is a mismatch, with its line, column and field. Tags:

lora 
type person = struct {
	@csv(name = "age") years: int,
	@csv(format = "unix") joined: time::datetime,   // rfc3339, unix_ms, unix
	@csv(skip) cache: int,
}
