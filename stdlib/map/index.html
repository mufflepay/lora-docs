Standard Library

map — generic hash maps

Module map (lib/map.lora) exports 26 declarations. Import with use map;.

Overview

map provides generic open-addressing hash maps (map::map[K, V]) with linear probing, power-of-two table sizing, and a maximum load factor of 3/4.

Because Lora has no traits, you pass a hash function (and optionally an equality function via new_eq) when constructing a map. The module exports ready-made hash functions for strings, integers, and rune, all mixed through the splitmix64 finalizer map::mix. Removal uses Knuth's Algorithm R to shift probe runs back without leaving tombstones, keeping lookups fast under heavy churn.

A map owns its backing slot table (freed on finish or automatic drop), not its keys or values: @owns(K) || @owns(V) is rejected at compile time with @error. Keep owned data in a separate arena or slice and store indices or handles in the map.

Valid Usage & Examples

Word-frequency table with string keys

Count occurrences using map::new, map::get for in-place updates, and map::iter to inspect results.

lora Allowed 
use fmt;
use map;

export fn main() void = {
	let counts: map::map[str, int] = map::new(&map::hash_str);
	defer map::finish(&counts);

	let words = ["ada", "lora", "ada", "zig", "lora", "ada"];
	for (let w .. words) {
		match (map::get(&counts, w)) {
			let n: *int => *n += 1,
			null => map::put(&counts, w, 1)!,
		}
	}

	let it = map::iter(&counts);
	for (true) match (map::next(&it)) {
		done => break,
		let kv: (str, *int) => fmt::printfn("{} = {}", kv.0, *kv.1)!,
	}
}

Custom struct keys with new_eq

Use map::new_eq with a custom hash and equality function for composite keys that == cannot compare directly.

lora Allowed 
use map;

type coord = struct {
	x: i32,
	y: i32,
}

fn hash_coord(c: coord) u64 =
	map::mix((@u64(@u32(c.x)) << 32) | @u64(@u32(c.y)));

fn eq_coord(a: coord, b: coord) bool =
	a.x == b.x && a.y == b.y;

export fn main() void = {
	let grid: map::map[coord, str] = map::new_eq(&hash_coord, &eq_coord);
	let origin = coord { x = 0, y = 0 };
	map::put(&grid, origin, "spawn")!;
	assert(map::contains(&grid, origin));
	assert(*(map::get(&grid, origin) as *str) == "spawn");
	assert(map::remove(&grid, origin));
	assert(!map::contains(&grid, origin));
}

Read-only iteration over *const map

Use map::read and map::next_read when only a *const map[K, V] reference is available.

lora Allowed 
use map;

fn sum_values(m: *const map::map[int, int]) int = {
	let total = 0;
	let it = map::read(m);
	for (true) match (map::next_read(&it)) {
		done => break,
		let kv: (int, *const int) => total += *kv.1,
	}
	return total;
}

export fn main() void = {
	let m: map::map[int, int] = map::new(&map::hash_int);
	map::put(&m, 1, 10)!;
	map::put(&m, 2, 20)!;
	assert(sum_values(&m) == 30);
}

Disallowed Forms & Diagnostics

Storing owning ^T keys or values

map::map rejects key or value types that own heap memory at compile time because it only frees its slot table.

@error: A map frees its table, not what is in it, so its keys and values can't own memory: keep the owners elsewhere, and map to them by index or handle
lora Rejected 
use map;

export fn main() void = {
	let m: map::map[str, ^str] = map::new(&map::hash_str); // error: @owns(V) rejected at compile time
}
lora Allowed 
use map;
use strings;

export fn main() void = {
	let arena: ^[]^str = [];
	append(arena, strings::clone("owned-value")!)!;
	let m: map::map[str, usize] = map::new(&map::hash_str); // ok: non-owning usize index value
	map::put(&m, "key", 0z)!; // ok: stores handle instead of ^str
	let idx = *(map::get(&m, "key") as *usize);
	assert(arena[idx] == "owned-value");
}

Constraints & Limits

Load factor
<= 75% (3/4)
Grows by 2x (starting at 8 slots) when `count + 1 > (len(slots) / 4) * 3`.
Max table size
~0z >> 1 slots
Returns `nomem` if doubling would exceed `~0z >> 1`.
Ownership
Non-owning K, V
`@owns(K) || @owns(V)` fails compilation.
Pointer stability
Until next mutation
`*V` from `get` is invalidated on `put`, `remove`, `clear`, or `finish`.
  • Do not mutate a map while iterating with iter or read; put and remove can rehash or shift probe runs.
  • put returns (void | nomem); handle allocation failure with ?, !, or match.

Module Guide & Examples

Hash maps from keys of any type that supports '==' to values of any type.

A map is an open-addressing table with linear probing, kept at most 3/4 full and sized in powers of two. Removal shifts later entries back instead of leaving tombstones, so lookups stay fast after many removals. Lora has no traits, so the hash function is given when the map is made (and an equality function, for keys '==' cannot compare); this module provides hash functions for strings and integers.

let ages: map::map[str, int] = map::new(&map::hash_str); defer map::finish(&ages); map::put(&ages, "ada", 36)!; match map::get(&ages, "ada") { null => abort(), let age: *int => *age += 1, };

A map owns its table, freed when the map is dropped, not what is in it: its keys and values can't own memory (a map of ^str is refused, rather than leaking them). A key or value that views something, such as a str, is a view the map holds: the map can't be used once what it views has ended.

lora 
let ages: map::map[str, int] = map::new(&map::hash_str);
map::put(&ages, "ada", 36)!;
match map::get(&ages, "ada") {
	null => abort(),
	let age: *int => *age += 1,
}

let it = map::iter(&ages);
for (true) {
	match map::next(&it) {
		done => break,
		let kv: (str, *int) => fmt::println(kv.0)!,
	}
}

With new, keys can be any type that supports ==: integers, runes, bools, strings, pointers. For other keys, such as structs, use new_eq with an equality function. Lora has no traits, so the hash function is passed in. Write your own for other key types, ideally ending in map::mix. The map uses open addressing with linear probing, stays at most 3/4 full, and grows by doubling. Removal shifts entries back instead of leaving tombstones. Nothing is allocated until the first put. Keys and values are stored by value and never freed by the map. Pointers from get and iteration are invalidated by the next put or remove, and the map must not change while it is iterated. Roughly 110 ns per operation for 1M int keys on an M-series Mac, including growth.
