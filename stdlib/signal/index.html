Standard Library

signal — signals

Module signal (lib/signal.lora) exports 23 declarations. Import with use signal;.

Overview

signal provides asynchronous signal watching (watcher), coroutine-aware waiting (wait, wait_within), structured scope cancellation (cancel_on, until), ignoring/resetting (ignore, reset), and process signaling (send, raise).

Catchable signals are delivered through a non-blocking self-pipe registered with the runtime so signal::wait yields to other coroutines in @scope/@go. Fault signals (illegal, trap, aborted, floating_point, bus, segfault) plus kill and stop cannot be watched or ignored (EINVAL).

Valid Usage & Examples

Watching and raising a user signal

Register a signal::watcher with notify, raise sig::user1, and receive it with wait_within.

lora Allowed 
use coro;
use fmt;
use signal;

export fn main() void = {
	let w = signal::notify([signal::sig::user1])!;
	defer signal::stop(&w);

	signal::raise(signal::sig::user1)!;
	match (signal::wait_within(&w, 1000)!) {
		let s: signal::sig => fmt::printfn("got {} ({})", signal::name(s), signal::describe(s))!,
		void => fmt::println("timed out")!,
	}
}

Cancelling a coroutine @scope on signal

Run signal::cancel_on inside @scope so a signal cleanly cancels sibling coroutines.

lora Allowed 
use coro;
use fmt;
use signal;

export fn main() void = {
	let w = signal::notify([signal::sig::user2])!;
	let pw = &w;
	let res = @scope {
		@go signal::cancel_on(pw)?;
		@go {
			signal::raise(signal::sig::user2)!;
		};
	};
	match (res) {
		let c: signal::caught => fmt::printfn("cancelled by {}", signal::name(c.sig))!,
		void => fmt::println("completed")!,
		let e: signal::error => fmt::printfn("error: {}", e)!,
	}
}

Disallowed Forms & Diagnostics

Watching or ignoring SIGKILL, SIGSTOP, or SIGCHLD

kill and stop cannot be watched or ignored (EINVAL), and ignore([sig::child]) is rejected with EINVAL.

Runtime: cannot watch kill: Invalid argument (EINVAL, errno 22)
lora Rejected 
use signal;

export fn bad() void = {
	let _ = signal::notify([signal::sig::kill])!; // error: SIGKILL cannot be caught or watched (EINVAL)
}
lora Allowed 
use signal;

export fn good() (signal::watcher | signal::error) = {
	return signal::notify([signal::sig::terminate]); // ok: SIGTERM is catchable
}

Constraints & Limits

Module Guide & Examples

Signals: hearing the ones a program is sent, ignoring them, and sending them to programs.

let w = signal::notify([signal::sig::interrupt, signal::sig::terminate])!; let s = signal::wait(&w)!; // in a coroutine, the others run meanwhile log::info($"stopping on {signal::name(s)}");

A signal that something watches is heard by every watcher of it, as it comes: a watcher holds the signals that came and were not yet taken, and waiting takes the first. While nothing watches a signal it does what it did before: its default, or nothing if it is ignored. A watcher stops when it is dropped.

Signals the system sends for a fault in the program itself (segfault, bus, illegal, floating_point, trap), Lora's own aborted, and kill and stop, which no program can catch, cannot be watched or ignored.

lora 
use signal;

export fn main() void = {
	let w = signal::notify([signal::sig::user1])!;
	signal::raise(signal::sig::user1)!;
	assert(signal::wait(&w)! == signal::sig::user1);
}

Every watcher of a signal hears it. The signal is held until wait or poll takes it, and a watcher holds a signal only while it is running. While nothing watches a signal, it does its default, or nothing if it is ignored. That holds when the last watcher stops, too.

notify, ignore and reset refuse these with EINVAL, and a signal the system lacks with ENOTSUP:

  • the fault signals (segfault, bus, illegal, floating_point and trap), whose handlers report crashes;
  • aborted, which is Lora's own abort;
  • kill and stop, which no program can catch.

child can't be ignored, because children could no longer be waited for.

A signal that is watched is caught by a handler that does no more than write the signal's number to each watcher's pipe. It allocates nothing, takes no lock, and leaves errno as it was. In a coroutine, wait suspends on that pipe. In a scope that is cancelled, it fails with ECANCELED.

cancel_on ends a scope on a signal. Started with @go, it waits until one of its watcher's signals comes and then fails with caught. That cancels the scope's other coroutines, and caught is what the scope gives. If the others all end first, it returns and the scope ends as it would have anyway. It doesn't wait for the scope's time limit either. A scope cancelled any other way ends it too. Use one to a scope. until(sigs) is the same, with a watcher made when it starts. A signal that comes before then isn't seen, so make the watcher with notify before the scope opens if none may be missed.

lora 
use coro;
use signal;

export fn main() void = {
	let w = signal::notify([signal::sig::interrupt, signal::sig::terminate])!;
	let pw = &w;
	let r = @scope {
		@go signal::cancel_on(pw)?;
		@go {
			// serving, until cancelled
			for (!coro::is_cancelled()) coro::sleep(5);
		}
		@go signal::raise(signal::sig::terminate)!;
	};
	assert(r is signal::caught);
}

fn cancel_on(w: *watcher) (void | caught | error)

For a coroutine of a scope: waits until one of w's signals comes, and fails with caught, which cancels the scope's other coroutines and is what the scope gives; or until the others have ended and the scope's code waits for it (coro::alone), and returns. let w = signal::notify([signal::sig::interrupt, signal::sig::terminate])?;
let r = @scope {
	@go signal::cancel_on(&w)?;
	@go serve()?;
};
match (r) {
	let c: signal::caught => ...,    // serve was cancelled
	...
}

A scope that is cancelled otherwise ends the wait, with void. Outside a coroutine it waits for a signal. One to a scope: two would each wait for the other to end.
