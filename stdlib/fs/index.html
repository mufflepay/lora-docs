Standard Library

fs — files

Module fs (lib/fs.lora) exports 54 declarations. Import with use fs;.

Overview

fs provides RAII file handles, whole-file I/O, directory operations, metadata inspection, symbolic/hard links, file locking, recursive copy/remove, and depth-first directory walking.

fs::file wraps a file descriptor opened with O_CLOEXEC, implements io::reader, io::writer, io::closer, io::seeker, io::reader_at, and io::writer_at, and closes automatically via impl drop for file. Path errors use fs::error (op, path, errno), while recursive tree operations (remove_all, copy_tree) use fs::tree_error with an owned path: ^str.

Valid Usage & Examples

Opening, writing, seeking, and reading with RAII fs::file

fs::file implements io::writer, io::seeker, and io::reader, and closes automatically on scope exit.

lora Allowed 
use fmt;
use fs;
use io;
use strings;

export fn main() void = {
	let dir = fs::make_temp_dir("", "fs-ex-*")!;
	defer fs::remove_all(dir)!;
	let p = fmt::format("{}/data.txt", dir)!;
	defer free(p);

	{
		let f = fs::open_with(p, fs::options {
			read = true, write = true, create = true, truncate = true, ...
		})!;
		io::write_str(&f, "hello fs")!;
		f.seek(0, .start)!;
		let content = io::read_all(&f, 1024)!;
		defer free(content);
		fmt::printfn("read: {}", strings::from_bytes(content))!;
	}
}

Atomic file replacement and metadata inspection

Use fs::write_file_atomic to write via a sibling temp file, sync, and rename, then inspect with fs::stat.

lora Allowed 
use fmt;
use fs;
use strings;

export fn main() void = {
	let dir = fs::make_temp_dir("", "fs-atom-*")!;
	defer fs::remove_all(dir)!;
	let p = fmt::format("{}/config.txt", dir)!;
	defer free(p);

	fs::write_file_atomic(p, strings::to_bytes("mode=prod\n"), 0o644)!;
	let st = fs::stat(p)!;
	fmt::printfn("kind={} len={} mode={:#o}", st.kind, st.length, st.mode & 0o777)!;
}

Depth-first directory traversal with fs::walk

Visit directories sorted by name and skip subtrees with fs::step::skip.

lora Allowed 
use fmt;
use fs;

export fn main() void = {
	let dir = fs::make_temp_dir("", "fs-walk-*")!;
	defer fs::remove_all(dir)!;
	let sub = fmt::format("{}/sub", dir)!;
	defer free(sub);
	fs::mkdir_all(sub)!;

	let cb: closure(e: *const fs::walk_entry) fs::step =
		fn(e: *const fs::walk_entry) fs::step = {
			fmt::printfn("depth={} path={}", e.depth, e.path)!;
			return .go_on;
		};
	fs::walk(dir, &cb)!;
}

Disallowed Forms & Diagnostics

Passing a pattern with "/" to fs::create_temp or fs::make_temp_dir

Temp patterns must be a filename template without directory separators.

Runtime: cannot create bad/pat-*: Invalid argument (EINVAL, errno 22)
lora Rejected 
use fs;

export fn bad() void = {
	let _ = fs::create_temp("", "bad/pat-*")!; // error: '/' in pattern fails with EINVAL
}
lora Allowed 
use fs;

export fn good() (fs::temp | fs::error | nomem) = {
	return fs::create_temp("", "good-pat-*"); // ok: filename-only pattern without '/'
}

Constraints & Limits

Default file permissions
0o644 / 0o755
`write_file`, `options.perm`, and `write_file_atomic` default to `0o644`; `mkdir`/`mkdir_all` default to `0o755`.
Temp permissions
0o600 / 0o700
`create_temp` creates files with `0o600`; `make_temp_dir` creates directories with `0o700`.
Symlink handling in walk
Not followed
`fs::walk` visits symlinks without following them and sorts each directory by name.

info also has the file's owner and group, its link count (links), and when it was last read (atime_ms).

Writing safely.

  • write_file_atomic writes to a new file beside the target, syncs it to storage, and renames it over the target, then syncs the directory. A crash, or the program stopping, leaves either the old file or the whole new one, never part of either. Nothing is left beside it. The new file replaces what was there: a symbolic link at the path is replaced, not written through, and the file is this user's, with perm.
  • sync, and the syncs write_file_atomic makes, flush the drive's own cache too (F_FULLFSYNC on macOS), so what they wrote survives the power going.
  • create_temp and make_temp_dir replace the pattern's last * (or add to its end) with random digits, until the name is new. Files get permissions 0o600 and directories 0o700, for this user only.
  • lock and try_lock are advisory locks on the whole file, shared or exclusive. They hold until unlock, or until the file is closed.

Trees.

  • remove_all removes a file, or a directory and everything in it. It opens each directory by name inside the one above it, never follows a symbolic link, and removes links rather than what they point to, so nothing outside the tree is touched even if names change meanwhile. A path that isn't there counts as removed.
  • copy_file refuses to copy a file onto itself, by its own name or another (EINVAL), and leaves it as it was.
  • copy_tree copies a directory: each directory with its permissions, each file, and each symbolic link made again pointing where it did. It won't copy a tree into itself (EINVAL). The destination may already exist, but nothing in it may share a name with the source; nothing is replaced (EEXIST).
  • walk visits the root, then everything under it, depth first:
    • each directory comes before what it holds, and entries go by name;
    • symbolic links are visited, never followed;
    • the visit's step can skip a directory's contents, skip the rest of a directory after a file, or stop;
    • a directory that can't be read is visited again with the reason;
    • an entry's strings last only while it is visited.
  • glob matches each name of a pattern against what's actually there, and returns paths in name order. * matches names beginning with a point too. A directory that can't be read matches nothing.
  • Errors from a tree operation own the path they name: tree_error.
lora 
use fs;
use path;
use strings;

export fn main() void = {
	let root = fs::make_temp_dir("", "example-*")!;
	let deep = path::join(root, "a/b")!;
	fs::mkdir_all(deep)!;
	let file = path::join(deep, "notes.txt")!;
	fs::write_file_atomic(file, strings::to_bytes("kept"))!;
	let pattern = path::join(root, "a/*/*.txt")!;
	let found = fs::glob(pattern)!;
	assert(len(found) == 1 && found[0] == file);
	let files = 0z;
	let pf = &files;
	fs::walk(root, &fn(e: *const fs::walk_entry) fs::step = {
		if (e.kind == fs::kind::file) *pf += 1;
		return fs::step::go_on;
	})!;
	assert(files == 1);
	fs::remove_all(root)!;
}

open_in opens a name in an open directory; with follow false it refuses a symbolic link (ELOOP) rather than following it. Opening a path one name at a time this way keeps to a directory whatever happens to the path meanwhile, as http's file server does.
