strconv — number formatting and parsing

Module strconv (lib/strconv.lora) exports 19 declarations. Import with use strconv;.

Overview

Minimal, zero-GC number formatting and parsing for signed/unsigned integers and IEEE-754 floats.

strconv separates zero-allocation buffer writers (u64_into, i64_into, put_u64, format_shortest, shortest) from heap-allocating converters (itos, utos, f64tos) that return (^str | nomem), and strict parsers (parse_int, parse_size, parse_i64, parse_u64, parse_i64_base, parse_u64_base, parse_f64, parse_f32) that return (T | invalid_number).

Valid Usage & Examples

Zero-allocation integer and shortest-float formatting

Format integers into stack buffers with u64_into, i64_into, and put_u64, and format floats with format_shortest without heap allocation.

lora Allowed 
use strconv;
use strings;

export fn main() void = {
	let buf: [strconv::DIGITS_MAX]u8 = [0...];
	let min_i64 = -9223372036854775807i64 - 1;
	let s = strings::from_bytes(strconv::i64_into(buf[..], min_i64));
	assert(s == "-9223372036854775808");

	let ts: [16]u8 = [0...];
	let pos = strings::put(ts[..], 0, "v");
	pos = strconv::put_u64(ts[..], pos, 7, 2);
	assert(strings::from_bytes(ts[..pos]) == "v07");

	let fbuf: [40]u8 = [0...];
	let fs = strconv::format_shortest(0.5, false, &fbuf) as str;
	assert(fs == "0.5");
}

Allocating conversions with affine cleanup

Convert integers and floats to owned ^str values using itos, utos, and f64tos, freeing them with defer.

lora Allowed 
use strconv;

export fn main() (void | nomem) = {
	let a = strconv::itos(-42)?;
	defer free(a);
	assert(a == "-42");

	let b = strconv::utos(1024z)?;
	defer free(b);
	assert(b == "1024");

	let c = strconv::f64tos(3.125)?;
	defer free(c);
	assert(c == "3.125");
}

Strict integer, radix, and float parsing

Parse decimal numbers, prefixed literals (base = 0 with _ separators), and floats while handling invalid_number.

lora Allowed 
use strconv;

export fn main() void = {
	assert((strconv::parse_int("-128")!) == -128);
	assert((strconv::parse_u64_base("0x_ff_01", 0u)!) == 0xff01u64);
	assert((strconv::parse_i64_base("-1010", 2u)!) == -10i64);
	assert(strconv::number_text("-1.5e+3"));
	assert((strconv::parse_f64("-1.5e+3")!) == -1500.0);

	match (strconv::parse_int("99999999999")) {
		let _: int => assert(false),
		let err: strconv::invalid_number => {
			assert(err.text == "99999999999");
		},
	}
}

Disallowed Forms & Diagnostics

Passing a buffer smaller than DIGITS_MAX to i64_into / u64_into

Both u64_into and i64_into enforce requires(len(buf) >= DIGITS_MAX). A smaller slice triggers a contract failure.

CONTRACT: strconv::i64_into: buf holds fewer than DIGITS_MAX bytes
lora Rejected 
use strconv;

export fn main() void = {
	let small: [8]u8 = [0...];
	let _ = strconv::i64_into(small[..], 42); // error: buffer smaller than DIGITS_MAX violates contract
}
lora Allowed 
use strconv;

export fn main() void = {
	let buf: [strconv::DIGITS_MAX]u8 = [0...]; // ok: buffer has at least DIGITS_MAX bytes
	let digits = strconv::i64_into(buf[..], 42);
	assert(len(digits) == 2);
}

Constraints & Limits

DIGITS_MAX
20 bytes
Minimum buffer length for `u64_into` and `i64_into` (`-9223372036854775808`).
f64tos format
512-byte stack buffer
Fixed notation up to 6 decimals; scientific notation outside `[1e-6, 1e18)`.
format_shortest
`*[40]u8` / `*[17]u8` digits
RFC 8785 / ECMAScript representation; returns `void` for `NaN` and infinities.
Radix range
0 or 2..36
Base `1` or `> 36` returns `invalid_number`; underscores `_` are only accepted when `base == 0`.

Module Guide & Examples

Minimal number formatting and parsing.

lora 
type invalid_number = !struct { text: str, why: str }
// "abc" is not a number; "99999999999" is out of range for int

fn utos(u: usize) (^str | nomem)
	fn itos(n: int) (^str | nomem)
	fn parse_int(s: str) (int | invalid_number)
	fn parse_size(s: str) (usize | invalid_number)
	fn parse_i64(s: str) (i64 | invalid_number);  fn parse_u64(s: str) (u64 | invalid_number)
	fn parse_f64(s: str) (f64 | invalid_number);  fn parse_f32(s: str) (f32 | invalid_number)
	fn parse_i64_base(s: str, base: uint) (i64 | invalid_number)   // base 2 to 36, or 0
	fn parse_u64_base(s: str, base: uint) (u64 | invalid_number)
	fn number_text(s: str) bool       // -1.5e+3: no +, no needless leading zero
	fn format_shortest(f: f64, single: bool, buf: *[40]u8) (str | void)
	fn shortest(f: f64, single: bool, digits: *[17]u8) (usize, int)

// into a buffer of the caller's, allocating nothing
def DIGITS_MAX: usize = 20;                       // the most u64_into and i64_into write
fn u64_into(buf: []u8, v: u64) []u8              // buf holds DIGITS_MAX: the digits
	fn i64_into(buf: []u8, v: i64) []u8          // with a '-' when negative
	fn put_u64(buf: []u8, at: usize, v: u64, width: usize = 0) usize
	// from at, zero-padded to width, as much as fits: where it ended

parse_i64_base and parse_u64_base read integers in any base from 2 to 36, with letters for the digits past 9 in either case, and an optional sign. With base 0, the prefix says the base: 0x is hexadecimal, 0o or a leading 0 octal, 0b binary, and anything else decimal. With base 0, _ may also stand between digits, as in 1_000_000 or 0x_ff.

parse_f64 gives the nearest f64 to a decimal number. format_shortest writes the fewest digits that read back as f (as an f32 when single): 1, 0.5, 1.5e+21, 1e-7; void for NaN and the infinities.
