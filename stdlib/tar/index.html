Standard Library

tar — tape archives

Module tar (lib/tar.lora) exports 13 declarations. Import with use tar;.

Overview

tar reads and writes POSIX tape archives in 512-byte blocks. The reader (tar::reader) supports V7, USTAR, PAX, and GNU archives—including PAX extended/global records, GNU long names/links, base-256 large numbers, and GNU sparse files. The writer (tar::writer) emits USTAR headers and automatically upgrades fields that do not fit (non-ASCII/long paths, large sizes/IDs, sub-second mtime, or atime/ctime) into PAX extended headers.

Both tar::reader and tar::writer are @sealed and implement io::reader and io::writer for streaming entry payloads.

Valid Usage & Examples

Writing files and directories to a tar archive

Create a tar::writer, emit each entry with write_header followed by io::write_all for exactly h.length bytes, and finish with tar::close.

lora Allowed 
use io;
use strings;
use tar;

export fn main() (void | io::failure | nomem) = {
	let buf = io::new_buffer();
	let w = tar::new_writer(&buf);

	tar::write_header(&w, &tar::header {
		name = "docs/",
		kind = tar::kind::dir,
		mode = 0o755,
	})?;

	let body = strings::to_bytes("hello tar");
	tar::write_header(&w, &tar::header {
		name = "docs/hello.txt",
		length = @i64(len(body)),
		mode = 0o644,
	})?;
	io::write_all(&w, body)?;
	tar::close(&w)?;
}

Reading entries sequentially from a tar stream

Call tar::next(&r) in a loop until done, reading each entry payload via r (which implements io::reader) before the next tar::next call.

lora Allowed 
use io;
use strings;
use tar;

fn read_all_entries(src: io::reader) (void | io::failure | nomem) = {
	let r = tar::new_reader(src);
	for (true) match (tar::next(&r)?) {
		done => break,
		let h: tar::header => {
			// `h.name` and other strings borrow `r` until the next `tar::next`
			let data = io::read_all(&r, 1 << 20)?;
			assert(@i64(len(data)) == h.length);
		},
	}
}

Attaching and iterating custom PAX extended records

Use tar::pax_add to encode custom PAX records onto header.pax and tar::pax_records to iterate (key, value, rest) tuples.

lora Allowed 
use io;
use strings;
use tar;

export fn main() (void | io::invalid | nomem) = {
	let raw: ^[]u8 = [];
	tar::pax_add(&raw, "SCHILY.xattr.user.tag", "release")?;
	tar::pax_add(&raw, "comment", "verified")?;

	let cur = strings::from_bytes(raw[..]);
	for (true) match (tar::pax_records(cur)?) {
		done => break,
		let rec: (str, str, str) => {
			cur = rec.2;
			assert(len(rec.0) > 0z);
		},
	}
}

Disallowed Forms & Diagnostics

Writing more bytes than `header.length` or forgetting `tar::close`

tar::writer enforces that each entry receives exactly header.length bytes (io::too_large if exceeded, io::invalid on next header/close if short).

io::too_large: Runtime io::failure: write exceeds header.length
lora Rejected 
use io;
use strings;
use tar;

export fn main() (void | io::failure | nomem) = {
	let buf = io::new_buffer();
	let w = tar::new_writer(&buf);
	tar::write_header(&w, &tar::header { name = "a.txt", length = 3 })?;
	io::write_all(&w, strings::to_bytes("toolong"))?; // error: returns io::too_large (exceeds header.length)
	tar::close(&w)?;
}
lora Allowed 
use io;
use strings;
use tar;

export fn main() (void | io::failure | nomem) = {
	let buf = io::new_buffer();
	let w = tar::new_writer(&buf);
	let data = strings::to_bytes("ok!");
	tar::write_header(&w, &tar::header { name = "a.txt", length = @i64(len(data)) })?; // ok: header.length matches payload
	io::write_all(&w, data)?; // ok: writes exact header.length bytes
	tar::close(&w)?;

Constraints & Limits

Block size
512 bytes
Every header and padded entry payload is aligned to 512-byte blocks; `tar::close` writes two zero blocks.
Special record cap
1 MiB (`SPECIAL_MAX = 1 << 20`)
PAX headers and GNU long names/links larger than 1 MiB are rejected to prevent unbounded memory growth.
Header string lifetime
Until next `tar::next`
`header.name`, `linkname`, `uname`, `gname`, and `pax` are views into `tar::reader`.
  • Notice the header size field is named length: i64 (not size).
  • tar::close does not close the underlying dst: io::writer; the caller remains responsible for closing it.

Module Guide & Examples

Tape archives: files one after another, each a 512-byte header and its data, as tar writes them. Reads the V7, USTAR, PAX and GNU formats, with PAX records and GNU's long names, large numbers and sparse files; writes USTAR, with PAX records for what does not fit.

let r = tar::new_reader(&file); for (true) match (tar::next(&r)?) { done => break, let h: tar::header => { // h's strings are good until the next call to next io::copy(&out, &r)?; // the entry's data }, };

let w = tar::new_writer(&file); tar::write_header(&w, &tar::header { name = "a.txt", size = 5, mode = 0o644, ... })?; io::write_all(&w, strings::to_bytes("hello"))?; tar::close(&w)?;

lora 
use io;
use strings;
use tar;

export fn main() void = {
	let out = io::new_buffer();
	let w = tar::new_writer(&out);
	tar::write_header(&w, &tar::header { name = "hello.txt", length = 5, ... })!;
	io::write_all(&w, strings::to_bytes("hello"))!;
	tar::close(&w)!;
	let src = io::new_bytes_reader(io::bytes_of(&out));
	let r = tar::new_reader(&src);
	let h = tar::next(&r)! as tar::header;
	assert(h.name == "hello.txt" && h.length == 5);
	assert(tar::next(&r)! is done);
}

next reads the V7, USTAR, PAX and GNU formats:

  • PAX records override what the header holds: path, size, ids, names, and times with their fractions. Global records apply to every entry after them, and are given as an entry of kind::global themselves.
  • GNU's long names and links, and its base-256 numbers, are read.
  • So are sparse files, in old GNU's form and in PAX's 0.0, 0.1 and 1.0; their holes read as zeros.
  • A header's strings are views into the reader, good until the next next. The data an entry leaves unread is skipped.
  • A checksum that does not match is io::invalid, at the byte where the header is. A PAX header or long name of more than 1 MiB is refused, so an archive cannot make the reader take memory without end.

write_header writes USTAR, splitting a long name between its name and prefix fields where it can. It adds PAX records for what USTAR cannot hold: long or non-ASCII names, large numbers, fractional times, and access and change times. Writing more data than the header's length is io::too_large, and less is refused at the next header.
