Standard Library

netip — addresses as values

Module netip (lib/netip.lora) exports 71 declarations. Import with use netip;.

Overview

netip models IPv4 and IPv6 addresses, addr_port pairs, CIDR prefix values, and hardware mac addresses as small, non-allocating value types. Every IPv4 address is stored internally in IPv4-mapped IPv6 form (::ffff:a.b.c.d), and IPv6 addresses may carry an inline interface zone (up to ZONE_MAX = 15 bytes).

Parsing is strict: leading zeros in IPv4 octets, invalid brackets, or malformed zones return netip::invalid with what, why: reason, at: u16 byte offset, and up to 64 bytes of offending input. All core types implement encoding text and binary interfaces and provide compare, equal, and hash helpers for maps and sorting.

Valid Usage & Examples

Parse, classify, and format IPv4/IPv6 addresses

Parse strict IPv4 and IPv6 addresses with zones, inspect classification predicates, and format canonical RFC 5952 text into a stack buffer.

lora Allowed 
use fmt;
use netip;

export fn main() void = {
	let v4 = netip::parse("192.168.1.10")!;
	let v6 = netip::parse("fe80::1%en0")!;
	let mapped = netip::parse("::ffff:10.0.0.1")!;

	let buf: [netip::TEXT_MAX]u8 = [0...];
	assert(netip::is_private(v4));
	assert(netip::is_link_local_unicast(v6) && netip::zone_of(&v6) == "en0");
	assert(netip::is4in6(mapped) && netip::is4(netip::unmap(mapped)));
	fmt::printfn("v6={} expanded={}",
		netip::text(&v6, buf[..]),
		netip::expanded(&mapped, buf[..]))!;
}

Check CIDR prefix containment and key a map by address

Mask prefixes, test whether an address belongs to a subnet, and deduplicate addresses in a hash map.

lora Allowed 
use map;
use netip;

export fn main() void = {
	let net = netip::parse_prefix("10.1.2.3/8")!;
	let masked = netip::masked(net);
	let buf: [netip::TEXT_MAX]u8 = [0...];
	assert(netip::prefix_text(&masked, buf[..]) == "10.0.0.0/8");
	assert(netip::contains(masked, netip::v4(10, 200, 0, 1)));

	let counts: map::map[netip::addr, int] = map::new_eq(&netip::hash, &netip::equal);
	defer map::finish(&counts);
	let ip = netip::parse("2001:DB8::1")!;
	map::put(&counts, ip, 1)!;
	assert(map::get(&counts, netip::parse("2001:db8::1")!) != null);
}

Disallowed Forms & Diagnostics

Parse IPv4 with leading zeros or unbracketed IPv6 addr_port

Leading zeros in IPv4 octets (ambiguous with octal) and unbracketed IPv6 host:port strings are rejected with netip::invalid.

E_NETIP_INVALID: cannot parse "01.2.3.4" as an IP address: an IPv4 field has a leading zero, at byte 0
lora Rejected 
use netip;

export fn main() void = {
	let bad_ip = netip::parse("01.2.3.4")!; // error: leading zero in IPv4 octet is rejected
	let bad_ep = netip::parse_addr_port("::1:80")!; // error: unbracketed IPv6 host:port is rejected
}
lora Allowed 
use netip;

export fn main() void = {
	let ip = netip::parse("1.2.3.4")!; // ok: no leading zeros in IPv4 octets
	let ep = netip::parse_addr_port("[::1]:80")!; // ok: bracketed IPv6 address with port
	assert(ep.port == 80 && netip::is4(ip));
}

Constraints & Limits

TEXT_MAX
72 bytes
Maximum formatted output buffer size required by text/addr_port_text/prefix_text.
ZONE_MAX
15 bytes
Maximum inline IPv6 zone identifier length.
MAC sizes
6, 8, or 20 bytes
Supports EUI-48, EUI-64, and 20-byte InfiniBand hardware addresses.
  • The zero value netip::addr { ... } has family::none and is_valid(a) == false.
  • netip::equal treats IPv4 1.2.3.4 and IPv4-mapped IPv6 ::ffff:1.2.3.4 as distinct unless unmap is called first.

Module Guide & Examples

Internet addresses as values: IPv4 and IPv6 addresses, an address with a port, prefixes (networks, as 10.0.0.0/8), and hardware (MAC) addresses.

Each is a small struct, copied as a value and allocating nothing; an IPv6 address may carry a zone (fe80::1%en0), kept inline. The zero value of each is not a valid address, and is_valid says so. Parsing is strict, with one text for each address, and an error that says what is wrong and at which byte:

cannot parse "1.2.03.4" as an IP address: an IPv4 field has a leading zero, at byte 4

Text is written as RFC 5952 has it (lowest case, the longest run of zero groups as ::), and an IPv4 address mapped into IPv6 as ::ffff:1.2.3.4. Every type has a text and a binary form through encoding's interfaces, so json, xml, csv and pack carry them as text or bytes.

IPv4 and IPv6 addresses (with an IPv6 zone, kept inline), an address with a port, prefixes, and hardware (MAC) addresses: small structs, copied as values, allocating nothing. The zero value of each is not valid. lora 
use netip;

export fn main() void = {
	let lan = netip::parse_prefix("192.168.0.0/16")!;
	let a = netip::parse("192.168.4.20")!;
	assert(netip::contains(lan, a) && netip::is_private(a));
	let buf: [netip::TEXT_MAX]u8 = [0...];
	let six = netip::parse("2001:DB8:0:0:0:0:0:1")!;
	assert(netip::text(&six, buf[..]) == "2001:db8::1");
	let ep = netip::parse_addr_port("[2001:db8::1]:443")!;
	assert(ep.port == 443 && netip::equal(ep.ip, six));
}
