Standard Library

time — instants, durations, the calendar and zones

Module time (lib/time.lora) exports 104 declarations. Import with use time;.

Overview

time provides durations, dual wall/monotonic instant values, civil calendar arithmetic, IANA/TZif/POSIX-rule time zones, strftime-style formatting and parsing, and ISO-8601/RFC-3339 datetime helpers with encoding::text_encoder/text_decoder implementations.

time::instant carries both wall-clock seconds/nanoseconds and a monotonic clock reading (mono), so time::sub, since, until, and compare use monotonic elapsed time when both instants have it.

Valid Usage & Examples

Parsing durations and measuring monotonic elapsed time

Parse human-readable durations and compute elapsed time with time::now and time::since.

lora Allowed 
use fmt;
use time;

export fn main() void = {
	let d = time::parse_duration("1m30s500ms")!;
	let buf: [32]u8 = [0...];
	fmt::printfn("parsed={} ({} ms)", time::format_duration(d, &buf), time::milliseconds(d))!;

	let start = time::now();
	time::sleep(5 * time::MILLISECOND);
	fmt::printfn("elapsed={} us", time::microseconds(time::since(start)))!;
}

Formatting and parsing instants in time zones

Use time::utc_zone(), time::fixed_zone(), time::format, and time::parse with time::RFC3339.

lora Allowed 
use fmt;
use time;

export fn main() void = {
	let utc = time::utc_zone();
	let est = time::fixed_zone("EST", -5 * 3600)!;
	let t = time::parse(time::RFC3339, "2026-06-15T14:30:00Z", &utc)!;
	let s = time::format(t, &est, time::RFC3339)!;
	defer free(s);
	fmt::println(s)!;
}

Civil calendar breakdown and date arithmetic

Convert an instant to time::civil and advance calendar dates with time::add_date.

lora Allowed 
use fmt;
use time;

export fn main() void = {
	let utc = time::utc_zone();
	let t = time::date(2024, 2, 29, 12, 0, 0, 0, &utc);
	let next_year = time::add_date(t, 1, 0, 0, &utc);
	let c = time::in_zone(next_year, &utc);
	fmt::printfn("{}-{:02}-{:02} ({})", c.year, @u8(c.month), c.day, time::weekday_name(c.weekday))!;
}

Disallowed Forms & Diagnostics

Passing an invalid duration string to time::parse_duration

Missing units or malformed numbers return time::invalid_duration.

Runtime: invalid duration "42": missing unit in duration
lora Rejected 
use time;

export fn bad() void = {
	let _ = time::parse_duration("42")!; // error: missing duration unit returns invalid_duration
}
lora Allowed 
use time;

export fn good() (time::duration | time::invalid_duration) = {
	return time::parse_duration("42ms"); // ok: includes valid unit suffix ("ms")
}

Module Guide & Examples

Time: instants and the durations between them, the calendar, time zones, and dates and times written as text.

An instant is a moment, the same everywhere: in seconds and nanoseconds since 1970-01-01T00:00:00Z, and, for one now gives, a reading of the monotonic clock, so that the time between two of them is right even when the wall clock is set meanwhile. A zone says what an instant is on the calendar and the clock somewhere: in_zone gives that as a civil time, date makes an instant of one, and format and parse write and read them as text.

use time;

export fn main() void = {
	let paris = time::load_zone("Europe/Paris")!;
	let t = time::date(2024, 3, 31, 1, 30, 0, 0, &paris);
	let later = time::add(t, time::HOUR);          // the clocks went on an hour at 2:00
	let text = time::format(later, &paris, "%F %T %Z")!;
	assert(text == "2024-03-31 03:30:00 CEST");
	let utc = time::utc_zone();
	let back = time::parse(time::RFC3339, "2024-03-31T01:30:00Z", &utc)!;
	assert(time::equal(back, later));
}

Instants are moments, the same everywhere. now also records the monotonic clock, so sub, since and the comparisons measure true elapsed time even if the wall clock is set meanwhile. wall, round, truncate and anything read from text carry no such reading. Compare instants with compare, equal, before and after, not their fields. sub saturates at the longest or shortest duration rather than overflowing.

Zones say what an instant is on the calendar and the clock somewhere. load_zone reads the system's time zone database: from $ZONEINFO if set when the program started, then the usual system directories. A name with a .. part, an empty part or a leading / is refused. Past the end of its table, a zone follows its POSIX rule.

local_zone follows $TZ as the program started:

  • a database name, or : followed by one;
  • a path to a zone file, as /etc/localtime;
  • a POSIX rule such as EST5EDT,M3.2.0,M11.1.0;
  • "", meaning UTC.

Without $TZ it reads /etc/localtime, and it falls back to UTC. zone_bounds gives when the period an instant is in began and ends, both in the table and past it.

Civil times (in_zone) give the date, the time, the weekday, the day of the year, and the zone's offset and abbreviation. date goes the other way:

  • Fields outside their range carry over: month 13 is January of the next year, and day 0 is the last day of the month before.
  • A clock time that occurs twice, when clocks go back, is the first of the two.
  • A clock time that never happens, when clocks skip ahead, is taken with the offset from before the skip: 2:30 when 2:00 became 3:00 is 3:30.

add_date adds years, months and days the same way, so a month after January 31 is March 2 or 3.

Layouts have % directives:

DirectiveMeaning
%Y %y %Cyear (four digits or more, with a sign before the year 0), its last two digits, century
%m %b %B %hmonth: 01–12, Jan, January, Jan
%d %e %jday: 01–31, space-padded, day of the year 001–366
%H %I %p %Phour 00–23, 01–12, AM/PM, am/pm
%M %Sminute, second
%fa point and the second's fraction, no trailing zeros; nothing if there is none
%N %3N %6Nnanoseconds, nine digits, or the first three or six
%a %A %u %wMon, Monday, 1–7 from Monday, 0–6 from Sunday
%G %V %U %WISO 8601 year and week; week of the year from Sunday, from Monday
%z %:z %::z %#zoffset: +hhmm, +hh:mm, +hh:mm:ss, Z for UTC or +hh:mm; seconds only with %::z
%Zthe zone's abbreviation (some are offsets, as +03), or +hhmm where it has none
%sseconds since 1970
%F %T %R %D%Y-%m-%d, %H:%M:%S, %H:%M, %m/%d/%y
%n %t %%newline, tab, %

After the %, - drops a number's padding (%-d) and _ pads it with spaces.

parse reads what format writes, with a few allowances:

  • Numbers take one digit as well as two.
  • Names are matched in either case.
  • %S may be followed by a fraction even when the layout doesn't mention one.

Fields the layout leaves out are those of 0000-01-01 00:00:00. A time with an offset (%z, or %Z naming UTC, GMT, an offset such as +03, or one of the zone's abbreviations) is taken at that offset; otherwise it is a time in the given zone. An abbreviation the zone doesn't have is an error, not a guess. Every field is checked, including the day against its month, and an error says which field is wrong and why.

instant reads and writes as RFC 3339 text in UTC, to the nanosecond, in json, xml, csv and the other encodings. Reading accepts any RFC 3339 offset; lower-case t and z, or a space for the T; and a leap second, :60, which counts as the minute's last second. datetime is the older compact UTC form, to the millisecond; to_datetime and from_datetime convert between the two.
