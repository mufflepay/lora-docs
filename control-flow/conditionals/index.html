Control Flow

Conditionals

if, else if, if let narrowing on tagged unions and nullable pointers, and right-associative cond ? a : b expressions.

Overview

Conditionals in Lora require exact bool expressions and double as value-producing expressions:

FormResult TypeNotes
if (c) a else bUnified type of a and b (or (A | B))Short-circuits; && and || also short-circuit
if (c) a (no else)(A | void)Evaluates to void when c is false
if (let x: T = v)Narrows tagged union or nullable *TExplicit : T type required; x scoped to if branch
c ? a : bSame as if (c) a else bRight-associative ternary expression

Specification: if & if let

  • Inside a generic function, lambdas can use its type parameters. A lambda can use locals of any enclosing function; each lambda in between captures the variable in turn.

9. Control flow

if, for, match and blocks are expressions with values.

if

lora 
let n = 7;
let kind = if (n % 2 == 0) "even" else if (n < 0) "negative" else "odd";
assert(kind == "odd");
if (n > 5) {
	n = 5;
}
assert(n == 5);

Without else, if has type (T | void):

lora 
let x: int = if (true) 1; // error: Initializer of type (void | int) is not assignable to binding type int

if let checks a tagged union or nullable pointer and binds the value. The binding must name its type:

lora 
fn find(xs: []int, v: int) (usize | void) = {
	for (let i = 0z; i < len(xs); i += 1) if (xs[i] == v) return i;
	return void;
}

export fn main() void = {
	let xs = [4, 5, 6];
	if (let i: usize = find(xs, 5)) {
		assert(i == 1);
	} else {
		abort("not found");
	}
	let x = 3;
	let p: nullable *int = &x;
	if (let q: *int = p) assert(*q == 3);
}

Valid Usage & Examples

Value-returning if/else, union branches, and ternary ?:

When if and else return different types, Lora infers a tagged union (A | B); never branches (like abort()) coerce to the other branch’s type.

lora Allowed 
export fn main() void = {
	let x = if (true) 1u8 else 0i8;
	assert(x is u8 && x as u8 == 1u8);

	let label = (2 > 1) ? "yes" : "no";
	assert(label == "yes");
}

Narrowing tagged unions and nullable pointers with if let

if (let q: T = expr) binds q only inside the truthy branch; supports *T pointer narrowing for in-place mutation.

lora Allowed 
export fn main() void = {
	let u: (int | uint) = 10u;
	if (let q: *uint = &u) {
		*q += 5u;
	}
	assert(u as uint == 15u);

	let n = 42;
	let p: nullable *int = &n;
	let doubled = if (let ptr: *int = p) *ptr * 2 else 0;
	assert(doubled == 84);
}

Disallowed Forms & Diagnostics

Using non-bool conditions or omitting : T in if let

Integers and pointers are never truthy, and if (let q = x) must explicitly annotate : T.

Compile error: Condition must be `bool` / `if let` binding requires explicit `: Type`
lora Rejected 
export fn main() void = {
	let x: (int | uint) = 10u;
	if (let q = x) void; // error: must provide a type (: uint)
}
lora Allowed 
export fn main() void = {
	let x: (int | uint) = 10u;
	if (let q: uint = x) assert(q == 10u); // ok: explicit : uint type annotation
}

Referencing an if let binding in the else branch

The narrowed variable is only in scope inside the if body, not in else or after the if.

L0001: `q` is an unknown object
lora Rejected 
export fn main() void = {
	let x: (int | uint) = 10u;
	if (let q: uint = x) void else {
		let _ = q; // error[L0001]: q is not in scope in else
	}
}
lora Allowed 
export fn main() void = {
	let x: (int | uint) = 10u;
	if (let q: uint = x) {
		assert(q == 10u); // ok: q is in scope inside the if branch
	}
}

Constraints & Limits

  • Conditions must have exact type bool (integers and pointers are never implicitly truthy).
  • if let requires naming the concrete member type (if (let n: int = v)), never omitting : T.
