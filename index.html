Getting Started

Introduction

Lora is a statically typed systems programming language targeting macOS and Linux (arm64 and x86_64) via QBE with affine ownership (^T), partial struct borrows (*T.{fields}), structured coroutine concurrency, direct C ABI interoperability, and zero garbage collection.

Overview

Lora is designed to combine C-level predictability with modern static guarantees that prevent whole classes of systems bugs before execution. Every function compiles ahead-of-time through the Lora compiler frontend (lorac) into QBE SSA IR, native assembly, and dead-stripped executables with all 141 core standard library modules and the rt runtime linked automatically.

Language Tour at a Glance

lora 
use fmt;
use strings;

type item = struct {
	name: str,
	qty: u32 = 1,
}

fn format_item(it: *const item) (^str | nomem) =
	strings::concat(it.name, " (ready)");

export fn main() (void | nomem | io::error) = {
	let it = item { name = "kernel" }
	let label = format_item(&it)?;
	fmt::printfn($"{label}: qty={it.qty}")?;
}

Compilation & Verification Pipeline

StageComponentGuarantee
1. Lexing & ParsingCcompiler/src/lex.c, Cparse.cUTF-8 source, UAX #31 Unicode identifiers, bounded nesting depths
2. Type & Value CheckingCcompiler/src/check.c, Ceval.c, Ccomptime.cNominal types, checked constant arithmetic, @comptime VM
3. Ownership & LoansCcompiler/src/loans.c, Cleak.c, Ceffects.cAffine moves, cross-module effects, leak & UAF diagnostics (L0100–L0609)
4. Concurrency & StackCcompiler/src/races.c, Cstack.cData-race proof (L0700), static stack-frame ceiling verification
5. Native CodegenCgen.c -> qbe -> clang/as -> ld -dead_stripAudited stack probing, bounds traps, zero-GC Mach-O binaries

Quickstart Commands

sh 
# Check types, borrows, races, stack frames, and leaks without linking
lora check hello.lora

# Compile and run with enforces on unit contracts
lora run hello.lora

# Enable runtime heap leak reporting and quarantine poisoning
lora run --leaks hello.lora

# Isolate every heap allocation with PROT_NONE guard pages
lora run --guard hello.lora

# Run @test, @bench, and @fuzz suites (parallel, leak-checked, JSON)
lora test -j 4 --leaks
lora test --bench --time 1s tests/my_bench.lora
lora test --fuzz --time 5s tests/my_fuzz.lora

Quick Reference: How Lora Compares

  • Versus C: Integer overflow traps instead of invoking UB (with opt-in wrapping +%, -%, *%), pointers cannot silently alias or dangle outside unsafe, slices carry length and bounds checks, and C functions are declared with @symbol.
  • Versus Rust: No lifetime syntax ('a), no borrow-checker fighting over disjoint struct fields (use *T.{a, const b}), and direct QBE compilation measured in milliseconds.
  • Versus Go: No garbage collector pauses, native tagged-union error handling instead of nil-interface error boilerplate, and compile-time data-race + stack-frame estimation on coroutines.
  • Versus Zig: Full compile-time evaluation (@comptime) alongside affine ownership (^T), deterministic RAII (impl drop), structured @all/@scope concurrency, and typed SQL verification.

Program Entry & Source Structure

A program is a list of declarations. It starts at export fn main, which takes no parameters and returns void:

lora 
use fmt;
use strings;

export fn main() void = {
	let greeting = strings::concat("hello", ", world")!;
	defer free(greeting);
	fmt::println(greeting)!;
}
sh 
lora run hello.lora          # build and run
lora build -o hello hello.lora
lora check hello.lora        # type-check only
  • use statements come first, before any other declaration.
  • A program can span several files: lora build -o app a.lora b.lora. The files share one namespace.
  • Command-line arguments come from os::args, the exit status from os::exit(n).
lora 
fn helper() void = void;
use fmt; // error: syntax error: expected 'const', 'let', 'def', 'type', 'fn', found 'use'
export fn main() void = void;

Disallowed Forms & Diagnostics

Ignoring or silently dropping an error return

Error unions cannot be discarded anonymously (L0003 / L0006). Handle them with ?, !, or, or exhaustive match.

L0003: Unhandled error: io::error must be propagated or handled
lora Rejected 
use fmt;

export fn main() void = {
	fmt::println("hello"); // error: Unhandled error: io::error must be handled
}
lora Allowed 
use fmt;

export fn main() void = {
	fmt::println("hello")!; // ok: unwrap with `!`, or propagate with `?` / handle with `or`
}

Constraints & Limits

Targets
macOS & Linux, arm64 & x86_64
QBE arm64_apple / amd64_apple on macOS, arm64 / amd64_sysv on Linux.
Main Stack Ceiling
8 MiB on every machine
Checked statically across the call graph; unbounded recursion warned of; page guard.
Core Library
140 lib + rt (141 modules)
Pure Lora modules linked with -Wl,-dead_strip per atom.
  • Applications share one flat program module per build invocation; custom external use package namespaces are not supported yet.
  • Passing or returning structs <= 16 bytes by value to external C ABI functions is disallowed cleanly by convention due to QBE ABI limits (pass pointers *T instead).
