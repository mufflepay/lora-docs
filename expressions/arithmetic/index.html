Arithmetic & Overflow Semantics

Checked integer math (+, -, *, /, %, unary -), explicit wrapping arithmetic (+%, -%, *%), signed/unsigned truncation rules, and compile-time L0009 constant overflow checks.

Overview

Every arithmetic operation in Lora has one canonical result across x86_64, ARM64, and @comptime evaluation—there is zero signed-overflow undefined behavior.

Operator FormSigned & Unsigned OverflowZero DivisorConstants
+, -, *, -xRuntime abort with operands—Compile error L0009
+%, -%, *%Two's-complement modulo 2^w—Folds modulo 2^w cleanly
/, %MIN / -1 traps; MIN % -1 == 0Runtime abortCompile error L0009
f32, f64 opsIEEE-754 (+Inf, -Inf, NaN)1.0 / 0.0 == +InfFolds per IEEE-754
  • Numbers never coerce implicitly across signedness or bit widths (i8 vs int, int vs u32).
  • Constant expressions with +, -, *, /, % are computed at arbitrary precision before checking whether the result fits the target type.

Detailed Integer & Float Rules

Arithmetic rules. Every operation has one result, the same on every machine, at run time and when constants are folded; none is left to the hardware:

  • Integer overflow aborts: +, -, *, -x and / whose true result does not fit the type stop the program with the values and the type, signed or unsigned (0u32 - 1 overflows too). A constant one is a compile error.
  • +%, -%, *% (and +%=, -%=, *%=) wrap instead (two's complement), for hashes, checksums and random numbers: 255u8 +% 1 == 0.
  • Integer division truncates toward zero, and % takes the sign of the dividend: -7 / 2 == -3, -7 % 2 == -1. Dividing by -1 negates, so i32::MIN / -1 overflows; its remainder is 0.
  • Integer division and remainder by zero abort with the location (a constant zero divisor is a compile error).
  • >> of a signed value fills with its sign (-16 >> 2 == -4); of an unsigned one, with zeros.
  • A shift count must be less than the type's width and not negative: a constant one is checked when compiling (1u32 << 40 is an error), and a variable one at run time, which aborts saying so.
  • A float converted to an integer, @i32(f), saturates: values beyond the type's range become its minimum or maximum, and NaN becomes 0.
  • Arithmetic on two constants is worked out when compiling, exactly, with +, -, *, /, %, &, |, ^, << and >>: its value then decides what it fits, so @u8((4999 * 7) & 0xff) is the constant 177.
  • A suffixed literal must fit its type: 300u8 is an error. Hex, octal and binary literals may give a signed type's bit pattern: 0xFFi8 is -1.
  • Floats follow IEEE 754: 1.0 / 0.0 is infinity.
lora 
// aborts
let a = 0;
let b = 7 / a;     // division by zero
lora 
let a: u32 = 1;
let b = a << 40; // error: Shifting a u32 by 40 shifts every bit out
lora 
let x = 300u8; // error: syntax error: Integer literal 300u8 does not fit its type
lora 
let x: u8 = 255;
x +%= 1;              // wraps: x += 1 would stop the program
assert(x == 0);
let y: i8 = 127;
y +%= 1;
assert(y == -128);
assert(0xcbf29ce484222325u64 *% 0x100000001b3 == 0xaf63bd4c8601b7df);
assert(-7 / 2 == -3 && -7 % 2 == -1);
lora 
let big = 2147483647i32 + 1; // error: Integer overflow: 2147483647 + 1 is out of range for i32
let small: u8 = 200 + 100;   // the constant 300 does not fit in u8: an error too
text 
main.lora:3:12: abort: 255 + 1 is 256, which is out of range for u8 (0 to 255).

Valid Usage & Examples

Wrap intentionally with `+%`, `-%`, `*%`; keep default checked math for invariants

FNV-1a hashes, CRC32, PRNGs, and ring-buffer deltas use explicit wrapping operators (+%, -%, *%, +%=, -%=, *%=).

lora Allowed 
export fn main() void = {
	let a: u8 = 250;
	assert(a +% 10 == 4);
	let s: i8 = 127;
	s +%= 1;
	assert(s == -128);
	let hash = 0xcbf29ce484222325u64 *% 0x100000001b3u64;
	assert(hash == 0xaf63bd4c8601b7dfu64);
}

Truncating division/remainder and arbitrary-precision constant folding

Integer / truncates toward zero, % keeps the dividend sign, and constant subexpressions fold before range checking.

lora Allowed 
export fn main() void = {
	assert(-7 / 2 == -3 && -7 % 2 == -1);
	assert(7 / -2 == -3 && 7 % -2 == 1);
	static assert(@u8((4999 * 7) & 0xff) == 177u8);
	let x = 10;
	x++;
	--x;
	assert(x == 10);
}

IEEE-754 floating-point arithmetic (`f32` and `f64`)

Floating-point division by zero produces IEEE-754 infinity or NaN rather than trapping.

lora Allowed 
export fn main() void = {
	let inf = 1.0 / 0.0;
	let nan = 0.0 / 0.0;
	assert(inf > 1.0e300 && nan != nan);
	static assert(@f64(0.3f32) != 0.3);
}

Disallowed Forms & Diagnostics

Overflowing constant integer bounds (`L0009`)

Constant arithmetic that exceeds the target type range is rejected at compile time.

L0009: Integer overflow: 2147483647 + 1 is out of range for i32
lora Rejected 
export fn main() void = {
	let bad = 2147483647i32 + 1; // error[L0009]: out of range for i32
}
lora Allowed 
export fn main() void = {
	let ok: i64 = @i64(2147483647i32) + 1; // ok: widen to i64
	let wrapped = 2147483647i32 +% 1;      // ok: explicit wrapping on i32
	assert(ok == 2147483648i64 && wrapped == -2147483648i32);
}

Mixing integer widths or signedness without `@T(x)` (`L0002`)

Operands of binary arithmetic must share the exact same concrete numeric type.

L0002: Types u8 and u32 do not match
lora Rejected 
export fn main() void = {
	let a = 1u8 + 2u32; // error[L0002]: mismatched integer widths
}
lora Allowed 
export fn main() void = {
	let a = @u32(1u8) + 2u32; // ok: explicit @u32 conversion matches operand types
	assert(a == 3u32);
}

Runtime Aborts

Runtime signed/unsigned overflow or `MIN / -1`

Both signed and unsigned checked operations (+, -, *, -x, MIN / -1) abort with exact operands and type.

lora Aborts 
let u: u8 = 255;
let _ = u + 1; // abort: 255 + 1 is 256, which is out of range for u8 (0 to 255).
lora Allowed 
let u: u8 = 255;
let wrapped = u +% 1u8; // ok: explicit modular wrapping addition
assert(wrapped == 0u8);

Runtime division or remainder by zero

Integer / or % with a runtime zero divisor aborts immediately.

lora Aborts 
let d = 0;
let _ = 7 / d; // abort: division by zero
lora Allowed 
let d = 0;
let q = if (d != 0) 7 / d else 0; // ok: checked against zero before /
assert(q == 0);
