Expressions

Member Access

Uniform dot lookup (.field, .0, .name, .method(), .enum_variant) with automatic single-level pointer dereferencing (ptr.field).

Overview

Lora uses . uniformly for struct/union fields, tuple elements, enum shorthand, and interface methods—there is no -> operator.

Resolution Order for expr.ident

  1. Type-known enum shorthand (.ident): Resolves to EnumType::ident when contextual target type is an enum.
  2. Tuples: Positional tuple.0, tuple.1 or named tuple.quot, tuple.rem.
  3. Struct / Union / Embedded Fields: Auto-dereferences *T, ^T, and *T.{fields} (checking view permissions L0200 and union safety).
  4. Methods (impl Interface for T): If no field matches, checks non-ambiguous implemented methods, passing &expr as receiver.

Valid Usage & Examples

Struct, embedded struct, and automatic single-level pointer dereference

Accessing p.x on p: *point or p: ^point dereferences one pointer level automatically.

lora Allowed 
type vec2 = struct { x: int, y: int }
type player = struct { vec2, hp: int }

export fn main() void = {
	let p = alloc(player { x = 3, y = 4, hp = 100 })!;
	assert(p.x == 3 && p.hp == 100);
}

Positional/named tuple fields and contextual enum shorthand

Tuples support .0 / .1 or named fields; enums support .VARIANT when the target type is known.

lora Allowed 
type status = enum { OK, ERR }
fn check(s: status) bool = s == .OK;

export fn main() void = {
	let t = (10, "hi");
	assert(t.0 == 10 && t.1 == "hi" && check(.OK));
}

Interface method calls and partial view `*T.{fields}` access

Methods defined via impl I for T can be called directly with .method(), and partial views restrict visible fields.

lora Allowed 
type counter = struct { val: int, secret: int }
type inc = interface { fn bump() int; }
impl inc for counter { fn bump(c: *counter) int = { c.val += 1; return c.val; }; }

fn read_val(v: *const counter.{val}) int = v.val;

export fn main() void = {
	let c = counter { val = 0, secret = 99 }
	assert(c.bump() == 1 && read_val(&c) == 1);
}

Disallowed Forms & Diagnostics

Ambiguous method calls when two implemented interfaces share a method name

Cast or assign &x to the specific interface type first before invoking the method.

Compile error: Method call is ambiguous between two implemented interfaces
lora Rejected 
type a = interface { fn id() int; }
type b = interface { fn id() int; }
type s = struct { n: int }
impl a for s { fn id(x: *s) int = 1; }
impl b for s { fn id(x: *s) int = 2; }
export fn main() void = {
	let v = s { n = 0 }
	let _ = v.id(); // error: ambiguous between interface `a` and `b`
}
lora Allowed 
type A = interface { fn id() int; }
type B = interface { fn id() int; }
type S = struct { n: int }
impl A for S { fn id(x: *S) int = 1; }
impl B for S { fn id(x: *S) int = 2; }
export fn main() void = {
	let v = S { n = 0 }
	let iface: A = &v; // ok: select the interface explicitly before calling
	assert(iface.id() == 1);
}

Accessing a field outside a partial view (`L0200`) or mutating `*const T` (`L0202`)

Partial views *T.{f} only expose listed fields; *const T forbids field writes.

L0200: Field `secret` is outside the view `*counter.{val}`
lora Rejected 
type counter = struct { val: int, secret: int }
fn bad(v: *counter.{val}) int = v.secret; // error[L0200]: outside the view
lora Allowed 
type counter = struct { val: int, secret: int }
fn ok(v: *counter.{val}) int = v.val; // ok: val is included in the partial view
export fn main() void = {
	let c = counter { val = 5, secret = 99 }
	assert(ok(&c) == 5);
}
