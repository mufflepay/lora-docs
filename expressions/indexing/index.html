Indexing, Slicing & Bounds Safety

Array indexing (a[i]), slice sub-views (a[lo..hi]), UTF-8 safe string slicing (s[a..b]), checked fixed-size slice views (@*[N]T(s)), and safe non-aborting element lookup (at(s, i)).

Overview

All indexing and slicing in Lora is bounds-checked by default and uses usize indices:

FormTargetBehavior
a[i][N]T, []T, *[*]T (in unsafe)0-based element access; auto-derefs *T / ^T
a[lo..hi][N]T, []THalf-open sub-slice [lo, hi); preserves remaining capacity
s[lo..hi]strUTF-8 byte-range sub-string; aborts if not on UTF-8 boundary
s[lo..hi] = src[]TCopies elements into slice range (len(src) == hi - lo)
at(s, i)[]T, [N]TNon-aborting lookup returning (T | void)

Arrays, Slices & Strings Indexing

Arrays

[N]T is a fixed-size array. It is a value: assigning or passing it copies all its elements. [_]T takes the length from the initializer, and [v...] fills the rest of an array with v:

lora 
let a: [_]int = [1, 2, 3];            // [3]int
let zeros: [64]u8 = [0...];
let grid: [3][3]int = [[0...]...];    // arrays of arrays
grid[1][2] = 5;
let b = a;                            // a copy
b[0] = 99;
assert(a[0] == 1 && len(a) == 3 && grid[1][2] == 5);
let c: [len(a)]int = [0...];          // len of an array is a constant
assert(len(c) == 3);

Indexing is bounds-checked. A constant index past the end is a compile error, any other one aborts at run time:

lora 
let a = [1, 2, 3];
let x = a[5]; // error: Index must be less than the array's length
lora 
// aborts
let a = [1, 2, 3];
let i = 5z;
let x = a[i];     // slice or array access out of bounds

Slices

[]T is a view of an array: a pointer, a length and a capacity. Slicing (a[lo..hi], either end optional) makes a view that shares the elements:

lora 
let a = [1, 2, 3, 4];
let s = a[1..3];      // [2, 3]
s[0] = 20;
assert(a[1] == 20 && len(s) == 2);
let all = a[..];
let tail = a[2..];
assert(len(all) == 4 && tail[0] == 3);

Slices that own heap memory are grown with append and insert, shrunk with delete and released with free (see Memory).

A slice is a span: it views elements it does not own, and the compiler tracks what it points into, so a view never outlives its array (L0608). Three forms say more about what a view may do:

FormWhat it is
[]const Ta view that only reads: no assigning, & gives *const T, no append or delete
@*[n]T(s)a view of exactly n elements, checked once: indexing it needs no more checks
at(s, i)element i of a slice or array as a pointer, or null when there is none

[]T and arrays pass where []const T is wanted, and not the other way:

lora 
fn total(xs: []const int) int = {
	let t = 0;
	for (let x .. xs) t += x;
	return t;
}

export fn main() void = {
	let v = [1, 2, 3, 4];
	assert(total(v) == 10 && total(v[1..]) == 9);
	let four = @*[4]int(v[..]);       // aborts unless len is 4
	four[0] = 7;
	assert(v[0] == 7);
	match (at(v, 9)) {
		let p: *int => *p = 0,
		null => void,                     // no element 9: handled, not a stop
	}
}
lora 
let xs: []const int = [1, 2];
xs[0] = 1; // error: Cannot change this: it is an element of a []const slice.
lora 
let xs: []const int = [1, 2];
let p = @*[2]int(xs); // error: A []const slice is only read through, and so is a view of it.

A view of a []const T is @*const [n]T(s), and at on one gives nullable *const T. Returning at(a, i) or @*[n]T(a) of a local array is L0608, as returning a[..] is.

Strings

A str is UTF-8 bytes. len(s) counts bytes. Strings compare with == and !=, and the strings module does everything else:

lora 
use strings;

export fn main() void = {
	let s = "héllo";
	assert(len(s) == 6);                         // bytes, not characters
	assert(strings::runecount(s) == 5);
	assert(s == "héllo" && s != "hello");
	let bytes = strings::to_bytes(s);
	assert(bytes[0] == @u8('h'));
	let up = strings::toupper(s)!;
	defer free(up);
	assert(strings::has_prefix(up, "H"));
}

s[a..b] is the bytes a to b of a string, as a str that borrows them: no copy is made. A bound may not fall inside a character, which would leave invalid UTF-8: that is a compile error for a constant string and bounds, and aborts at run time otherwise, saying where.

lora 
export fn main() void = {
	let s = "héllo";
	assert(s[..3] == "hé" && s[3..] == "llo");   // é is two bytes
	let n = 1z;
	assert(s[n..3] == "é");
}
lora 
let s = "héllo"[..2]; // error: This slice 0..2 cuts a character: byte 2 is inside a multi-byte UTF-8 character.

What strings cannot do:

lora 
let s = "abc";
let c = s[0]; // error: Can only index into an array or a slice, but this is str
lora 
let s = "a" + "b"; // error: Cannot do arithmetic on a str
lora 
let lt = "a" < "b"; // error: Cannot order values of a str with <, >, <= or >=

Use strings::to_bytes(s)[i] or strings::at(s, i) for bytes, strings::concat or interpolation to join, and strings::compare to order.

Valid Usage & Examples

Array/slice indexing, sub-slicing, and range assignment

Slicing omits lo (defaults to 0) or hi (defaults to len); s[lo..hi] = ... overwrites a slice range.

lora Allowed 
export fn main() void = {
	let a = [1, 2, 3, 4, 5];
	let s = a[1..4]; // [2, 3, 4]
	assert(len(s) == 3 && s[0] == 2 && s[2] == 4);
	s[..] = [20, 30, 40];
	assert(a[1] == 20 && a[3] == 40);
}

Non-aborting `at(s, i)` lookup and UTF-8 string slicing

at(s, i) returns (T | void) so out-of-bounds indices never abort.

lora Allowed 
export fn main() void = {
	let xs = [10, 20, 30];
	let fallback = -1;
	assert(*(at(xs, 1) ?? &fallback) == 20);
	assert(*(at(xs, 9) ?? &fallback) == -1);

	let s = "hello, λ";
	assert(s[..5] == "hello" && s[7..] == "λ");
}

Reslicing preserves underlying capacity for `static append`

Taking buf[..0] keeps len == 0 while preserving cap == len(buf).

lora Allowed 
export fn main() void = {
	let buf: [8]int = [0...];
	let view = buf[..0];
	static append(view, [1, 2, 3]...)!;
	assert(len(view) == 3 && buf[2] == 3);
}

Disallowed Forms & Diagnostics

Constant out-of-bounds array index (`L0009`)

Indexing a fixed-size array with a constant index >= N fails at compile time.

L0009: Index 3 is out of bounds for [3]int
lora Rejected 
export fn main() void = {
	let a = [1, 2, 3];
	let _ = a[3]; // error: out of bounds for [3]int
}
lora Allowed 
export fn main() void = {
	let a = [1, 2, 3];
	assert(a[2] == 3); // ok: in-bounds constant index
	assert((at(a, 3) ?? 0) == 0); // ok: safe non-aborting bounds check
}

Indexing with a non-integer or indexing `[]opaque` (`L0002`)

Indices must be usize (or untyped integer constants), and opaque elements have unknown size.

L0002: Index must be an integer / Cannot index []opaque
lora Rejected 
export fn main() void = {
	let x: []int = [1, 2, 3];
	let _ = x["hello"]; // error[L0002]: invalid index type str
}
lora Allowed 
export fn main() void = {
	let x: []int = [1, 2, 3];
	assert(x[1z] == 2); // ok: usize index
}

Runtime Aborts

Runtime out-of-bounds index or slice range

Accessing s[i] with i >= len(s) or slicing s[lo..hi] with lo > hi or hi > cap(s) aborts.

lora Aborts 
let s: []int = [1, 2];
let i = 5z;
let _ = s[i]; // runtime abort: index 5 out of bounds for length 2
lora Allowed 
let s: []int = [1, 2];
let i = 5z;
let v = if (i < len(s)) s[i] else 0; // ok: bounds-checked before indexing
assert(v == 0);

Slicing a `str` inside a multi-byte UTF-8 codepoint

String slicing verifies both endpoints are valid UTF-8 codepoint boundaries.

lora Aborts 
let s = "λ"; // 2 UTF-8 bytes: 0xCE 0xBB
let _ = s[1..]; // runtime abort: slice boundary is not on a UTF-8 codepoint
lora Allowed 
use strings;
let s = "λa";
let tail = strings::sub(s, 1z, 2z); // ok: slice by rune boundary or full UTF-8 char length
assert(tail == "a");

Constraints & Limits

Index Type
usize
Untyped integer constants infer usize.
Unchecked Access
@unchecked (unsafe)
Default indexing always bounds-checks.
  • Zero-sized arrays ([0]u8) slice cleanly without aborts (Ccompiler/src/gen.c uses the AST element type cleanly).
  • Opting out of bounds checks requires @unchecked (which requires unsafe).
