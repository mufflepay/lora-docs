Expressions

Explicit Conversions (`@T(x)`) & Assertions (`as`)

Explicit type conversions (@T(x) for numbers, enums, pattern types, pointers, newtypes) and checked tag/null assertions (x as T).

Overview

Lora separates explicit value/representation conversions (@T(x)) from runtime-checked variant assertions (x as T) and non-aborting type predicates (x is T).

FormApplies ToBehavior
@T(x)Numbers, rune, enum, pattern types, newtypes, pointers, slicesConverts value (float→int saturates; int→smaller int keeps low bits); pointer/slice casts require unsafe
x as TTagged unions (A | B), nullable *TExtracts T if active/non-null; aborts at runtime on mismatch
x is TTagged unions, nullable *T, pattern typesReturns bool without aborting

Conversion Syntax & Rules

Everything else needs an explicit conversion, written @T(value): @int(x), @usize(i), @*u8(p), @(int | str)(v), @color(2). The old form value: T is an error that points to it.

A type whose name is also a built-in form's, as @kind(T) and @sealed(T) are, is converted to by its module's name, which its own module may use too: in a module wire with type kind = enum u8 { ... }, @wire::kind(b) converts a byte to it.

lora 
let a: u8 = 3;
let b: i64 = a; // error: Initializer of type u8 is not assignable to binding type i64
lora 
let a = 3;
let b = a: u8; // error: syntax error: a conversion is written @T(value)
lora 
let i: int = 3;
let f: f64 = i; // error: Initializer of type int is not assignable to binding type f64
lora 
let a: int = 3;
let b: uint = 4;
let c = a + b; // error: Cannot combine an int and a uint here
lora 
let a: u8 = 3;
let b = @i64(a);           // explicit: fine
let f = @int(3.7);         // truncates toward zero: 3
let c = @u32('a');         // 97
let r = @rune(65);         // 'A'
let p = @uintptr(&b);      // a pointer as an integer, and back,
let back = unsafe { @*i64(p) } // which is unsafe
assert(b == 3 && f == 3 && c == 97 && r == 'A' && *back == 3);

Casts between integer types truncate or extend silently. Some casts are never allowed:

lora 
let i = @int(true); // error: A bool can't be converted to an int

The three type operators:

OperatorApplies toResult
@T(x)numbers, pointers, enums, tagged membersconverts; never fails
x as Ttagged unions, nullable pointersT, aborting if x holds something else
x is Ttagged unions, nullable pointersbool

Valid Usage & Examples

Numeric, saturating float-to-int, enum, and newtype `@T(x)` conversions

Float-to-int conversions saturate cleanly at type bounds with NaN -> 0; integer narrowing keeps low bits.

lora Allowed 
type user_id = u32;
type mode = enum u8 { READ = 1, WRITE = 2 }

export fn main() void = {
	let wide: i64 = @i64(42i8);
	let sat = @i32(1.0e30);
	let nan_i = @i32(0.0 / 0.0);
	let id = @user_id(100u32);
	let m = @mode(2u8);
	assert(wide == 42i64 && sat == 2147483647i32 && nan_i == 0);
	assert(@u32(id) == 100u32 && m == mode::WRITE);
}

Narrowing tagged unions and `nullable *T` with `is` and `as`

Guard with is before as, or use as directly when a variant is known to hold.

lora Allowed 
export fn main() void = {
	let v: (int | str) = "ok";
	assert(v is str);
	assert((v as str) == "ok");

	let x = 7;
	let p: nullable *int = &x;
	assert(p is *int && *(p as *int) == 7);
}

Pointer and fixed-size slice conversions inside `unsafe`

Round-tripping *opaque or viewing a slice as *[N]T is explicit and requires unsafe { ... }.

lora Allowed 
export fn main() void = unsafe {
	let a = 42u32;
	let op = @*opaque(&a);
	let back = @*u32(op);
	assert(*back == 42u32);

	let s: []int = [1, 2, 3];
	let fixed = @*[3]int(s);
	assert(fixed[2] == 3);
}

Disallowed Forms & Diagnostics

Converting integers or `null` to non-null pointers outside `unsafe` (`L0800`)

Non-null pointer guarantees and slice-element reinterpretation are protected by unsafe { ... }.

L0800: Unsafe operation: converting integer/null/ownership/slice element requires `unsafe { ... }`
lora Rejected 
export fn main() void = {
	let p = @*int(null); // error[L0800]: Converting null to non-nullable pointer needs `unsafe { ... }`
}
lora Allowed 
export fn main() void = {
	let x = 42;
	let p: nullable *int = null; // ok: use `nullable *T` when a pointer may be null
	let q: *int = &x;            // ok: non-null pointer from address-of
	assert(p == null && *q == 42);
}

Using `as` on non-nullable pointers or unrelated scalar types (`L0002`)

as is only for tagged unions and nullable *T; use @T(x) for scalar conversions.

L0002: Type assertion `as` is not valid on *int
lora Rejected 
export fn main() void = {
	let x = 4;
	let p: *int = &x;
	let _ = p as *int; // error: type assertions on non-nullable pointers are prohibited
}
lora Allowed 
export fn main() void = {
	let x = 4;
	let p: nullable *int = &x;
	let q = p as *int; // ok: `p` is nullable *int
	assert(*q == 4);
}

Runtime Aborts

Failed `x as T` assertion on a mismatched union or `null` pointer

If the runtime tag or non-null check fails, the program aborts cleanly.

lora Aborts 
let v: (int | str) = 123;
let _ = v as str; // runtime abort: expected str, got int
lora Allowed 
let v: (int | str) = 123;
let s = if (v is str) v as str else ""; // ok: check variant with `is` before `as`
assert(s == "");
